# PhysBoneからの揺れ物変換

VRChat SDKが導入済みの場合、元モデルのPhysBoneを読み、MA / NDMF処理後の
一時コピーにVRM 1.0 SpringBoneを作成します。元シーン・Prefab・アセットは
変更しません。SDKがない場合も通常のVRM出力は利用できます。
髪の名前から設定を推測しません。揺れ設定のない既存VRMには、元のUnityモデルからの
再出力が必要です。この機能は0.10.6以降で利用できます。

## 保存する内容

- Root Transform、Ignore Transformsとその子孫、Ignore Other PhysBones、
  有効状態、子ボーン、Endpoint Positionを参照します。
- チェックを外したPhysBoneと非表示のPhysBoneは揺れ物にしません。
  Ignore Other PhysBonesがオンのPhysBoneは、VRChatと同じく、無効・非表示のPhysBoneの
  Root Transformから先を自分の連鎖に入れません。そのため、チェックを外したPhysBoneのボーンは
  このPhysBoneの設定では揺れず、親のボーンが動いたときにだけ付いて動きます。
- 分岐のIgnoreでは分岐元を固定し、Firstでは最初の子へ向け、
  Averageでは子の平均位置に仮想末端を作ります。各子の連鎖を別途保持します。
  同一ボーンを複数PhysBoneが駆動する場合は、より深いRoot Transformの設定を
  優先します。同じRootでは、そのRoot上のコンポーネント、次に元の階層・
  コンポーネント順を優先します。重ならない範囲は各PhysBoneの設定で残します。
  親側の連鎖は境界の元位置に専用末端を置いて分割し、長さと向きを保持します。
  VRMでは末端も複数連鎖で共有できないため、子の関節を親の末端に再利用しません。
- 既存のVRM SpringBoneを優先します。関節・末端・関節間のボーンに重なる範囲を
  保護し、PhysBoneの残る連鎖を保持します。優先した対象と近似の理由を表示します。
- 各ボーンの階層深度 / 最大深度で設定カーブを評価します。
  各値とカーブの積を使い、長い分岐の末端を深度1とします。分割後も元の深度を
  保ち、連鎖ごとのコライダー参照を引き継ぎます。
- 長さゼロの区間は、その区間の駆動だけ省略します。元のTransformを削除・移動せず、
  長さのある残りの連鎖を保持します。仮想末端は他のPhysBoneの対象に混入しません。
- Sphere / Capsule / Planeと内側判定、位置・回転・半径を変換します。
  Capsuleの長さは半径を含む全高から両端の中心を求めます。
  高さが直径以下の内側判定のCapsuleは、長さが無いのでSphereの内側判定で書き出します。
  アバター最上位のコライダーは、出力用コピーの子オブジェクトへ移して保持します。
  UniVRMが最上位を省略する際のコライダー欠落と衝突参照のずれを防ぎます。
- Cone / Hinge / Polarの角度と回転を、UniVRMのCone / Hinge / Sphericalへ写します。
  UniVRM既存のVRMC_springBone_limit・VRMC_springBone_extended_colliderを使用します。
  独自拡張は追加しません。これらを扱わないビューアーでは制限・特殊衝突は再現されません。
- Inside Boundsの球とカプセルは、半径にRoot Transformのワールドスケールを掛けて書き出します。
  同梱のUniVRM 0.131のソルバーは外側のコライダーの半径にだけスケールを掛けるためです。
  Insideの半径にもスケールを掛けるビューアーでは、拘束の範囲が変わります。

## 近似と未対応

PhysBoneとSpringBoneは別のソルバーです。見た目が一致する保証はありません。
重複の整理は静止姿勢、ボーンの配置、メッシュ、マテリアルを変更しません。
同じ関節を重ねて動かす挙動は再現できないため、揺れ方は上記の優先順位による
近似になります。警告に対象と方針を残します。
カーブ評価後のPullをp、Spring / Momentumをs、ボーンの長さをL（ワールドの長さを
そのボーンのスケールで割った値）とします。VRMのソルバーはスケールを掛けて使うので、
元のスケールが変わっても同じ揺れになります。

- Simplified: r = max(1 - p(1 - s'), 0.02) として、stiffness = 60L(1/r - 1)、
  dragForce = 1 - s'/r です。s'はsをpに応じた上限で抑えた値です。pが小さくsが
  大きいとVRM側だけ揺れ続けるため、実測に合わせて抑えています。
- Advanced: r = max(1 - p, 0.02) として、stiffnessは同じ式、
  dragForce = 1 - s(1 - Stiffness)です。

重力gはPhysBoneの版で意味が違います。

- 1.1: 静止方向を(1-g)・元の方向 + g・下向きへ変えます。
  stiffness = K(1-g)、gravityPower = Kgです（Kは上のstiffness）。
- 1.0: Pullと競合し、tanθ = g/pの角度で釣り合います。stiffness = Kのまま、
  gravityPower = 60Lg(1-s')/r（Advancedは60Lg/r）です。

Gravity Falloffをfとすると、重力は元の姿勢からの角度θでg(1 - f cosθ)に変わります。
VRMの重力は一定なので、釣り合う角度で解いた値を書き出します。揺れている間に重力が
変わる分は、静止点を保ったままstiffnessとgravityPowerへ同じ倍率を掛けて補います。
倍率は釣り合いから45度振れた位置の復元力の比です。

Immobile TypeがAll Motionのときは、カーブ評価後のImmobileをiとして、力を1/(1-i)倍に
します。親の動きを割合だけ隠すことと、力を同じ割合だけ強めることで、遅れの大きさが
そろうためです。dragForceは変えません。Worldのときは足さず、アプリの安定化
（揺れの基準をモデルのルートにする）に委ねます。

VRMのソルバーは最後のジョイントを動かさず、取得済みの回転を書き戻します。そのままだと
最後のボーンが親の揺れに付いてこないので、実在するボーンで終わる連鎖には長さが1/4の
短い末端を足し、硬さを上限にして元の向きへ追従させます。
stiffnessの上限は60L(1/0.02 - 1)です。半径は元値を使います。

伸縮、動的なIs Animated追従、
Grab / Pose、他アバターとの衝突、PhysBoneパラメーターの連動は保存しません。
Is Animatedは出力時の姿勢を基準とします。
PolarのZ角度はUniVRMの対応範囲0〜90度に制限します。
角度制限もソルバーの差を含む近似です。変換結果の「詳細を見る」で各警告を確認できます。

変換件数・連鎖数・動く関節数（末端を除く）・コライダー数・省略数を表示します。
無効、除外、連鎖なし、既存VRM優先の各理由を残します。未知の種類、非有限値、
アバター外参照は保存前にエラーとします。重複や有限の長さゼロは上記の方針で整理し、
姿勢を推測して変更したり、すべての揺れ設定を削除して続行したりしません。
変換済みの連鎖・関節・コライダーが出力から欠落した場合も保存を止めます。

Humanoidのボーンは連鎖に入れません。SpringBoneのソルバーは関節の回転を毎フレーム
上書きするので、手足や胴を連鎖に入れるとアニメーションに従わなくなるためです。
Humanoidのボーンの親も、割り当てが無くても同じ扱いです。
Hipsなどをルートにした全身のPhysBoneでは体は揺れず、Humanoidのボーンにぶら下がる
ボーンだけがそれぞれの連鎖として揺れます。ぶら下がるボーンが1本だけでEndpointも
無いときは揺らす区間が無いので、そのPhysBoneは省略します。

## 検証

Tests/Editor/PhysBoneSpringExportTests.csは、導入された実際のSDKを使って
分岐・末端・カーブ・コライダー・除外・既存設定・元モデル非変更を検証します。
親子の重複、同じRootの競合、部分重複、末端共有、長さゼロも検証し、
境界の長さ・元のカーブ深度・設定の優先順位が保持されることを確認します。
標準出力とlilToon出力をUniVRMで再読込し、頭側の回転後に髪が遅れて動き、
静止後に収束することを測定します。MA Bone Proxy処理後の経路も含みます。
SDK / MA不在時は対応する統合テストのみスキップします。
実機の見た目と保存動画の確認はUnityテストと別に行う必要があります。

[VRM SpringBone](https://github.com/vrm-c/vrm-specification/blob/master/specification/VRMC_springBone-1.0/README.md)
