# QRコードでiPhoneに送る

QRクラウド転送は安定版 **0.11.15** に搭載しています。配信済みbeta.2と同じ転送機能です。対応する最新iPhone TestFlightで受信します。Android配布版のQR受信は無効のままです。旧LAN直接転送は停止したままです。

PCとiPhoneの両方にインターネット接続が必要です。実サービスでの正常転送は検証済みですが、主要失敗時の両実機復旧確認は継続中です。

## 接続条件と一時保存

PCとスマホの両方にインターネット接続が必要です。同じWi-FiやLAN接続、PCのポート開放は不要です。完成済みVRMをPCで暗号化し、通常のHTTPSで固定のVR Vlog転送サービスへアップロードします。復号鍵はQRにだけ含め、サービスには送りません。元のファイル名や元のVRMのハッシュもサービスには送らず、暗号化したファイルだけを一時保存します。VRMは転送のために再変換せず、スマホで認証・復号した後もlilToon、表情、ライセンス情報を含む完成済みファイルのバイト列を維持します。

アバターはクラウドへ一時保存されます。受取期限は転送作成時から **3分**、容量上限は **256MiB（268,435,456バイト）** です。アップロード中も期限が進み、QRの表示時に期限を延長しません。サーバーが返す受取期限で残り時間を表示し、期限切れ時にQRを消します。受取完了・中止・期限切れで転送用コピーを削除します。PCから中止通知が届かなかった場合も、サービス側の期限による削除が適用されます。無料枠を保護する受付・日次転送量の上限があるため、混雑や上限到達時は新しい転送を受け付けません。時間を置くか、通常のファイル書き出しを利用してください。

クラウドの保存先に障害がある場合は、受取アクセスを停止したまま削除を再試行します。PCの保存完了表示はスマホへの正式保存を示し、クラウドの削除完了を確認した表示ではありません。

QRには受取用の認証情報と復号鍵が含まれます。QRを持つ人はアバターを受け取り、復号できます。共有、画面の撮影、ログや不具合報告への添付はしないでください。アップロード権限の認証情報はQRに含みません。

## 操作

1. ALCOMの通常の一覧から安定版 **0.11.15** をインストールします。**Show pre-release packages** の有効化は不要です。開発用defineは不要です。
2. **VR Vlog → VRMを書き出す** でVRMを保存します。
3. 保存後の **QRコードでスマホに送る** を押します。元のVRMを保持したまま一時コピーを作成します。
4. [プライバシーポリシー](https://vrvlog.fun/privacy/)を確認し、**プライバシーポリシーに同意する**にチェックして、**アップロードしてQRを表示** を押します。メニューを開くだけでは送信しません。PCで暗号化してから転送を作成します。進捗を確認し、アップロード完了後にQRが出るまで待ちます。
5. スマホのVR Vlogで **モデルを変更 → PCから受け取る** を開き、アプリ内のカメラでQRを読み取ります。カメラの許可が必要です。QR対応の最新iPhone TestFlightを使います。Android配布版は受信できません。
6. ファイル名と容量を確認して受け取ります。スマホは暗号文の認証を確認してから復号し、元の容量・SHA-256を検証して既存のVRM保存・読み込みへ進みます。鍵が違う場合やファイル・QRのメタデータが改ざんされた場合は採用しません。
7. PCに保存完了が表示されることを確認します。状態は5秒ごとに確認するため、スマホでの完了から表示まで少し時間がかかります。

同意チェックはこのPCのUnity Editorに保存し、次回も選択した状態で表示します。初回の既定値は未選択です。チェックを外すと保存した同意も解除され、新しいアップロード・QR再作成を開始できません。同意済みでも、画面を開くだけでは送信しません。進行中の転送を止める場合は **転送を中止** を使います。

完了・中止・期限切れ・失敗後は **新しいQRを作成** で、同じ完成済みVRMから転送を作り直せます。以前のQRは再利用できません。画面を閉じるとPCの転送用一時VRMも削除します。その後に新しく転送する場合は、VRM書き出し画面の保存完了欄から転送画面を開き直してください。通常の **VRMを保存** で保存したVRMはこの後始末の対象になりません。

## アプリに転送

未リリースの機能です。クラウド転送が有効な版（プレリリース版と、転送を採用した安定版）では、Hierarchyのアバターを右クリックし、名前と同意を決めるだけでQRを表示できます。それ以外の版ではメニューに表示されません。QRはスマホのOSのカメラで読み取ります。VR Vlogが開いて取り込みが始まるので、アプリ内で受け取り画面を開く操作は不要です。OSのカメラからの取り込みに対応したVR Vlogが必要です。未対応の版では、上の **QRコードでスマホに送る** とアプリ内のカメラを使ってください。

右クリックのメニューは **アプリに転送（かんたん）** と **アプリに転送（通常）** の2つです。かんたんは、表情ボードを画面に出さずに準備し、表情ボードで何も変えずに通常で書き出した場合と同じ内容（表情はそのアバターで前に決めた割り当て、無ければ自動。書き出さないオブジェクトはそのアバターに記録した設定）を、下の手順だけで転送します。通常は、先に表情ボードで表情と書き出さないオブジェクトを決めます（[通常の流れ](#アプリに転送通常)）。

1. Hierarchyでアバターの一番上のオブジェクトを1つ選んで右クリックし、**VR Vlog → アプリに転送（かんたん）** を選びます。
2. **名前** を確認します。初期値は、このアバターで前に転送の書き出しに成功したときの名前です（プロジェクトの `UserSettings` にアバターごとに記録）。記録が無ければオブジェクト名です。名前はアプリのアバター一覧に表示されます。末尾の `.vrm` と見えない文字（制御文字・書式文字）は除いて表示するので、名前が `.vrm` だけや見えない文字だけのときは **名前を入れると作れます** と表示します。
3. **利用規約を読む** で[利用規約](https://vrvlog.fun/terms/)を確認し、同意にチェックを入れます。同意は保存しません。ウィンドウを開くたび、アバターを替えるたびに確認します。[プライバシーポリシー](https://vrvlog.fun/privacy/)にまだ同意していない場合は、**QRコードでスマホに送る** と同じ同意の行も表示します。こちらの同意は **QRコードでスマホに送る** と共有し、保存します。
4. 作者名（必須）を確かめます。VRMに記録するライセンス設定は **VRMの利用条件** を開くと変えられます。この欄は最初は閉じていて、閉じたままでも1行で今の設定を表示します。開いた・閉じたはこのPCのUnity Editorの設定に記録します。項目は **VRMを書き出す** の **ライセンス設定** と同じです。作者名は、このアバターで前に書き出したときの作者名（**VRMを書き出す** と共通で、このPCのUnity Editorの設定に記録）を初期値にします。記録が無い場合は、開いている **VRMを書き出す** に入力済みの作者名を使います（その画面のアバターが違っても使います）。ライセンス設定は、**VRMを書き出す** で同じアバターを開いている場合はその設定を、それ以外はこのアバターで前に書き出したときの設定（**VRMを書き出す** と共通で、アバターごとに記録）を初期値にします。記録が無ければ既定値から始めます。書き出すたびに、ここで決めたライセンス設定をアバターごとに記録します。作者名が空のあいだは欄の下に「VRMには作者名が必要です」と表示します。書き出しに失敗したあとの **もう一度** でも、作者名が空なら入力の画面に戻ります。
5. **QRコードを作る** を押します。押せないあいだは、ボタンの上に押せない理由（「利用規約に同意すると作れます」など）を警告色で1行表示します。押せない理由とボタンはウィンドウの下に固定され、入力欄をスクロールしても隠れません。書き出し、暗号化、アップロードの順に進み、完了するとQRと残り時間を表示します。QRの下には「スマホのカメラで読み取る」と、警告アイコン付きの「QRを他の人に見せたり配信に映したりしないでください」を、赤字でほかの文字の2倍の大きさで表示します。ウィンドウの幅に収まらないときは折り返します。書き出す内容は、表情ボードで何も変えずに通常で書き出した場合と同じです。かんたんでは、自動設定できなかった項目の確認（書き出し結果の一覧）を出さずにアップロードへ進みます。表情ボードに直すところ（保存した書き出さないオブジェクトでプレビューを作れないなど）があるときは、「表情の割り当てを直すと作れます」と、続けて直すところの理由を表示して止まります。**表情とオブジェクトを選ぶ** で通常に切り替えて直してください。書き出しを止める失敗は、下のとおり理由を表示して止まります。書き出しの詳細（警告など）は、書き出し画面と同じくConsoleに出します。
6. スマホのカメラでQRを読み取り、VR Vlogで受け取ります。受け取りが終わると、ウィンドウに **取り込みが終わりました** と表示します。

画面の上の「表情は前回の割り当て（なければ自動）・書き出さないオブジェクト N件」の行の **表情とオブジェクトを選ぶ** を押すと、同じアバターで通常の流れに切り替えます。

### アプリに転送（通常）

1. 右クリックで **VR Vlog → アプリに転送（通常）** を選びます。**VRMを書き出す** の表情ボードが開き、そのアバターで **書き出しを準備** まで進みます。
2. 表情ボードの下の **書き出さないオブジェクト** で、外すオブジェクトを **除外するオブジェクトを追加** で選び、**プレビューに反映** を押します。表情の割り当てを保ったままプレビューを作り直します。選んだオブジェクトはアバターごとに記録し、かんたん・一括書き出し画面と共通です。
3. 表情をVRMの表情5枠・**その他の表情**・**書き出さない表情** へ振り分けます。
4. **次へ：名前と利用条件** を押します。作者名と利用条件はこの次の画面で入力するので、表情ボードの保存欄には出しません。
5. 転送の画面で、かんたんの手順2〜5と同じく名前・利用規約の同意・**VRMの利用条件** を確認して **QRコードを作る** を押します。表情ボードの今の割り当てと除外で書き出します。自動設定できなかった項目があるときは、書き出し画面と同じ確認を出し、**設定を変更する** を選ぶとアップロードせずに止めます。

転送の画面の **戻って編集** で表情ボードに戻れます。表情ボードを閉じたり別のアバターに替えたりすると、転送の画面に「表情の割り当て画面が開いていません」と表示し、**割り当て画面を開く** で開き直せます。開き直したときに戻るのは、VRMの表情5枠の割り当てと書き出さないオブジェクト（どちらもアバターごとの記録）です。追加した表情ファイルとポーズは入れ直しになります。表情ボードに直すところ（割り当てのエラー、反映していない書き出さないオブジェクトなど）があるあいだは、「表情の割り当てを直すと作れます」と表示し、**QRコードを作る** を押せません。

一時保存と受取期限の扱いは **QRコードでスマホに送る** と同じです。期限は転送の作成から3分で、アップロードにかかった時間も含みます。残り時間のバーは、QRを表示した時点の残りを全体として減っていきます。期限が切れたら **QRを作り直す** で、書き出し済みのVRMからアップロードし直します。ウィンドウを閉じると、進行中の転送を中止し、転送用の一時VRMを削除します。アップロード中や読み取り待ちに同じアバターの **アプリに転送（かんたん）** を開くと、転送を続けたままウィンドウを前に出します。表情ボードの **次へ** で戻ったときや、かんたんと通常を切り替えたときは、表示中のQRが今の内容と違うことがあるので、QRを作り直してよいか確認します。別のアバターを選んだ場合は、転送を中止してよいか確認します。転送を始める前に表情ボードとのあいだを行き来したときは、入力した名前・同意・ライセンス設定をそのまま残します。

QRの中身は `vrvlog://import#` で始まるリンクです。**QRコードでスマホに送る** のQRと同じ8項目を、URLのフラグメントに入れています。受取用の認証情報と復号鍵を含むので、共有・撮影しないでください。リンクが4096文字を超える名前や、1つのQRに収まらない名前では、QRを作る前に **名前を短くすると作れます** と表示します。

書き出しに失敗した場合は、その場に理由と **もう一度** を表示し、書き出し画面と同じ対策画面を開きます。対策画面から保存すると、そのままアップロードへ進みます。書き出しの失敗・取り消しでアップロードに進まなかったときは、転送用に書き出した一時VRMをその場で削除します。

転送用の一時VRMと暗号化したコピーは、OSの一時フォルダー、Unityの一時キャッシュ、プロジェクトの `Temp`、ユーザーのローカルアプリデータの `VRVlog` の順に、書き込めて空き容量（512MiB）のある場所へ置きます。空き容量の足りない場所は、ほかに書き込める場所がないときだけ使います。どこにも書き込めないときは、書き出す前に「転送用の一時ファイルを置ける場所が見つかりません」と表示して止めます。Unityが異常終了して残った転送用の一時ファイルは、1日たったものを次の転送のときに削除します。

## 接続できないとき

| 状況 | 対処 |
| --- | --- |
| アップロード失敗／受付上限 | インターネット接続を確認し、新しいQRを作成する。混雑時は時間を置く。通常のVRMファイル書き出しも利用できる。 |
| QRが読み取れない | VR Vlog内のカメラを使い、QR v3対応のアプリか確認する。古いLAN QR・QR v2は利用できない。 |
| 期限切れ／転送中止 | PCで新しいQRを作成する。PC・スマホの日時も正しく設定する。 |
| スマホ保存完了、PCの状態確認に失敗 | アバターを再受信する必要はない。PCの接続を確認するか転送画面を閉じる。残っている転送用コピーも受取期限で削除される。 |
| 容量やSHA-256が一致しない | 受信ファイルを採用せず、新しい転送を作成する。 |
| 転送画面を閉じた／Unityを再読み込みした | 待機中の転送を中止し、PCの転送用一時ファイルを削除する。必要なら改めて書き出す。 |
| 転送用の一時ファイルを置ける場所が見つからない | ドライブの空き容量と、一時フォルダーへの書き込み権限を確認する。通常のVRMファイル書き出しも利用できる。 |

## 検証の範囲

開発時のホスト試験では、独立Python生成の共通ベクトルと実際のC#ストリーム暗号化を比較し、合成データとfake transportで暗号文のmultipart分割、復号した元ファイルとの一致、HTTPへの鍵・元のメタデータの非送信、再発行時の鍵・IV更新、公開完了前のQR非表示、中止の競合、期限切れ、一時ファイルの後始末を検査します。既存LANは無効のままで、旧プロトコルのTLS loopback回帰も継続します。

**アプリに転送** は、リンクの組み立て（アプリと共通のベクトル）と、ウィンドウが出す状態・残り時間・期限切れ・後始末を同じホスト試験で検査します。

暗号化プロファイルは [RFC 7518 A256CBC-HS512](https://www.rfc-editor.org/rfc/rfc7518.html#section-5.2.5) です。PCは標準のAES-256-CBC/PKCS7とHMAC-SHA-512を使い、元の名前・容量・SHA-256を認証対象に含めます。サービスは暗号文の容量・ハッシュ、通信元、時刻、転送状態を扱います。E2E暗号化はPCやスマホ自体、QRを撮影・共有した場合のアクセスを保護するものではありません。

クラウドサービスへの実アップロード、配布パッケージとAndroid・iPhone配布版の一連の転送、対応Unity 2022.3 Editorのコンパイル・画面・テストは別途確認が必要です。ホスト試験や別Unity版の参照DLLコンパイルを、これらの実機確認として扱いません。
