# QRコードでiPhoneに送る

QRクラウド転送は **1.0.0以降** の安定版に搭載しています（0.11.15から搭載）。対応する最新iPhone TestFlightで受信します。Android配布版のQR受信は無効のままです。旧LAN直接転送は停止したままです。

PCとiPhoneの両方にインターネット接続が必要です。実サービスでの正常転送は検証済みですが、主要失敗時の両実機復旧確認は継続中です。

## 接続条件と一時保存

PCとスマホの両方にインターネット接続が必要です。同じWi-FiやLAN接続、PCのポート開放は不要です。完成済みVRMをPCで暗号化し、通常のHTTPSで固定のVR Vlog転送サービスへアップロードします。復号鍵はQRにだけ含め、サービスには送りません。元のファイル名や元のVRMのハッシュもサービスには送らず、暗号化したファイルだけを一時保存します。VRMは転送のために再変換せず、スマホで認証・復号した後もlilToon、表情、ライセンス情報を含む完成済みファイルのバイト列を維持します。

アバターはクラウドへ一時保存されます。対応サービスで新しい期限が有効な場合、アップロードは作成から最大15分、受取はサーバーで公開を確定してから最大3分、作成から全体で最長18分です。旧サービス・旧経路の受取期限はアップロードと受信を含め作成から3分です。QR表示や再試行で期限を延長せず、サーバーが返す受取期限で残り時間を表示し、期限切れ時にQRを消します。容量上限は256MiB（268,435,456バイト）です。受取完了・中止・期限切れでアクセスを停止し、転送用コピーの削除処理を行います。通知が届かない場合も期限に基づいて処理します。サービス全体の受付・容量や外部基盤の利用上限により、一時的に新しい転送を受け付けない場合があります。時間を置くか、通常のファイル書き出しを利用してください。

クラウドの保存先に障害がある場合は、受取アクセスを停止したまま削除を再試行します。PCの保存完了表示はスマホへの正式保存を示し、クラウドの削除完了を確認した表示ではありません。

QRには受取用の認証情報と復号鍵が含まれます。QRを持つ人はアバターを受け取り、復号できます。共有、画面の撮影、ログや不具合報告への添付はしないでください。アップロード権限の認証情報はQRに含みません。

## 操作

1. ALCOMの通常の一覧から安定版 **1.5.1** をインストールします。**Show pre-release packages** の有効化は不要です。開発用defineは不要です。
2. 下の[アプリに転送](#アプリに転送)の手順で **QRコードを作る** を押し、QRを表示します。メニューを開くだけでは送信しません。PCで暗号化してから転送を作成します。
3. スマホのカメラでQRを読み取ります。QR対応の最新iPhone TestFlightを使います。Android配布版は受信できません。
4. スマホで受け取ります。スマホは暗号文の認証を確認してから復号し、元の容量・SHA-256を検証して既存のVRM保存・読み込みへ進みます。鍵が違う場合やファイル・QRのメタデータが改ざんされた場合は採用しません。
5. PCに **アプリに取り込みました** と表示されることを確認します。

0.11.15でVRMの保存後に出していた **QRコードでスマホに送る** の画面は、1.0.0以降にはありません。

## アプリに転送

Hierarchyのアバターを右クリックし、名前と同意を決めるだけでQRを表示できます。QRはスマホのOSのカメラで読み取ります。VR Vlogが開いて取り込みが始まるので、アプリ内で受け取り画面を開く操作は不要です。OSのカメラからの取り込みに対応したVR Vlogが必要です。未対応の版では、**アプリに転送（通常）** の3ページ目の **VRMを保存** で保存したファイルを **モデルを変更 → 端末のVRMを選ぶ** から読み込んでください。

右クリックのメニューは **アプリに転送（かんたん）...** と **アプリに転送（通常）...** の2つです。上のメニューバーの **VR Vlog** にも同じ2つが同じ順に並び、Hierarchyで選んでいるアバターを転送します。アバターの一番上のオブジェクトを1つだけ選んでいないときは、どちらも灰色で選べません。かんたんは、表情ボードを画面に出さずに準備し、表情ボードで何も変えずに通常で書き出した場合と同じ内容（表情はそのアバターで前に決めた割り当て、無ければ自動。書き出さないオブジェクトはそのアバターに記録した設定）を、下の手順だけで転送します。通常は、先に表情ボードで表情と書き出さないオブジェクトを決めます（[通常の流れ](#アプリに転送通常)）。VRMファイルだけを保存するときは、通常の3ページ目で **VRMを保存** を押します。

1. Hierarchyでアバターの一番上のオブジェクトを1つ選んで右クリックし、**VR Vlog → アプリに転送（かんたん）...** を選びます。メニューバーの **VR Vlog → アプリに転送（かんたん）...** でも同じです。
2. **名前** を確認します。初期値は、このアバターで前に転送の書き出しに成功したときの名前です（プロジェクトの `UserSettings` にアバターごとに記録）。記録が無ければオブジェクト名です。名前はアプリのアバター一覧に表示されます。末尾の `.vrm` と見えない文字（制御文字・書式文字）は除いて表示するので、名前が `.vrm` だけや見えない文字だけのときは、名前が入っていないものとして扱い、**QRコードを作る** を押すと名前の欄を赤字にします。
3. **利用規約を読む** で[利用規約](https://vrvlog.fun/terms/)を確認し、同意にチェックを入れます。同意は保存しません。ウィンドウを開くたび、アバターを替えるたびに確認します。[プライバシーポリシー](https://vrvlog.fun/privacy/)にまだ同意していない場合は、その同意の行も表示します。こちらの同意はこのPCのUnity Editorに保存します。
4. 作者名（必須）を確かめます。VRMに記録するライセンス設定は **VRMの利用条件** を開くと変えられます。この欄は最初は閉じていて、閉じたままでも1行で今の設定を表示します。開いた・閉じたはこのPCのUnity Editorの設定に記録します。作者名は、このアバターで前に書き出したときの作者名（このPCのUnity Editorの設定に記録）を初期値にします。ライセンス設定は、このアバターで前に書き出したときの設定（アバターごとに記録）を初期値にします。記録が無ければ既定値から始めます。書き出すたびに、ここで決めたライセンス設定をアバターごとに記録します。作者名が空のあいだは欄の下に「VRMには作者名が必要です」と表示します。書き出しに失敗したあとの **もう一度** でも、作者名が空なら入力の画面に戻ります。
5. **QRコードを作る** を押します。名前・作者名・同意などが足りないまま押すと、何も始めずに足りない欄を赤字で示します。同意の欄とボタンはウィンドウの下に固定され、入力欄をスクロールしても隠れません。書き出し、暗号化、アップロードの順に進み、完了すると残り時間と、QRの場所にぼかした模様と **QRを表示** のボタンを出します。QRは **QRを表示** を押すまで作らず、描きません。模様は固定の画像で、QRとしては読めません。模様の右下には、どの言語でも「SAMPLE」と表示します。表示中は「スマホのカメラで読み取る」の行の右端の **QRを隠す** で模様に戻せます。期限切れや中止のあとに **QRを作り直す** で作った新しいQRも、**QRを表示** を押すまで隠れています。QRの中央にはアプリのアイコンを、QRの場所の四隅には青い読み取り枠の印を出します。アイコンを重ねても読めるように、QRは誤り訂正のレベルHで作ります。名前が長くレベルHで1つのQRに収まらないときは、これまでと同じレベルMで作り、アイコンを出しません。「QRができたら音を鳴らす」の音は、**QRを表示** を押す前のQRができた時点で1回鳴らします。QRの下には、スマホのアイコン付きの「スマホのカメラで読み取る」を、QRを表示する前から警告アイコン付きの「QRを他の人に見せたり配信に映したりしないでください」を表示します。注意は赤字でほかの文字の2倍の大きさです。ウィンドウの幅に収まらないときは折り返します。書き出す内容は、表情ボードで何も変えずに通常で書き出した場合と同じです。かんたんでは、自動設定できなかった項目の確認（書き出し結果の一覧）を出さずにアップロードへ進みます。表情ボードに直すところ（保存した書き出さないオブジェクトでプレビューを作れないなど）があるときは、「表情の割り当てを直すと作れます」と、続けて直すところの理由を表示して止まります。**表情とオブジェクトを選ぶ** で通常に切り替えて直してください。書き出しを止める失敗は、下のとおり理由を表示して止まります。書き出しの詳細（警告など）は、通常と同じくConsoleに出します。
6. スマホのカメラでQRを読み取り、VR Vlogで受け取ります。受け取りが終わると、ウィンドウに **アプリに取り込みました** と表示します。

画面の上の「表情は前回の割り当て（なければ自動）・書き出さないオブジェクト N件」の行の **表情とオブジェクトを選ぶ** を押すと、同じアバターで通常の流れに切り替えます。

### アプリに転送（通常）

1. 右クリックかメニューバーで **VR Vlog → アプリに転送（通常）...** を選びます。表情ボードが開き、そのアバターで **書き出しを準備** まで進みます。
2. 表情ボードの1ページ目で、表情をVRMの表情5枠・**その他の表情**・**書き出さない表情** へ振り分けます。
3. **次へ：除外するオブジェクト** を押し、外すオブジェクトを **除外するオブジェクトを追加** で選びます。選んだオブジェクトはアバターごとに記録し、かんたんと共通です。
4. **次へ：VRMの保存と転送** を押します。変えた除外を、表情の割り当てを保ったままプレビューへ反映してから、表情ボードの3ページ目「3 VRMの保存と転送」に進みます。3ページ目には、VRMの情報の代わりに転送の画面を表示します。作者名と利用条件もここで入力します。
5. 3ページ目の転送の画面で、かんたんの手順2〜5と同じく名前・利用規約の同意・**VRMの利用条件** を確認して **QRコードを作る** を押します。表情ボードの今の割り当てと除外で書き出します。自動設定できなかった項目があるときは、書き出し画面と同じ確認を出し、**設定を変更する** を選ぶとアップロードせずに止めます。

ボタンは左から **戻る**、**VRMを保存**、**QRコードを作る** の順です。**QRコードを作る** が青いボタンです。書き出しを始めると **VRMを保存** は **戻る** のすぐ右に移ります。かんたんのウィンドウでは左端に **VRMを保存**、右端に **閉じる** を出します。QRの表示中は作り直しのボタンを出しません。期限切れと中止のあとは、QRの場所に **QRを作り直す** を出します。保存の結果と **保存先を開く** はボタンの下の行に出します。

**戻る** で2ページ目に戻れます。アップロード中とQRの表示中に **戻る** を押すか、メニューの **アプリに転送（通常）...** で別のアバターに替えて3ページ目を離れるときは、「転送を中止」の確認（「このQRコードは使えなくなります」）を出します。**中止して移動** を選ぶと転送を中止して移り、**転送を続ける** を選ぶと3ページ目のまま転送を続けます。中止で削除するのは転送用の一時VRMだけで、**VRMを保存** で保存したファイルは消しません。表情ボードを閉じたときは確認を出さずに転送を中止し、転送用の一時VRMを削除します。アップロード中とQRの表示中は、QRと進捗の近くに「ページを移るかボードを閉じると転送を中止します」と表示します。別のアバターで **アプリに転送（通常）** を選ぶと、表情ボードは1ページ目からやり直します。3ページ目のQRは、表情ボードの高さに収まる大きさで表示します（QR本体は200pt以上。それより低いとスクロールします）。「QRを他の人に見せたり配信に映したりしないでください」は1行で、幅に合わせて文字を小さくします。表情ボードを開き直したときに戻るのは、VRMの表情5枠の割り当てと書き出さないオブジェクト（どちらもアバターごとの記録）です。追加した表情ファイルとポーズは入れ直しになります。表情ボードに直すところ（割り当てのエラー、反映していない書き出さないオブジェクトなど）があるあいだは、「表情の割り当てを直すと作れます」と表示し、**QRコードを作る** を押せません。

一時保存と受取期限の扱いは[接続条件と一時保存](#接続条件と一時保存)のとおりです。期限は転送の作成から3分で、アップロードにかかった時間も含みます。残り時間のバーは、QRができた時点の残りを全体として減っていきます。QRを隠しているあいだも減ります。期限が切れたら **QRを作り直す** で、書き出し済みのVRMからアップロードし直します。かんたんのウィンドウを閉じると、進行中の転送を中止し、転送用の一時VRMを削除します。アップロード中や読み取り待ちに同じアバターの **アプリに転送（かんたん）** を開くと、転送を続けたままウィンドウを前に出します。かんたんと通常を切り替えたときは、表示中のQRが今の内容と違うことがあるので、QRを作り直してよいか確認します。別のアバターを選んだ場合は、転送を中止してよいか確認します。

転送（アップロード中かQRの表示中）はUnity Editor全体で1つです。かんたんのウィンドウと表情ボードの3ページ目の一方が転送しているときに、もう一方で **QRコードを作る**・**もう一度**・**QRを作り直す** を押すか対策画面から保存すると、「転送を始める」の確認を出します。本文は相手がアップロード中なら「「アプリに転送（かんたん）」のアップロードを中止します。」、QRの表示中なら「「アプリに転送（かんたん）」で表示中のQRは使えなくなります。」のように相手を名指しします。**中止して始める** を選ぶと相手の転送を中止して一時VRMを削除し、相手を名前と同意の画面に戻してから始めます。**戻る** はダイアログを閉じるだけで、どちらの画面もそのままです。転送の画面を開くだけでは相手の転送を止めません。

QRの中身は `vrvlog://import#` で始まるリンクです。0.11.15の **QRコードでスマホに送る** のQRと同じ8項目を、URLのフラグメントに入れています。受取用の認証情報と復号鍵を含むので、共有・撮影しないでください。リンクが4096文字を超える名前や、1つのQRに収まらない名前では、QRを作る前に **名前を短くすると作れます** と表示します。

書き出しの途中の段階（材質の変換など）が失敗したときは、かんたんも通常も、書き出し画面と同じく失敗した段階を省いて書き出し、省いた段階を書き出し結果の一覧に出します（かんたんはConsoleに、通常は確認として出します）。この扱いはUnity Editorの設定 `VRVlog.LilToonExporter.ContinueOnStageFailure`（既定はオン）に従い、オフにするとかんたんも通常も失敗した段階で止まります。表情ボードの **VRMを保存** は、この設定にかかわらず失敗した段階で止まります。書き出しに失敗した場合は、その場に理由と **もう一度** を表示し、書き出し画面と同じ対策画面を開きます。対策画面から保存すると、そのままアップロードへ進みます。書き出しの失敗・取り消しでアップロードに進まなかったときは、転送用に書き出した一時VRMをその場で削除します。

**VRMを保存** と **QRコードを作る** は、どちらを先に押しても書き出しは1回です。QRを作ったあと（アップロード中・読み取り待ち・スマホへの保存の完了後・期限切れのあとも）に保存すると、送った一時VRMをそのまま保存先へコピーし、コピーしたファイルのSHA-256が送ったものと一致しなければ削除して「保存できませんでした」と表示します。転送の書き出しで失敗した段階を省いたときは、送ったファイルは保存に使わず、**VRMを保存** と同じく書き出し直します（失敗した段階で止まり、対策画面が出ます）。転送用の一時VRMは、スマホへの保存が完了しても消さず、別のアバターを選ぶ・新しい書き出しを始める・画面を閉じる・表情ボードの3ページ目を離れるまで残します。先に保存したときは、名前・作者名・VRMの利用条件が保存したときと同じで、アバター（メッシュ・マテリアル・オブジェクトの有効と無効など、表情ボードが「元のアバターが変更されました」で見るもの）と、保存された表情ボードの選択・書き出しの設定が保存のあとに変わっていなければ、保存したファイルを転送用にコピーして送ります。保存の結果の行は「（ファイル名）を保存しました・このファイルを送ります」になります。シーンを変えたあとは、この行は「（ファイル名）を保存しました」に戻り、QRを作るときにアバターを確かめて、変わっていなければ保存したファイルを、変わっていれば書き出し直したものを送ります。アバターをシーンで動かす・回すだけなら変わったとみなしません。保存したファイルが保存のあとに書き換わっていた（SHA-256が違う）ときと、画面を離れたあとは、改めて書き出して送ります。利用規約とプライバシーポリシーの同意は、どちらの順でもQRを作る前に必要です。

転送用の一時VRMと暗号化したコピーは、OSの一時フォルダー、Unityの一時キャッシュ、プロジェクトの `Temp`、ユーザーのローカルアプリデータの `VRVlog` の順に、書き込めて空き容量（512MiB）のある場所へ置きます。空き容量の足りない場所は、ほかに書き込める場所がないときだけ使います。どこにも書き込めないときは、書き出す前に「転送用の一時ファイルを置ける場所が見つかりません」と表示して止めます。Unityが異常終了して残った転送用の一時ファイルは、1日たったものを次の転送のときに削除します。

## 接続できないとき

| 状況 | 対処 |
| --- | --- |
| アップロード失敗／受付上限 | インターネット接続を確認し、**QRを作り直す** を押す。混雑時は時間を置く。通常のVRMファイル書き出しも利用できる。 |
| QRが読み取れない | スマホのカメラで読み取り、OSのカメラからの取り込みに対応したVR Vlogか確認する。読み取れないときはVRMを保存し、ファイルで読み込む。古いLAN QR・QR v2は利用できない。 |
| 期限切れ／転送中止 | PCで **QRを作り直す** を押す。PC・スマホの日時も正しく設定する。 |
| スマホ保存完了、PCの状態確認に失敗 | アバターを再受信する必要はない。PCの接続を確認するか転送画面を閉じる。残っている転送用コピーも受取期限で削除される。 |
| 容量やSHA-256が一致しない | 受信ファイルを採用せず、新しい転送を作成する。 |
| 転送画面を閉じた／Unityを再読み込みした | 待機中の転送を中止し、PCの転送用一時ファイルを削除する。必要なら改めて書き出す。 |
| 転送用の一時ファイルを置ける場所が見つからない | ドライブの空き容量と、一時フォルダーへの書き込み権限を確認する。通常のVRMファイル書き出しも利用できる。 |

## 検証の範囲

開発時のホスト試験では、独立Python生成の共通ベクトルと実際のC#ストリーム暗号化を比較し、合成データとfake transportで暗号文のmultipart分割、復号した元ファイルとの一致、HTTPへの鍵・元のメタデータの非送信、再発行時の鍵・IV更新、公開完了前のQR非表示、中止の競合、期限切れ、一時ファイルの後始末を検査します。既存LANは無効のままで、旧プロトコルのTLS loopback回帰も継続します。

**アプリに転送** は、リンクの組み立て（アプリと共通のベクトル）と、ウィンドウが出す状態・残り時間・期限切れ・後始末を同じホスト試験で検査します。

暗号化プロファイルは [RFC 7518 A256CBC-HS512](https://www.rfc-editor.org/rfc/rfc7518.html#section-5.2.5) です。PCは標準のAES-256-CBC/PKCS7とHMAC-SHA-512を使い、元の名前・容量・SHA-256を認証対象に含めます。サービスは暗号文の容量・ハッシュ、通信元、時刻、転送状態を扱います。E2E暗号化はPCやスマホ自体、QRを撮影・共有した場合のアクセスを保護するものではありません。

クラウドサービスへの実アップロード、配布パッケージとAndroid・iPhone配布版の一連の転送、対応Unity 2022.3 Editorのコンパイル・画面・テストは別途確認が必要です。ホスト試験や別Unity版の参照DLLコンパイルを、これらの実機確認として扱いません。

## 低速回線と中国・VPN経由での接続

転送先は固定のHTTPSサービスです。VPNの接続表示やブラウザーでの閲覧成功だけでは、
Unityの通信が同じ経路を使えるかは確認できません。アプリ別の経路やプロキシ設定を確認し、
QRや復号鍵を診断情報へ含めないでください。中国・VPNの実回線での利用成功は未確認です。

旧サービスではアップロードとスマホ受信を作成から3分以内に終える必要があるため、
送信が進んでいても容量と実効速度によってQR発行前に期限切れになります。
対応Workerが新しいアップロード経路を有効化している場合、このExporterは作成前の能力確認で
その経路を選び、アップロード最大15分と公開確定から最大3分の受取期限を分けます。
未対応・無効時は従来の3分契約です。作成の応答を失った後に別経路で二重作成はしません。
新経路では1分割の通信は最大270秒で、元のアップロード期限も超えません。
QRはv3のまま、送信先の追加や証明書検証の解除は行いません。
このソース変更はWorkerの本番配備や利用環境での正常動作を示すものではありません。

クラウドへ接続できない場合は、通常のVRMファイルを書き出し、本人が利用できる方法で
スマホへ移してファイルとして取り込む既存経路も利用できます。
