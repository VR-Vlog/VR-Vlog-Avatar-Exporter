# 閉眼用の変形が見つからないときも書き出しを止めない

- 日付: 2026-10-13
- 対象: `Editor/BlinkShapeNames.cs`・`Editor/BlinkExportSession.cs`・`Editor/UniVrmOneClickExporter.cs`

## 背景

販売中の VRChat 用アバター 8 体で書き出しを試したところ、2 体が「閉眼用の変形を特定できません。「確認・調整」で選択するか「瞬きなし」を指定してください。」で止まった。

- 1 体は `eyelid_Blink`・`eyelid_Blink.L`・`eyelid_Blink.R` と VRChat SDK の `vrc.blink_left`・`vrc.blink_right` を持っていたが、どちらも自動判定の名前表に無かった。
- もう 1 体（2018 年の SDK2 用アバター）は閉眼に当たる名前が表に一つも無かった。

自動判定は「正確な名前だけを使い、推測しない」方針（`eye_close` が目の間隔の意味で使われる例がある）で、この方針は残したい。

## 決定

- `eyelid_Blink`（両目）と `eyelid_Blink.L`/`.R`、`vrc.blink_left`/`vrc.blink_right`（左右）を、既存の名前表とは別の「後回しの名前」として加える。既存の名前・Unified Expressions の閉眼・片側だけの候補のどれも無いときにだけ使うので、これまで自動で決まっていたアバターの選ばれ方は変わらない（`Blink` と `vrc.blink_*` を両方持つアバターも、従来どおり `Blink` だけを使う）。
- 自動設定で、正確な名前の候補も片側だけの候補も一つも無いときは、書き出しを止めずに「瞬きなし」にし、次の警告を出す。

  `閉眼用の変形が見つからないため瞬きなしで書き出しました（「瞬き」の「確認・調整」で手動選択）`

  画面の「瞬き」欄には「瞬きなし（閉眼用の変形が見つかりません）」と出し、隣の「確認・調整」から手で選べる。
- 名前の重複・左右がそろわない・片側だけ見つかった、のように候補があるのに確定できない場合は、これまでどおり明示の選択を求める。
- 線引き（2026-10-14 追記）。瞬きなしへ切り替えるのは、瞬きの設定が「自動」で、元の VRM の瞬き設定も VRChat の閉眼設定も無く、書き出し対象のメッシュに閉眼の候補名（正確な名前・Unified Expressions の閉眼・片側だけの候補・後回しの名前。動かない変形でも名前があれば数える）が一つも無いとき。Unified Expressions の名前や追跡プロファイル（`VrmTrackingMarker.profile`）を持つが追跡経路が使えないアバターも、この条件なら同じく瞬きなしにする。Unified Expressions の追跡経路が使えるアバターは従来どおり瞬きなしを許し、書き出したファイルに使える経路が残っているかの検査（`RequiresUnifiedEvidence`）も従来どおり行う。
- 従来の「閉眼が無ければ、使える Unified Expressions の経路が無い限り止める」検査は、瞬きができないアバターを止めるためのもので、Unified Expressions の経路そのものを守る検査（Modular Avatar / NDMF で追跡用の変形が失われたときの停止など）とは別にある。後者は今回の変更の影響を受けないので、追跡経路が使えないアバターも警告付きの瞬きなしに揃えた（mk の指示で、既存テストを新しい挙動に合わせる方を採った）。

## 検討した代替案と不採用理由

- 名前に `blink`・`close`・`まばたき` を含む変形を広く拾う: 推測しない方針に反し、目の間隔や表情の変形を瞬きとして使うおそれがある。
- これまでどおり止める: 瞬きは無くても使えるのに、書き出し全体ができない。

## 影響

- 閉眼の候補が無いアバターは、瞬き無しの VRM として書き出せる。
- 顔のメッシュを非表示にしたり書き出し対象から外したりした場合も、閉眼の名前が書き出し対象に無くなるので、エラーではなく警告付きの瞬きなしになる。誤って顔を外したときは、警告と画面の「瞬き」欄の表示で気づく前提にした。
- `vrc.blink_left/right` か `eyelid_Blink` 系だけを持つアバターは、自動で瞬きが設定される。
- 単体テスト `AmbiguousOrPartialNamesNeedAnExplicitChoice` は、未知の名前だけの場合に例外ではなく瞬き無しになることを確かめるテストへ置き換えた（`UnknownClosingNamesExportWithoutBlinkInsteadOfGuessing`）。
- 最初の版は瞬きまわりの一部のテストスイートだけを回して出したため、`UnifiedExpressionExportTests` の 61 件と `PreparedNeutralEligibilityTests` の 1 件が「例外が出ない」で落ちることに気づかなかった。PR の CI は Unity のテストを回さない。62 件はどれも「閉眼が無く、使える追跡経路も無いと書き出しが止まる」ことを確かめていたテストなので、mk の指示で、テスト名と残りの検査はそのままに、止まる代わりに書き出しが通り警告 `BlinkExportSession.MissingAutomaticWarning` が出ることを確かめる形に直した。

## 未決

- 失敗画面に「瞬きの BlendShape を手で選ぶ」専用の導線を足すか。今回は警告文と既存の「確認・調整」ボタンで足りるとした。
- Unified Expressions の名前を持つのに経路が使えないアバターで、瞬きなしの警告とは別に「追跡経路が使えない」ことも知らせるか。今回は瞬きなしの警告だけにした。
- テストを広く回さなかったことが今回の見落としの原因なので、変更した機能に関わる Unity のテストの範囲をどう決めるか（アセンブリ全体を回すか、CI で回すか）。
