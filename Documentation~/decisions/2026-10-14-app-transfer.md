# Hierarchy の右クリックから「アプリに転送」で QR まで進める

- 日付: 2026-10-14
- 対象: `Editor/LanTransfer/AppTransferWindow.cs`・`Editor/LanTransfer/AppTransferWindow.uxml`・`Editor/LanTransfer/AppTransferWindow.uss`・`Editor/LanTransfer/AppTransferFlow.cs`・`Editor/AppTransferExport.cs`・`Editor/LanTransfer/CloudTransferProtocol.cs`・`Editor/LanTransfer/CloudVrmTransferSession.cs`

## 背景

既存の **QRコードでスマホに送る** は、書き出し画面で VRM を保存してから転送画面を開き、アプリ内の受け取り画面のカメラで QR を読む手順になっている。VR Vlog 側で、スマホの OS のカメラで読んだリンクからアプリを開いて受け取りを始める取り込みに対応したので、Exporter 側でも短い手順で QR まで進めたい。

## 決定

- Hierarchy のアバターの一番上（Animator を持ち、親に Animator が無いオブジェクト）を 1 つ選んだときだけ、右クリックの **VR Vlog → アプリに転送…** を出す。クラウド転送が無効な版（`CloudTransferAvailability.Enabled` が false）では出さない。
- ウィンドウ 1 枚で、名前・利用規約の同意・プライバシーポリシーの同意・VRM の利用条件を決め、**QRコードを作る** で書き出し・暗号化アップロード・QR の表示まで進める。書き出しは **VRMを書き出す** で表情・ポーズを追加せずに保存した場合と同じ処理を使う。
- QR の中身は `vrvlog://import#` で始まるリンクで、既存の QR と同じ 8 項目を URL のフラグメントに入れる。フラグメントにしたのは、端末側でアプリを起動するときのログに残りにくいため。名前は RFC 3986 の非予約文字以外をすべて `%XX` にする。
- プライバシーポリシーの同意は、既存の **QRコードでスマホに送る** と同じ保存された選択・リンク・文言を共有し、未同意ならアップロードしない。新しい同意の文言は作らない。
- 有効期限は転送サービスの 3 分のまま（アップロードの時間を含む）。期限が切れたら読める QR を残さず、灰色の枠と **QRを作り直す** を出す。
- 転送中に同じアバターでメニューを開いたときは、ウィンドウを前に出すだけで転送を続ける。別のアバターへ替えるときは、進行中の転送を中止する前に確認する。
- ウィンドウは UI Toolkit で作り、構造を UXML、見た目を USS に分ける。文言は UXML に書かず、C# からすべて `ExporterLocalization.T` を通して入れる（ロケールの検査が C# の文字列を見ているため）。UXML と USS は C# の隣に置き、.meta の GUID で読み込む（パッケージのパスを書かない）。
- VRM の利用条件の欄は、書き出し画面と共有している IMGUI の部品（`AppTransferExport.DrawTerms`）をそのまま `IMGUIContainer` に入れる。
- QR は UI Toolkit の中央寄せだと端末の半ピクセルに乗ることがあるので、QR の枠の位置を C# で計算して端末のピクセルにそろえる。各行の高さは固定し、状態が変わっても下の行が動かないようにする。
- QR を表示している間、QR の下に警告アイコン付きで「QRを他の人に見せたり配信に映したりしない」を出す。QR を持つ人はアバターを受け取れるので、配信や画面共有に映さないことをその場で伝える。この行は QR を表示していない状態でも高さを取っておく。
- **QRコードを作る** を押せない理由の行は警告色（暗いテーマは黄、明るいテーマは茶）で出す。押せない理由の行とボタンはスクロールの外（ウィンドウの下）に固定する。作者名が空のときは VRM の利用条件の欄が開いたままになり、フォームの中に置くとボタンが画面の外へ出るため。
- 利用規約の同意の文と利用規約のリンクは、2026-10-14 のオーナーの指示でモックの文言のまま採用した。法的な文言なので、オーナーの承認なしに一字も変えず、翻訳もしない（英語などの表示でも日本語のまま出す）。
- クラウド転送を有効にする版の判定（`CloudTransferAvailability.IsSupportedVersion`）は変えない。安定版ごとに転送を採用するリリースの方針どおり、次の安定版を出すときに判定を更新する。

## 検討した代替案と不採用理由

- https のリンク（App Links／Universal Links）にする: 案内ページと関連付けのファイルを置く https のホストと、アプリ側の設定が要る。カスタムスキームを OS のカメラが開かない機種が見つかったときに改めて検討する。
- 有効期限を 10 分にする: 転送サービスの期限を延ばすか、期限の前に上げ直して QR を差し替える仕組みが要る。今回は既存の 3 分に合わせた。
- IMGUI のまま作る: オーナーが Editor 側の UI に UI Toolkit を使う方針を示し、UXML+USS で作ると伝えてある。レイアウトと見た目を C# から分けられる。
- UXML を使わず C# だけで UI Toolkit の要素を組む: 構造が C# に埋もれ、USS との対応も追いにくい。
- VRM の利用条件を UI Toolkit で作り直す: 書き出し画面と同じ部品を 2 つ持つことになり、片方だけ直す事故が起きる。共有を優先して IMGUIContainer に入れた。
- 既存の **QRコードでスマホに送る** の QR をリンクに置き換える: 古い版のアプリが読めなくなるので、既存の QR は変えずに入口を分けた。

## 影響

- 既存の **QRコードでスマホに送る** の QR と手順は変わらない。VRM の利用条件の入力欄は書き出し画面と同じ部品を共有する（描画を分けただけで挙動は同じ）。
- OS のカメラからの取り込みに対応していない版のアプリでは、この QR を読んでもアプリが開かない。
- パッケージに入れるファイルの拡張子に `.uxml` と `.uss` を加えた（`Tools/build-package.py`）。`Editor/LanTransfer/` の下にあるので、転送を含まない版には入らない。

## 未決

- 利用規約の同意の文の翻訳。法的な文言なので、オーナーの承認があるまで日本語のまま出す。
- アプリ側のリンクの解析と同じベクトルを使うテストは、Exporter 側のテストのサンプル名を一般名に替えたので、アプリ側のテストのサンプル名もそろえる必要がある。
- 実機で OS のカメラから QR を読んで取り込むところまでは、この PR では確かめていない。
- UI Toolkit の画面は Unity 2022.3.22f1 の Editor（ダークテーマ・表示倍率 100%）で、フォーム・アップロード中・QR の表示中・期限切れを目視で確かめた。明るいテーマと 100% 以外の表示倍率は確かめていない。
