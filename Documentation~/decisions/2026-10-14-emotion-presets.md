# 喜怒哀楽の標準表情を書き出し画面で指定できるようにする

- 日付: 2026-10-14
- 対象: `Editor/ExperimentalExpressionCaptureSession.Presets.cs`・`Editor/ExperimentalExpressionCaptureSession.cs`・`Editor/ExperimentalExpressionCaptureWindow.cs`・`Editor/ExpressionPresetStore.cs`・`Editor/UniVrmOneClickExporter.cs`

## 背景

これまでの書き出しは、VRM 1.0の標準表情のうち口（aa など）と瞬きだけを自動で埋め、喜怒哀楽の happy・angry・sad・relaxed・surprised は空のまま保存していた。元のアバターに Vrm10Instance があり、そこに作者が設定した喜怒哀楽があればそれを保持するが、VRChat 用アバターではほとんど無い。

表情・ポーズ指定UI（「VRM書き出し」）では、FaceEmo・Controller の表情ファイルを追加して `VRChat / 記録 / <名前>` のカスタム表情として保存できる。喜怒哀楽を読む VRM アプリやツールのために、同じ表情を標準表情にも割り当てたい。

## 決定

- 画面の「追加した表情」と「全身ポーズ」の間に **標準の表情（喜怒哀楽）** の5行を置く。各行のプルダウンで次のどれかを選ぶ。
  - 追加した表情、FaceEmo の登録、アバターの Controller が参照する表情ファイル（候補ファイルと同じ範囲）。値は追加した表情と同じくクリップ終端の BlendShape 値。
  - 書き出すメッシュの BlendShape 1つ。値は100。
  - なし。
- 対象は happy・angry・sad・relaxed・surprised だけにする。口・瞬き・視線・neutral は既存の自動設定と衝突させないため選べない。
- 名前から判断できる候補を初期値として入れ、行に **自動** と出す。× で「なし」にできる。候補の探し方:
  - 対象の名前は、追加した表情・FaceEmo の登録・アバターの Controller（FX・Gesture・MA で統合される Controller を含む）が参照する表情ファイルの名前と、書き出すメッシュの BlendShape 名。
  - BlendShape 名は英語の語だけで判定する。日本語の BlendShape 名は MMD の標準モーフ（`怒り` は眉、`びっくり`・`なごみ` は目、`にっこり` は口だけ）であることが多く、顔の一部だけの標準表情が既定で入るのを避けるため。日本語の BlendShape も手では選べる。VRoid 系の部位の略記（`BRW`・`MTH`）も除外語に入れた。
  - 元のアバターの Vrm10Instance に作者が設定した喜怒哀楽がある表情は、自動候補で置き換えない。行は「元のVRM設定」と表示し、ユーザーが選んだときだけ置き換える。
  - 語表は2段。0段目は感情そのものを表す語（`smile`・`angry`・`sorrow`・`fun`・`surprise`・`笑顔`・`怒` など）、1段目はゆるい語（`joy`・`cry`・`笑`・`泣` など）。英語は記号・数字・大文字の区切りで分けた単語と完全一致（`function` は `fun` にならない）、日本語は名前の中の部分一致。
  - 同じ段で2つの感情に当たる名前（`smile_angry`・`泣き笑い`）と、目・口・眉・頬・左右（`L`/`R` を含む）・ウィンク・瞬き・解除・off/reset を含む名前は候補にしない。
  - 感情ごとに、段の小さいもの → 追加した表情 → 登録済みの表情ファイル → BlendShape の順に選び、基準の顔と形が同じものなど保存できないものは飛ばす。
  - 語表の全語をテスト（`EveryVocabularyWordSuggestsItsEmotionAndTier`）で確かめる。
- 自分で選んだ行は、プルダウンの「自動の候補に戻す」で自動に戻せる。
- 保存できない指定（元のファイルの変更でエラーになったもの）があると「VRMを保存」を無効にし、ボタンの近くに該当する表情名を出す。自動で入った値がエラーになった場合は、候補を選び直す。
- 自分で選んだ内容と「なし」にした内容は、プロジェクトの `UserSettings/VRVlogLilToonExporter/ExpressionPresets.json` にアバターごと（シーン上のオブジェクトの `GlobalObjectId`）に保存し、次に準備したときに読む。自動の候補は保存せず、毎回名前から選び直す。読めないファイル・削除された表情ファイル・不正な種類の指定は外して続行し、画面に一行出す。
- 記録データ（`ExperimentalExpressionCaptureSession.Settings`）にも `Presets` を足した。`Version` は1のまま。`Presets` の無い古い記録は「指定なし」として読む。種類の重複・口などの種類・表情ファイルと BlendShape の両方を持つ指定は読み込みを拒否する。
- 出力の形:
  - 記録した表情は従来どおり `VRChat / 記録 / <名前>` のカスタム表情として残し、標準表情は別の表情として足す。カスタム表情の名前を変えない。
  - 標準表情は `isBinary: false`、瞬き・口・視線の override は `blend`。重み1では `block` と同じく瞬き・口・視線を止め、途中の重みでは比例して弱める。
- 書き出し経路:
  - 記録した表情がある場合（従来の記録経路）は、記録した表情と同じく基準の顔との差分を新しい morph target として焼き込み、標準表情に割り当てる。
  - 記録した表情が無く標準表情だけを指定した場合は、通常の書き出し経路のまま、その一時コピーに作者設定の VRM 表情として標準表情を足す（`UniVrmOneClickExporter.Export` の `authorCopyExpressions`）。既存の作者設定の表情と同じ識別子の追跡・MA/NDMF 後の付け替え・基準形からの焼き込みを通るので、VRChat のメニュー表情や FaceEmo の表情を失わない。元のアバターの Vrm10Instance は変更しない。元のアバターに Vrm10Instance が無い場合に作る設定には lookAt・firstPerson を入れず、出力に新しく現れないようにする。
- 何も指定しない場合は、どちらの経路も従来とまったく同じ呼び出しになる。
- SoulFlame VRM Exporter 0.6.1 の表情タブ（13 の標準表情の編集、FX・FaceEmo・CGE のクリップを候補として提示する考え方）と、クリップ名を2段の語表で判定する考え方（感情そのものの語 → ゆるい語、日本語は部分一致・英語は単語一致）を参考にしたが、考え方の参考のみで、コードと語表は移植していない。語表・単語の分け方・除外語はこのリポジトリで独自に選んで書いた。

## 検討した代替案と不採用理由

- 記録した表情の行ごとに「標準の表情」欄を足す: 指定できる対象が「追加した表情」に限られ、FaceEmo の表情を一度追加しないと選べず、BlendShape も選べない。表情ごとに1行の表のほうが、どの標準表情が埋まっているかが一目で分かり、同じ標準表情への二重割り当ても起きない。
- 標準表情だけの指定でも記録経路を使う: 記録経路は VRChat の記述子と Animator を外して書き出すため、VRChat メニューの表情や FaceEmo の表情が消える。自動候補が入るだけで出力が大きく変わるので採らない。
- カスタム表情を標準表情へ移す（カスタム側を消す）: アプリは表情アニメーション（`VRVLOG_expression_animations`）をカスタム表情の名前で引き、名前が一つでも合わないとアニメーション全体を捨てる。既存の表情の動きが消えるので採らない。
- 指定をアバターのコンポーネントに保存する: アバターの元データを変えることになり、変更検出（ソースの指紋）で書き出し準備をやり直す必要が出る。VRChat へのアップロード時に不明なコンポーネントとして扱われるおそれもある。
- SoulFlame VRM Exporter の語表をそのまま使う: 移植になり、MIT の著作権表示（同ツールと、その元になったツールの両方）を同梱する必要がある。必要な語は一般的な語彙で、独自に選んでも同じ目的を果たせるので、考え方だけを使った。
- EditorPrefs に保存する: PC 全体で共有され、プロジェクトをまたいで同じアバターの識別子が衝突しうる。
- 標準表情も `isBinary: true`・`block` にする（記録した表情と同じ）: 顔追跡などから途中の重みで動かすと0.5で切り替わり、少しでも重みが入ると瞬き・口が止まる。重み1の見た目は `blend` と同じなので、連続値の扱いを選んだ。

## 影響

- VR Vlog アプリ側の読み込みを確認した（このリポジトリ外のコードの読み取りのみ。アプリは変更していない）。
  - 通常の顔追跡・リップシンク・自動瞬き・待機演出は、喜怒哀楽の標準表情を動かさない。顔追跡の Joy/Angry などの値は、同じ名前の BlendShape をメッシュから直接探す経路で、VRM の標準表情は使わない。
  - 表情一覧は標準表情とカスタム表情を両方並べる。同じファイルを標準表情とカスタム表情の両方に使うと、一覧に `happy` と `記録 / <名前>` の2行が出る。選べる表情は1つなので、同時に二重にかかることはない。
  - 一覧で標準表情の行を選んだ場合は、カスタム表情に付く表情アニメーションは再生されず、静止した顔になる。
- 何も指定しない・すべて「なし」のときの出力は従来と同じ（Unityテスト `WithoutAssignmentsTheExportedExpressionsAreUnchanged` で、通常経路と記録経路の両方の表情データが一致することを確認）。
- 名前から候補が見つかったアバターでは、初めて画面を開いたときから標準表情が入った状態になり、何も操作せずに保存すると従来と出力が変わる（自動候補を初期値にする指示による）。保存前に行の **自動** 表示で確認し、不要なら × で外す。
- 通常の書き出し経路では、表情ファイル中の値0の BlendShape は標準表情に含めない（作者設定の VRM 表情で0は「その変形を使わない」意味になるため）。基準の顔で0以外の値を持つ変形を0に戻す表情ファイルは、その変形だけ基準の値のままになる。記録経路では基準の顔との差分を焼き込むので、この差は出ない。

## 未決

- アプリの表情一覧に同じ顔が2行並ぶことを許容するか（アプリ側で中身が同じ標準表情を一覧から外す等）は、アプリ側の判断とした。
- 口・瞬き・視線・neutral の指定は今回扱わない。
- 元の VRM 設定にある喜怒哀楽を、画面から「空にする」操作は無い（「なし」は元の設定を残す）。

- UniVRM 0.131 の `VRM10ObjectExpression.AddClip` と override の重みの計算
- SoulFlame VRM Exporter 0.6.1（CucumberWorks・MIT）の表情タブの考え方（コードは移植していない）
