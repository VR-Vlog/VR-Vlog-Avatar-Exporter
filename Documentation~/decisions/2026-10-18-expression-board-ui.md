# VRM書き出しの表情の選び方を表情ボードに変える

- 日付: 2026-10-18
- 対象: `Editor/ExpressionBoard.cs`・`Editor/ExperimentalExpressionCaptureWindow.cs`・`Editor/ExperimentalExpressionCaptureSession.cs`・`Editor/ExpressionPresetStore.cs`・`Editor/Locales/*.json`・`Tests/Editor/ExpressionBoardTests.cs`・`Tests/Editor/ExperimentalExpressionCaptureTests.cs`・`Tests/Editor/ExpressionPresetTests.cs`

## 背景

これまでの書き出し画面では、表情を選ぶ操作が3か所に分かれていた。

- **候補ファイル** のチェックと **選んだ○件を追加** で、カスタム表情として記録するファイルを選ぶ。
- 追加した一覧で、チェックを外して除外し、表情名を変える。
- **標準の表情（喜怒哀楽）** の5行のプルダウンで、喜怒哀楽に使う顔を選ぶ。

同じファイルがカスタム表情と喜怒哀楽の両方に入れられ、どの表情がVRMのどこに入るのかを画面の1か所で確かめられなかった。喜怒哀楽の自動候補がどれなのかも、行ごとに見に行かないと分からなかった。

## 決定

- 画面の中心を表情ボードにする（モックのV1）。上段にVRMの表情5枠（喜び・怒り・悲しみ・安らぎ・驚き）、下段に **その他の表情** と **書き出さない** を並べる。表情はどれも、このうち1か所だけに入る。どこに入るかの判定は `ExpressionBoard` に置き、画面は描画と入力だけを持つ。
- 移す操作はドラッグ＆ドロップを基本にし、同じ移動を右クリックのメニューと **×** にも置く。枠の **×** は **その他の表情** へ戻し、**その他の表情** の **×** は **書き出さない** へ移す。カードを押すとプレビューに顔を出す。
- 枠の見出しのメニューから、BlendShapeと **なし**（元のVRM設定がある枠は **元のVRM設定**）、**自動の候補に戻す** を選べる。
- 見つかった表情は、最初すべて **その他の表情** に入れる。従来の画面では、何も選ばずに保存するとアバターの表情がそのまま入った。最初から一部を外すと、利用者が何もしないうちに表情が減る。外すのは利用者が **書き出さない** へ移したときだけにする。
- 名前から入れた喜怒哀楽はカードに **自動** と出し、**自動の○件をすべて確定** でまとめて手で割り当てた扱いにする。**割り当てをリセット** は、手で割り当てた表情と書き出さない指定を消して名前から割り当て直す。推定の規則そのものは `ExpressionNameInference` のまま変えない。
- 書き出さない指定は、喜怒哀楽の指定と同じ `UserSettings/VRVlogLilToonExporter/ExpressionPresets.json` のアバターごとの項目に `Excluded` として足す。1件はクリップのアセットのGUIDとローカルIDの組で、インスタンスIDやパスは使わない。以前の形式のファイルには `Excluded` が無く、空の一覧として読む。読むときに見つからないクリップは外し、外したことを画面に出す。喜怒哀楽だけを保存する呼び出しでは、記録済みの書き出さない指定をそのまま残す。
- 書き出しの経路は次のように決める。
  - **書き出さない** が0件で、.animを追加していないときは、表情を記録しない従来の通常の書き出しにする。出力はこれまで何も選ばずに保存した場合と同じになる。
  - それ以外は、**その他の表情** の対応している表情を画面の並び順でそのまま記録する。記録する表情が0件になっても（全部を書き出さないへ移した、または喜怒哀楽の枠だけが残った場合）、この経路のままにする。画面はセッションの `Export` に `replaceCustomFaces` を渡し、セッションは表情が0件のときの近道（通常の書き出し、喜怒哀楽だけの書き出し）を通らない。近道を通ると、書き出さないへ移した表情メニューの表情がそのまま残るためである。
  - 通常の書き出しで表情メニューから入った表情が **その他の表情** より少ないときは、同じ保存を記録する経路でやり直す（2026-10-21 追記。経緯は [2026-10-21-board-other-faces-record-fallback.md](2026-10-21-board-other-faces-record-fallback.md)）。
  - どちらの経路になるかを見出しで分かるようにする。**その他の表情** の見出しの説明は、通常の書き出しでは「アバターの表情メニューをそのまま書き出し」、記録する経路では「この一覧を記録して書き出し」にする。以前の「VRMのカスタム表情として書き出し」はどちらの経路でも同じ文言で、通常の書き出しでは一覧の内容と出力が一致しない場合があった。
- 記録する経路では、**その他の表情** を64件（`MaximumExpressions`）までにする。超えているあいだは **この割り当てでVRMを保存** を押せず、次にやることに「その他の表情から○件を書き出さないへ移す」と出す。通常の書き出しは何も記録しないので、この上限はかけない。
- 記録する経路で **その他の表情** に同じ名前の表情が2つ以上あるときも保存を止める（`ExpressionBoard.DuplicateNames`）。次にやることに「同じ名前の表情○組の片方を書き出さないへ移す」と重なった名前を出す。表情名の変更をなくしたので、画面で直せるのは片方を移す操作だけである。セッションの名前の重複検査は残し、画面の検査はその手前で止める。
- 表情名の変更をなくす。カスタム表情はクリップの名前で記録する。ボードではカードが1枚の表情を表し、名前を変える欄を置く場所が無い。名前を変えたい場合はファイル名を変える。
- 枠・カード・列の大きさは固定の値（カードの高さ36、枠の本文44など）で決め、文字の大きさから計算しない。入りきらない名前は末尾を省き、全文はツールチップに出す。名前の長さや言語でボードの配置が変わらないようにする。
- 幅が狭いウィンドウでは、カードのバッジを名前の下へ、下部の保存ボタンを2段目へ回す。

## 検討した代替案と不採用理由

- 表の形（1行に1表情、列に「喜怒哀楽のどれか」「カスタム」「書き出さない」の選択）: 表情が64件近くあると、喜怒哀楽の5つがどの行に入っているかを縦に探すことになる。5枠が空かどうかも一目で分からない。
- 一覧と詳細の2画面（左に表情の一覧、右に選んだ表情の行き先）: 1件ずつ選んでから行き先を決めるので、操作が2段になる。全体の割り当てが画面に出ない。
- 見つかった表情を最初は **書き出さない** に入れる: 何も選ばずに保存すると表情が無くなり、従来の出力と変わる。
- 経路を常に記録する経路にする: 何も変えていない利用者の出力まで変わる。64件の上限で保存できないアバターも出る。

## 影響

- 候補ファイルのチェック、**選んだ○件を追加**、**表示中を選択**、追加した一覧の **確認**・**理由**・表情名の欄が無くなる。保存ボタンは **この割り当てでVRMを保存** になる。
- 表情を評価・焼き込み・記録する処理は変えていない。ボードが渡すのは、記録するクリップの一覧と喜怒哀楽の指定だけである。
- 状態の行と通知の文言を、画面の文言の規則（句点を使わない、状態はます／ませんで終える）に合わせ、使わなくなった訳を4言語から外した。

## 未決

- 同じ名前のクリップを両方とも書き出したい場合は、ファイル名を変えるしかない。画面の中で名前を変える手段は置いていない。
- 色は暗いテーマに合わせて固定している。明るいテーマのEditorでは見え方を確かめていない。
- モックのカードには顔の縮小画像があるが、この変更では入れていない。カードは名前だけで、顔はカードを押してプレビューで見る。
