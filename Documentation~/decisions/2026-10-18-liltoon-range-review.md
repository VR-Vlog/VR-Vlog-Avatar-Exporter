# lilToon の対応範囲を 2.0.0〜2.3.4 のまま据え置く

> 2026-10-22の[lilToonのバージョンで書き出しを止めない](2026-10-22-liltoon-no-version-gate.md)で一部を置き換えた（上限・下限をなくした）。

- 日付: 2026-10-18
- 対象: `Compatibility/README.md`（コードの変更はない）

## 背景

オーナーから、VRChat SDK・lilToon・UniVRM の対応範囲をできるだけ広げるよう指示があった。lilToon は 2026-10-14 の決定（`2026-10-14-liltoon-version-range.md`）で 2.0.0〜2.3.4 を受け付けている。この範囲を上下に広げられるかを見直した。

## 決定

- 対応範囲は 2.0.0〜2.3.4 のまま変えない。
- 上側: 2026-10-18 時点で、lilToon の公式 VPM リストは 41 版で最新が 2.3.4、プレリリースはない。GitHub のリリースとタグも最新は 2.3.4（2026-06-25）。広げる先の版がないので、2.x の正式版はすべて範囲に入っている。
- 下側: 1.x は入れない。理由は「確認したこと」の 2 つ目に書いた。
- `DependencyPolicy.AcceptsNewerLilToon` は `false` のままにする。2.3.4 より新しい版が出たら、構成ハッシュと Unity での実行を確かめてから `lilToon.supported.maximum` を上げる。

## 確認したこと

- 構成ハッシュは 2.0.0・2.1.0〜2.1.10・2.2.0・2.2.1・2.3.0〜2.3.4 の 19 タグで同じで、1.10.3 だけ違う。
- 1.10.3 から 2.0.0 で、プロパティが 35 件消え（`_IgnoreEncryption`・`_Keys`・`_BitKey0`〜`_BitKey31`・`_FurMeshType`）、3 件増えた（`_EnvRimBorder`・`_EnvRimBlur`・`_Ramp`）。書き出しは材質のプロパティ集合を 2.3.4 のカタログと完全一致で要求するので、1.x の材質はそのままでは止まる。
- 1.x を通すには、1.x 用の別カタログか 2.3.4 への正規化、構成ハッシュの表の追加、下限の変更が要る。2.0.0 でファーの Shrink モードの削除、`openlit_core.hlsl` と Light Volumes の変更があり、構成をそろえても描画が同じとは言えない。1.10.3 までのパッケージの対応 Unity は 2018.3 で、Unity 2022.3 での動作も確かめていない。
- 1.x の材質は lilToon を 2.0.0〜2.3.4 に更新すれば lilToon 本体の移行処理で 2.x の構成になり、そのまま書き出せる。止めたときの案内もこの手順を示している。
- 2.0.0 の下端は、VRChat SDK の対応範囲の確認で Unity 2022.3.22f1 の実プロジェクト（UniVRM 0.131.0・VRChat SDK 3.7.0・NDMF 1.8.3・AAO 1.7.13）でも使い、表情の記録と PhysBone の書き出しを回した。lilToon が原因の失敗はなかった。

## 検討した代替案と不採用理由

- 1.8.x〜1.10.x を別の構成クラスとして受け付ける: 1.x 用のカタログと、Unity で 1.x の書き出しを再生して見た目を確かめる作業が要る。lilToon の更新だけで書き出せるようになるので、利用者の手間に対して作業が大きい。
- 2.3.4 より新しい 2.x を構成ハッシュが一致すれば受け付ける: まだ新しい版がなく、構成が同じでもシェーダーの計算が変わることがある。新しい版が出てから判断する。

## 影響

- 動作は変わらない。`Compatibility/README.md` の lilToon の節に、2.3.4 が最新の正式版であることと 1.x を入れない理由を足した。
