# 右クリックのアプリに転送を「かんたん」と「通常」の2つにする

- 日付: 2026-10-20
- 対象: `Editor/LanTransfer/AppTransferWindow.cs`・`Editor/LanTransfer/AppTransferFlow.cs`・`Editor/AppTransferExport.cs`・`Editor/ExperimentalExpressionCaptureWindow.cs`・`Editor/ExperimentalExpressionCaptureSession.cs`・`Editor/ExportSettingsStore.cs`・`Editor/Locales/*.json`

## 背景

Hierarchy の右クリックの **VR Vlog → アプリに転送…** は 1 つだけで、名前と同意を入れると、表情を名前から自動で選んで書き出し、QR まで進めていた（[2026-10-14-app-transfer.md](2026-10-14-app-transfer.md)）。オーナーから次の指示があった。

- 右クリックのメニューを **アプリに転送（かんたん）** と **アプリに転送（通常）** の2つにする。
- かんたんは、名前や VRM のライセンスなどの必須の項目だけ入れたら、すぐに書き出して転送する。
- 通常は、表情をドラッグ＆ドロップで割り当てる画面（**VRMを書き出す** の表情ボード）を出し、不要なオブジェクトを書き出さない工程を踏んでから転送する。

## 必須の項目

コードから、転送の前に人が入れなければならない項目を次の4つと判断した。

1. 名前（アプリのアバター一覧に出る名前。VRM の `name` にもなり、アプリの上限に収まる長さ）
2. 作者名（VRM 1.0 の meta で必須の `authors`。空では保存できない＝[2026-10-14-require-author.md](2026-10-14-require-author.md)）
3. 利用規約への同意（毎回）
4. プライバシーポリシーへの同意（初回だけ。**QRコードでスマホに送る** と共有して保存）

VRM の meta で必須のもう1つ `licenseUrl` は書き出し側が入れる。利用条件（アバターの利用者・商用利用・改変・再配布など）には既定値（作者のみ・個人非営利・クレジット表記が必要・改変と再配布なし）があるので、入力は必須にしない。かんたん・通常とも **VRMの利用条件** の折りたたみに作者名と利用条件の要約を1行で出し、前回の値（無ければ既定値）で書き出す。作者名が空のときは今どおり折りたたみを開いたままにする。

利用規約への同意は、かんたん・通常とも毎回求める。同意の文言（`AppTransferFlow.ConsentText`）と利用規約の URL（`TermsUrl`）は法務の判断（2026-10-14）なので変えない。

## 決定

### メニュー

- **VR Vlog → アプリに転送…** を **アプリに転送（かんたん）** と **アプリに転送（通常）** に分ける。名前はオーナーの指定どおり。出す条件（クラウド転送が有効な版で、アバターの一番上を1つ選んだとき）は今と同じ。

### かんたん

- 今の **アプリに転送** の画面をそのまま使う。
- 名前の初期値は、このアバターで前に転送の書き出しに成功したときの名前にする。記録が無ければ今どおりオブジェクト名。記録はプロジェクトの `UserSettings` の書き出し設定（`ExportSettingsStore`）にアバターごとに置く。アバター・シーン・Prefab・VRM には書き込まない。
- 作者名と利用条件は、今どおりアバターごとに記録した前回の値を使う。前回の入力が揃っていれば、利用規約の同意にチェックを入れるだけで **QRコードを作る** を押せる。
- 書き出しは、自動で設定できなかった項目の確認（書き出し結果の一覧）を出さずに続ける。内容は今どおり Console の書き出し詳細に残る。書き出しを止める失敗は、今どおり理由と **もう一度** を出し、対策画面を開く。
- 表情は名前から自動で選ぶ（[2026-10-18-emotion-preset-inference.md](2026-10-18-emotion-preset-inference.md)）。書き出さないオブジェクトは、そのアバターに記録した設定を使う（[2026-10-18-export-settings.md](2026-10-18-export-settings.md)）。
- 画面の上に「表情は名前から自動・書き出さないオブジェクト N件」と **表情とオブジェクトを選ぶ** を出す。押すと同じアバターで通常に切り替える。何が自動で、何が前回の設定かを、書き出す前に見えるようにするため。

### 通常

- **VRMを書き出す** の表情ボードを「転送」の状態で開き、そのアバターで **書き出しを準備** まで自動で進める。
- 画面の上に工程の1行「1 表情と書き出さないオブジェクト › 2 名前と利用条件」を出す。
- 表情ボードの下（ポーズの上）に **書き出さないオブジェクト** の欄を足す。表情ボードの上に置くと、表情の割り当てという主な作業が下へ押し出されるため。中身は一括書き出し画面（`LilToonExporterWindow`）の除外の一覧と同じで、行ごとの **解除** と **除外するオブジェクトを追加** を持つ。変更は **プレビューに反映** で確定し、そのときにプレビューを作り直す（ボードの割り当ては保つ）。確定まではプレビューを作り直さない。作り直しに数秒かかるため、1件ごとに走らせない。
  - この欄は転送の状態に限らず、メニューの **VRMを書き出す** でも出す。これまで表情ボードからの書き出しは、記録した除外オブジェクトを使っていなかった（ギミックの自動除外だけ）ので、同じアバターでも画面によって中身が違っていた。表情ボードのプレビューと書き出しは、記録した除外オブジェクトとギミックの設定を使う。
- 転送の状態では、保存欄の作者名と **ライセンス設定** を隠し、「作者名と利用条件は次の画面で入力します」を出す。同じ項目を2つの画面で聞かないため。瞬きとポーズはそのまま。
- 下の強調ボタンは **次へ：名前と利用条件** にする。押すと **アプリに転送** の画面（通常）を開く。その画面は、かんたんと同じ名前・利用条件・同意の欄の上に「VRMの表情 n/5・書き出さないオブジェクト N件」と **戻って編集** を出す。
- **QRコードを作る** で、表情ボードの今の割り当てと除外で書き出す。VRM の名前は転送の名前、作者名と利用条件は転送の画面で入れたもの。通常では、自動で設定できなかった項目の確認を今どおり出す。
- 表情ボードを閉じた・別のアバターに替えた・準備が済んでいないときは、「表情の割り当て画面が開いていません」と出して **QRコードを作る** を押せなくし、**割り当て画面を開く** を出す。割り当ては表情ボードの記録（`ExpressionPresetStore`）と書き出し設定から戻る。

## 検討した代替案と不採用理由

- 通常でも転送の画面を先に開き、そこから表情ボードを開く: 入口は揃うが、表情ボードを開かずに QR を作れてしまい、「工程を踏む」順序が画面から読めない。
- 通常の表情ボードを閉じても、割り当てを控えておいて転送を続けられるようにする: 表情ボードの書き出し（記録した表情を使う経路）は準備済みのプレビューを使うので、閉じたあとに同じ内容を作れない。理由と開き直すボタンを出す方にした。
- 新しい転送専用の画面を作る: 既存の2画面（転送・表情ボード）で足りる。画面を増やさない。

## Codex への相談

設計案を Codex に見せ、案の比較と指摘をもらった。

- 採用: 通常は「表情・除外 → 名前・利用条件 → QR」の順にする案、工程の1行と **次へ：名前と利用条件**、転送の画面の要約と **戻って編集**、かんたんに自動・除外の件数と切り替えのボタンを出すこと、除外の欄と一括の **プレビューに反映**、転送の名前をアバターごとに記録すること。
- 一部採用: 表情ボードを閉じたときに割り当てを控えて続ける案は、上の理由で採らず、理由と開き直すボタンにした。
- 不採用: 表情ボードの **書き出さない** の改名（この変更の範囲外）、自動で設定できなかった項目を「知らせる／確認する／止める」に分けること（かんたんは確認を出さない指示のため。止める失敗は今どおり止める）、同意の文言の変更（法務の判断）、メニュー名の変更（オーナーの指定）。

## 影響

- 右クリックの項目が1つから2つになる。かんたんの書き出し内容は今の **アプリに転送** と同じで、確認の一覧を出さなくなる点だけが違う。
- 表情ボードからの書き出し（メニューの **VRMを書き出す** を含む）は、そのアバターに記録した除外オブジェクトを書き出さなくなる。記録が無いアバターの出力は変わらない。
