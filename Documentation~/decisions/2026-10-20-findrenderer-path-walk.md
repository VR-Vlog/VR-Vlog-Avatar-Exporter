# 表情の解析でパスから Renderer を探すとき、名前に沿って子だけをたどる

- 日付: 2026-10-20
- 対象: `Editor/VrChatExpressionSampler.cs`（`FindRenderer`）・`Tests/Editor/RendererPathTests.cs`

## 背景

表情の解析は、アニメーションのパス（`Body` や `Armature/Hips/...`）から BlendShape を持つ Renderer を探す `FindRenderer` を何度も呼ぶ。これまでの実装は、呼ぶたびにアバターの複製の全 Transform について `AnimationUtility.CalculateTransformPath` でパスを作り、探しているパスと比べていた。Transform の数に比例する処理を、表情の数・BlendShape の数だけ繰り返していたことになる。

統合ブランチで計測すると、表情メニューが 119 項目あるアバターでは `FindRenderer` が 1 回の書き出しで約 15 万回呼ばれ、合わせて約 70 秒かかっていた（表情の解析全体は約 244 秒）。表情の少ないアバターでも、Transform の多いものは数秒かかっていた。

## 決定

- パスを `/` で区切った名前に沿って、ルートから子だけをたどって探す。たどる子は名前の前方一致で絞り、同じ名前の兄弟があればそのすべてをたどる。
- 結果はこれまでの全件の走査と同じにする。
  - 同じパスの Transform が 2 つ以上あれば「重複する階層パス」のエラー。
  - 見つからない、Skinned Mesh Renderer が無い、メッシュが無いときは「Rendererのパスを一意に解決できません」のエラー。
  - 空のパスはルート自身。
  - 非表示のオブジェクトもたどる。
  - 名前に `/` を含むオブジェクトを通るパスは、これまでどおりエラーにする。名前に `/` を含むと、同じパスの文字列が別の階層にも当てはまりうるため、名前の区切りを変えずにすべての分け方をたどって重複を数え、そのうえで通ったオブジェクトの名前を確かめる。

(複製のルート, パス) ごとに結果を覚えておく方法も考えた。しかし解析の途中では NDMF の処理や書き出さないオブジェクトの除外で複製の階層が変わることがあり、覚えた結果を捨てる時機を誤ると古い Renderer を返す。子だけをたどる方法なら覚えておくものが無く、1 回の探索も Transform の総数ではなくパスの深さと兄弟の数で済むので、こちらにした。

## 変えなかったもの

- エラーの文と、どの場合にエラーになるか。
- `FindRenderer` の呼び出し元と呼ぶ回数。

## 確認したこと

- `RendererPathTests` で、重複する名前・`/` を含む名前・非表示・Renderer やメッシュの無いもの・空の名前・ルートの Renderer・null のパスについて、これまでの全件の走査と同じ結果（同じ Renderer か、同じエラー）になることを確かめた。
- Unity 2022.3.22f1 の EditMode テストを全件実行した。失敗した 47 件は変更前のコミットでも同じ 47 件が失敗する（実際の VRChat SDK などが要るテスト）。
- 書き出しの時間と、書き出した VRM の表情が変更前と同じことは、PR の本文に載せた。
