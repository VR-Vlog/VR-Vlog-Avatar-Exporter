# 時間で決めた表情から外す Blend Tree を「動くもの」に絞り、遷移の後も確かめる

- 日付: 2026-10-20
- 対象: `Editor/VrChatExpressionSampler.cs`・`Editor/VrChatFxExpressions.cs`・`Editor/ExpressionSettlement.cs`・`Tests/Editor/ExpressionSettlementTests.cs`

## 背景

メニューの表情と FX の条件から見つけた表情は、選んでから 2 秒で顔が止まらないとき、Animator の遷移を時間どおりにたどった最終状態の顔で保存する（[2026-10-20-settlement-review-followups.md](2026-10-20-settlement-review-followups.md)）。Blend Tree のステートはこの経路にアニメーションとして読む手段が無いので、時間で決めたときに Blend Tree のステートがあれば表情ごと外していた（`SettledFxTreeOmitted`）。

#237 のレビューで次の 4 件が残っていた。

1. 止まっている Blend Tree の層があるだけでも外す。子のアニメーションがどれも一定で入力も一定なら、最終状態の 1 フレームは正しい顔なのに外れる。
2. 時間で決める前のステートしか見ていない。待ってから遷移した先で動く Blend Tree に入る表情は、最終状態の 1 フレームで保存されていた。
3. Synced Layer のテストは依存の解析で先に外れて、この判定まで届かない。
4. ステートの引き当てが `ExpressionSettlement` の索引と重複している。

## 決定

- 外すのは「まだ動く」Blend Tree だけにする。動くとは、子孫のアニメーション（Override 後のもの）のどれかが顔の BlendShape を時間で変えるか、コントローラーのどれかのアニメーションが Blend Tree の入力パラメーター（1D・2D の入力と Direct の各子の重み）を時間で変えること。どちらも無ければ子と入力が一定なので、最終状態の 1 フレームはその Blend Tree の正しい顔になる。入力を書くアニメーションは、実際に再生されるかを問わずコントローラーの全体から探す（再生されるかの判定は遷移の解析そのものになるため、外す側に倒す）。
- 時間で決める前に加えて、決めた後のステート（遷移中なら遷移先も）も同じ判定にかける。
- FX の条件から見つけた表情も同じ報告を使い、「候補のステートが Blend Tree か」ではなく「動く Blend Tree の層があるか」で外す。メニューの表情と同じ基準になる。
- ステートの引き当ては `ExpressionSettlement.StateResolver`（`Settle` と同じ索引）に寄せる。これまでの引き当てが見ていた同期元の層の名前を索引の根に足した。
- Synced Layer の件は今も依存の解析で先に外れる。テストのコメントのとおり、その制限を外したときもこの判定が同期元へたどることを確かめる位置づけのまま残す。
- Gesture の手の Blend Tree（アニメーションとして書き出す経路）は変えない。

## 確かめたこと

- 止まっている Blend Tree から待って別のステートへ移る表情が、移った先の顔で保存される（変更前は外れていた）。
- 同じ形で、入力を動かすアニメーションがコントローラーにあれば外れる。
- 待ってから動く Blend Tree に入る表情が外れる（変更前は 1 フレームで保存されていた）。
- これまでの「動く Blend Tree を選ぶメニュー」「FX の動く Blend Tree の候補」のテストは同じ結果。

FX の条件から見つけた止まっている Blend Tree の候補で、別の層の動きで時間の決定が起きる形はテストを足していない。候補のステートへ到達したまま別の層だけが動き続ける FX を作るのが重く、判定はメニューの表情と同じ報告を使うため。
