# 「次にすること:」の見出しと、画面が自分を説明する案内文を消す

- 日付: 2026-10-20
- 対象: `Editor/ExportFailureWindow.cs`・`Editor/ExportResultWindow.cs`・`Editor/ExportResultList.cs`・`Editor/ExportDetailsText.cs`・`Editor/LilToonStructureCheck.cs`・`Editor/ExportRecoveryComparisonWindow.cs`・`Editor/LilToonExporterWindow.cs`・`Editor/Locales/ExporterLocale_*.json`・`Tools/LilToonStructureCheckTests.cs`・`CHANGELOG.md`

## 背景

書き出しの失敗・結果の画面には「次にすること: 」「次の操作: 」の見出しや、「〜してください」で次の操作を案内する文があった。使う人から見ると、画面の中身を言い直しているだけで機械的に見える、という指摘を受けた。表情の割り当て画面の「次にやること:」の行は別の PR で扱い、この変更はそれ以外の画面を扱う。

UI の文言は、画面が自分を説明する文を書かない、同じ内容を二重に書かない、「ください」を使わない、という方針に合わせる。ただし、状態・条件・注意などの意味を担う語と、エラーの対処文（remedy）の中身は消さない。

## 決定

- 見出しを変えたもの（対処文の中身は変えない）:
  - 書き出しの失敗の画面の各項目（`ExportFailureWindow.DrawIssue`）: 「次にすること: 」を「対処: 」にした。同じカードの「対象: 」「理由: 」「変わる点: 」と並ぶ項目名なので、項目名は残して中立の語にした。
  - 書き出し結果の一覧で行を開いたときの欄（`ExportResultWindow.DrawDetail`）: 「次にすること」を「対処」にした。
  - コピー・保存する詳細のテキスト（`ExportResultList`・`ExportDetailsText`）: 「次にすること: 」を「対処: 」にした。画面と同じ語にそろえるため。
  - lilToon の構成の確認の結果（`LilToonStructureCheck`）: 「次の操作: 」を「対処: 」にした。`Tools/LilToonStructureCheckTests.cs` の期待値も合わせた。Python 側に同じ文言は無かった。
- 短くしたもの:
  - 書き出しの失敗の画面の上の 1 行: 「次に試すことを選んで、もう一度書き出してください。元のアバターは変更しません。」と「表示された設定を確認してください。元のアバターは変更しません。」を、どちらも「元のアバターは変更しません」にした。前半は下に並ぶ項目とボタンを言い直しているだけなので消し、元のアバターに手を入れないという事実は残した。
- 消したもの:
  - 書き出しの失敗の画面の「試す対処にチェックを入れてください。変わる点を確認してから進めます。」: 代わりに、対処できる項目があってまだ何もチェックしていないときも「選んだ対処で書き出す」ボタンを押せない状態で出す。これまでは何も選んでいないとボタン自体が出ず、案内文を消すと何を押せばよいかの手がかりが無くなるため。ボタンの高さ（36）と位置は、押せるときと同じ。
  - 書き出したVRMの確認画面の「見た目と変更点を確認し、下の「このVRMを保存する」で保存してください。」: 保存のボタンが同じ画面の下にあり、文がボタンの場所を言い直しているだけなので消した。
  - 書き出し画面の瞬きの欄の「瞬きはこの欄で設定します。設定後、「開閉をプレビュー」で確認できます。」: 欄の中の「設定」と「開閉をプレビュー」がそのまま見えるので消した。
- ローカライズ: 使われなくなった 9 つの source（「次にすること: 」「次にすること」「\n次の操作: 」、前から使われていなかった「次の操作: 」、上の案内文 5 つ）を英語・韓国語・中国語（簡体・繁体）から消し、「対処: 」「対処」「\n対処: 」「元のアバターは変更しません」の訳を足した。訳は既存の「対象: 」「理由: 」の語調に合わせた（英語は「Fix: 」）。

## 変えなかったもの

- エラー・警告の対処文（「〜を確認してください」など。瞬き・書き出しの失敗・依存パッケージほか）: エラーの中身で、消すと直し方が分からなくなる。
- QR・転送の注意と、利用規約・プライバシーの同意まわりの文言: 安全・同意にかかわる文言はこの変更では触らない。
- 書き出しの失敗の画面の「必要な表情を残し、取り込まないメニューを選んでください。メニューを分割するだけでは合計項目数は減りません。」: メニュー数が多すぎるときの対処で、後半は誤解を防ぐ事実。
- 書き出し画面の「保存先を選ぶと、VRMの書き出しと保存まで自動で進みます。」: ボタンを押すと確認なしで保存まで進む、という結果を言っている。
- 揺れ物の書き出しの警告の中の「次に」: 文の中の語で、見出しではない。
- 表情の割り当て画面（`ExperimentalExpressionCaptureWindow`）: 別の PR で扱う。

## 確認したこと

- `Tools/run-validation.py` の検査が、Windows で動かない 2 つ（`test-vpm-mirrors.py`・`test-exporter-publication.py`。どちらも `os.O_NOFOLLOW` が Windows に無いため。この変更は Python に触れていない）を除いて通った。`Tools/validate.py` のローカライズの検査も通った。
- Unity 2022.3.22f1 の EditMode テストで、書き出しの詳細・失敗からの再試行・比較・lilToon の構成の確認まわりの 8 クラス（117 件）がすべて通った。
- 合成データで瞬きの欄・失敗の画面（対処を選んだとき／選んでいないとき／対処の無い項目だけのとき）・結果の一覧の詳細・確認画面を開き、変更前と変更後を UI 倍率 300% で撮って比べた。何も選んでいないときに押せないボタンが出ること、ボタンの高さと位置が押せるときと同じことを確かめた。
