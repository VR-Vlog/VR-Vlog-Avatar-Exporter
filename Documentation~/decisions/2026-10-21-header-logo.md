# Exporter のウィンドウの上部にロゴと画面名の見出しを出す

- 日付: 2026-10-21
- 対象: `Editor/Compatibility/ExporterWindowHeader.cs`（新規）・`Editor/Compatibility/ExporterWindowIcon.cs`・`2026-10-21-window-title-icon.md` でタブにロゴを付けた各ウィンドウ・`Editor/LanTransfer/AppTransferWindow.cs`・`Editor/Locales/*.json`・`Tests/Editor/ExperimentalExpressionCaptureTests.cs`・`Tests/Compatibility/DependencyStartupTests.cs`・`Tests/Startup/ExporterStartupProbe.cs`

## 背景

`2026-10-21-window-title-icon.md` で、Exporter のウィンドウのタブに VR Vlog のロゴを付けた。その後、ロゴはタブではなく **アプリに転送（かんたん）** の本文の一番上と同じところ（ロゴと画面名の見出し）に出してほしい、**アプリに転送** のタブのロゴ（かんたん・通常とも）も外してほしい、という要望があった。

## 決定

- タブのロゴをすべて外し、タブは文字だけに戻した。**アプリに転送** のタブも文字だけにした。タブの文字は変えていない。
- 前回タブにロゴを付けた 12 画面の本文の一番上に、**アプリに転送（かんたん）** と同じ形の見出しを出す。左にロゴ、右に画面名、下に 1px の罫線を引く。
- 寸法と色は **アプリに転送** の USS（`.header`・`.header-icon`・`.heading`・`.hairline`）に合わせた。行の高さは 60px、左右の余白は 16px、ロゴは 36px、ロゴと文字の間は 10px、文字は 14px の太字。罫線の色は、ダークテーマでは白の 14%、ライトテーマでは黒の 18%。画面名が長いときは枠の中で切り、見出しの高さは変わらない。
- 描画は `ExporterWindowHeader` の 1 か所にまとめた。GUILayout で組む画面は `Layout(画面名)` を最初に呼ぶ。座標で組む **アプリでの見え方** と **書き出し結果** は、`Draw` で上端に描いて残りを `ExporterWindowHeader.Height`（61px）下げる。あとで見出しの形を変えるときはここだけを直せばよい。
- 見出しの文字は、原則としてタブの文字と同じ画面名にした。以下の 3 つは例外。
  - ロゴが VR Vlog のものなので、タブ名の頭の「VR Vlog 」は見出しでは省いた（**VRM書き出し**・**書き出し結果**・**動作環境**）。「書き出し結果」は翻訳がなかったので、4 言語に足した。
  - 表情ボードの画面（**VRM書き出し**・**アプリに転送（通常）**）は、本文の一番上にあった太字の見出し（「VRMを書き出す」「アプリに転送（通常）」）を新しい見出しに置き換えた。
  - **瞬きを確認** と **ポーズを確認・調整** は、プレビューの準備ができる前から見出しを出す。
- ロゴのテクスチャは前回と同じ `ExporterWindowIcon.Texture` の 1 枚を使い回す。タブに付け直す処理（`Title`・`Restore`）は要らなくなったので消した。

## 文言の監査

この変更で見出しを足した画面の文言（434 種）を確かめ、次の 2 つを直した。

- **アプリでの見え方**: 「lilToon 2.3.4 と版が違います」を「lilToon 2.3.4 とバージョンが違います」にした。一般のアプリでは「版」とは言わないため。
- **スマホに送る**（LAN）: 案内の「VRVlog」を、ほかの画面と同じ「VR Vlog」にした。

次のものは直していない。

- 「材質」（マテリアルのこと）と「枝」（メニューのサブメニューのこと）。どちらも書き出しの失敗理由・工程名・テストを含めて 40 か所以上で使っている。この画面だけ言い換えると呼び方がばらばらになるので、全体をそろえるなら別の変更でまとめて行う。
- 「待受」「割当」のような短縮形。表示幅が限られた行にあり、意味は通じる。
- ライセンス・利用条件・同意に関わる文言は対象外にした。

## 入れなかったもの

- 手順を上に出して 3 ページに分ける構成。別の変更で行う予定で、そのときは `ExporterWindowHeader` を差し替えればよいようにしてある。
- **アプリに転送** の UI Toolkit の見出しを `ExporterWindowHeader` で描き直すこと。この画面は UXML と USS で見出しを持っており、ほかの画面がそれに合わせる側になる。

## 確認したこと

- 検証PC の Unity 2022.3.22f1 で 14 画面を開いた。12 画面に加えて、**アプリに転送（かんたん）** と **アプリに転送（通常）** を含む。変更前（develop）と変更後で、タブと本文の上部を撮って比べた。変更後は、どのタブにもロゴがなく、本文の上部にロゴと画面名の見出しが出た。Unity を再起動して、保存済みのレイアウトから戻ったウィンドウでも同じだった。
- 同じ検証PC で EditMode テストを全件回した。389 件のうち、382 件が成功、1 件がスキップ、6 件が失敗した。失敗した 6 件は develop でも同じように失敗する。4 件は任意の SDK が検証PC のプロジェクトに入っていないため、2 件はクリック操作を使うテストのため。
- タブにロゴがないことは、`ExperimentalExpressionCaptureTests`（5 言語）・`DependencyStartupTests`・起動時の確認で確かめた。見出しのロゴを閉じても破棄せず、スクリプトの再読み込み後も同じテクスチャを使うことは、`HeaderLogoIsSharedAndSurvivesScriptReload` で確かめた。
- 変更前から、Unity を再起動して戻った **アプリに転送（かんたん）** では、最初の数秒だけ見出しの画面名が空になる。この変更とは関係なく、develop でも同じだった。
