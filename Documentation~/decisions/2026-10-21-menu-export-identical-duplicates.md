# 同じ名前で中身も同じ表情は、VRMに1つだけ書く

- 日付: 2026-10-21
- 対象: `Editor/VrmMenuExpressions.cs`・`Tests/Editor/ExpressionAnimationV2WriterTests.cs`・`CHANGELOG.md`

## 背景

表情ボードの表示とVRMの中身を突き合わせる一括検証を手元のアバターで回したところ、手のジェスチャーで表情を変えるアバターの多くで、VRMのカスタム表情に `X` と `X (2)` の組が6〜18組あった。組の多くはモーフの指定もアニメーションもまったく同じで、アプリでは同じ顔が2回並ぶ。

ジェスチャーの表情は、左手と右手のレイヤーのそれぞれから読む（`VrChatGestureExpressions`）。ここで1つにまとめるのは、同じクリップで結果も同じ（`SameOutcome`。パラメーターなど書き出しに出ない値も比べる）登録だけで、両手で別のクリップを使っている場合や、手ごとに比べる値が違う場合は別の登録になる。登録は別でも、VRMに書く内容は同じになる。書き出し（`VrmMenuExpressions.Add`）は同じ名前の2つ目以降に ` (2)` を付けて全部書いていた。

## 決定

- `VrmMenuExpressions.Add` で、同じ名前・同じ由来（menu・gesture など）・同じ推定用の名前（`InferenceName`。表情メニューではメニューの階層つきの名前）で、書くモーフの指定（node・index・weight）とアニメーション（長さ・ループ・カーブのキー・点の値と出力先）が前に書いたものと完全に同じ表情は書かない。最初の1つだけを残す。
- 書かなかった表情は `RegisteredName` を null のままにする。喜怒哀楽の候補（`EmotionCandidates`・`EmotionShapes`）は残した1つから選ぶ。
- 名前が同じでも中身が違う表情（左右で一部のモーフが違うものなど）、由来が違う表情、別のメニューにある同じ名前の項目（`Smile / 1` と `Other / 1`。喜怒哀楽の推定が項目ごとに違う）は、これまでどおり ` (2)` を付けて書く。

`VrmMenuExpressions.CountRegistered` は重複を数えなくなる。#274（表情メニューから入った表情が **その他の表情** より少ないときに記録する経路でやり直す）が比べる数も、同じ顔を2回数えなくなる。

## 採らなかったもの

- `VrChatGestureExpressions` の `SameOutcome` を緩めること。そこでは書き出しに出ない値（パラメーターなど）も比べて「違う結果になる登録」を残す方針で、どの値がVRMに出ないかを書き出しの手前で決めるのは難しい。書き出す内容で比べれば、どこから来た重複でも同じ判定になる。
- 重複を書き出し結果の一覧に出すこと。出力から消えるのは同じ顔の2つ目だけで、利用者が対処することは無い。

## 確認したこと

- EditMode: `ExpressionAnimationV2WriterTests.IdenticalRegistrationsOfOneFaceAreWrittenOnce`（同じ顔の2回目を書かない・中身が違う同名と由来が違う同名は ` (2)` `(3)` で残る・アニメーションも同じ判定）と、既存の `EveryRegisteredExpressionIsListedWithItsSource`。
- 関連する EditMode テスト（表情メニュー・ジェスチャー・アニメーションの書き出し・統合したメッシュ・最適化の参照）424件が通ることを確かめた。
- マージ後に一括検証で同じアバターを書き出し直し、` (2)` の組が中身の違うものだけになるかを確かめる。
