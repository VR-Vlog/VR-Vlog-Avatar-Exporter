# アプリに転送の画面の文字を専用のフォントで描き、一部のかなだけ太く見えるのを直す

- 日付: 2026-10-21
- 対象: `Editor/LanTransfer/AppTransferWindow.cs`・`CHANGELOG.md`

## 背景

**アプリに転送** の QR の画面で、赤い注意書き「QRを他の人に見せたり配信に映したりしないでください」の「たり」だけが太く、色も薄く見えていた。

Unity 2022.3 のエディタの UI Toolkit は、英字を Inter で描き、日本語は代替フォント（Yu Gothic UI と Yu Gothic UI Bold）から取る。このとき「どの文字をどの代替フォントから取ったか」を文字ごとに覚えるが、太字かどうかを区別していない。エディタのどこかの UI Toolkit の画面で一度太字で描いた文字は、そのあと普通の太さの文字でも Yu Gothic UI Bold から取られる。転送の画面には太字の **残り 0:59** や見出しがあるため、注意書きの「た」「り」が太字の字形になっていた。

同じ画面を作る UXML と USS をエディタのウィンドウに開き、先に太字の「たり 残り」を描いてから各文字の取り出し元のフォントを記録すると、次のように混ざっていた（Unity 2022.3.22f1・Windows）。

- 注意書き: 「を他の人に見せ」「配信に映し」「しないでください」は Yu Gothic UI、「たり」2か所は Yu Gothic UI Bold
- 読み取り待ち・QRができたら音を鳴らす・QRを作り直す・書き出したVRMをアップロードしています も、「り」「た」「作り」が Yu Gothic UI Bold
- 逆に太字の見出し「QRコードを作っています」では「ードを」「ています」が普通の太さの Yu Gothic UI

太字を先に描かなければ、注意書きはすべて Yu Gothic UI から取られる。パッケージの他の画面は IMGUI で、2022.3 では UI Toolkit の文字描画（TextCore）を使わないため、この混ざり方は UI Toolkit で作っている転送の画面だけに出る。

## 決定

Windows では、転送の画面の文字を、エディタが日本語に使っているのと同じ OS のフォント（Yu Gothic UI の Semilight）から作った画面専用の動的なフォントアセットで描く。`FontAsset.CreateFontAsset("Yu Gothic UI", "Semilight", 90)` で作り、画面のルートの `unityFontDefinition` に入れる。子の要素（ラベル・ボタン・トグル）はこれを引き継ぐ。

- 専用のアセットは他の画面と字形の取り出しを共有しないので、他の画面の太字の影響を受けない。上と同じ手順で、すべての文字がこのアセットから取られることを確かめた。
- Semilight にしたのは、これまでの日本語の見た目（エディタの代替フォント Yu Gothic UI SDF は Semilight）と同じ太さにするため。
- 太字の **残り 0:59** や見出しは、同じアセットから Unity が太字に描く。
- 韓国語と、Yu Gothic UI に無い簡体字（「维」「码」「显」など）は、これまでエディタが代替に使っていたのと同じ Malgun Gothic と Microsoft JhengHei（Regular）から作った専用のアセットを、上のアセットの代替に入れて取る。エディタの代替フォントのままだと、画面の中で太字で描いた韓国語・中国語の文字が、同じ画面の普通の太さの文字に Malgun Gothic Bold・Microsoft JhengHei Bold の字形で出ることを、同じ手順で確かめた。
- ドメインのリロード後は、名前で探して前のアセットを使い回す（開くたびに増やさない）。
- Windows 以外と、フォントを作れなかったときは、これまでどおりエディタのフォントで描く。

## 入れなかったもの

- エディタ全体のテキスト設定の変更。Unity の設定を書き換えることになり、他のパッケージや Unity 自身の画面に影響するため。
- USS での `-unity-font-definition` 指定。OS のフォントからアセットを作るのはコードでしかできず、パッケージにフォントファイルを入れると配布物が大きくなるため。
- Windows 以外の対応。macOS では日本語の代替フォントが異なり、同じ現象が出るかを確かめていない。
- 画面の文言の変更。転送の画面の文言 59 個を見直したが、今回はフォントの直しだけにとどめた。

## 確認したこと

- 上の手順（Unity 2022.3.22f1 のエディタのウィンドウ、幅 420）で、直す前は「たり」などが Yu Gothic UI Bold から取られ、直した後はすべての文字が専用のアセットから取られることを記録で確かめた。
- 韓国語・簡体字・繁体字の注意書きで、文字が欠けず、直す前と同じフォント（Malgun Gothic・Microsoft JhengHei）の字形で描かれることを確かめた。他の画面と転送の画面の中で先に太字で描いても、普通の太さの文字は太字の字形にならない。
- 最小幅 420 での注意書きの高さを 5 つの言語で比べ、行数が増えないことを確かめた（日本語 64→64、英語 59→64、韓国語 96→96、簡体字 65→64、繁体字 64→64。英語は 2 行のまま）。
- パッケージの転送の画面そのものを開き、文字が専用のアセットから取られること、ドメインのリロードのあとも同じアセット（代替の 2 つを含む）が使い回されて増えないことを確かめた。エディタの代替フォント Yu Gothic UI SDF の書体が Semilight であることも、このとき記録で確かめた。
- 最小幅 420 で、英語の QR の画面の文字の高さが日本語のときと同じになることを確かめた（英字の行が Inter より少し高くなり、日本語の画面と同じ高さになる。日本語の画面の高さは `TransferChrome` に入っている）。
- 画面の QR の部分をエディタのテキスト設定で描いた 3 倍の画像で、注意書きの太さがそろい、**残り 0:59** が太字のままであることを目で確かめた。
