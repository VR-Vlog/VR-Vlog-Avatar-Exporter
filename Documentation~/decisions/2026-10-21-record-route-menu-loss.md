# 記録して書き出す経路で VRM に入らない表情メニューの項目を、その他の表情の上に出す

- 日付: 2026-10-21
- 対象: `Editor/ExperimentalExpressionCaptureSession.Clips.cs`・`Editor/ExperimentalExpressionCaptureSession.Presets.cs`・`Editor/ExperimentalExpressionCaptureWindow.cs`・`Editor/Locales/ExporterLocale_*.json`・`Tests/Editor/RecordRouteMenuLossTests.cs`・`CHANGELOG.md`

## 背景

表情ボードで表情を外したり、ファイルを追加したり、名前を変えたりすると（`ExpressionBoard.UsesRecordRoute` が true）、書き出しはアバターの表情メニューをそのまま使わず、**その他の表情** の一覧を記録して書き出す。この一覧に並ぶのは、1 つのクリップとして読めた表情だけになる。

表情メニューの Toggle と Button には、顔を動かすのに 1 つのクリップに対応しないものがある。

1. 顔が複数のレイヤーに分かれている（目のレイヤーと口のレイヤーを同じパラメーターで切り替える等）
2. 遷移先が Blend Tree
3. 遷移先がサブステートマシン

これらはボードに並ばないので、記録して書き出す経路では何も出さずに VRM から消えていた。表情メニューをそのまま書き出す経路では入る。

## 決定

- 表情メニューの読み取りを `MenuLinks` 1 つにまとめ、項目からクリップへのパス（`MenuClipPaths` の結果）と、ボードに無い項目のパス（`MenuEntriesOutsideBoard`）を同じ走査で返す。オンとオフの判定（自分のパラメーター値で遷移し、既定値では遷移しない）は共通にした。`MenuClipPaths` の結果は変えていない。
- ボードに無い項目は、1 つのクリップに対応せず、選ばれた遷移先のうち顔を動かすもの（SkinnedMeshRenderer の `blendShape.` カーブを持つもの）が「2 つ以上ある」か「Blend Tree またはサブステートマシンである」もの。服の Toggle（顔を動かさない遷移先だけのもの）は数えない。
- 遷移先を数えるのは、項目のパラメーターの等号の条件（Equals・If・IfNot）で選ばれるものだけにする。Any State から `Face NotEqual 0`（Greater・Less も同じ）で入る共通のリセット用の顔は、どの値でも選ばれるので数えない。数えると、そのレイヤーがあるだけで全部の Toggle が「顔が 2 つ」になって並ぶため。`MenuClipPaths` の結果は変えないよう、この除外はボードに無い項目を数えるときだけにした。
- 1 つのクリップと Blend Tree の顔の両方へ切り替わる項目は、そのクリップに対応する項目として扱い、数えない。クリップはボードに並ぶので、Blend Tree の分だけを理由に行を出すことはしない（仕様としてこう決めた）。
- セッションは表情メニューを 1 回だけ読み、結果を自動割り当てと共用する。読み取りで例外が出たときは一覧を null（読み取れない）にし、0 件とは分ける。VRChat の表情メニューが無いアバターは 0 件。
- 表情メニューが読み取りの上限（項目 256 件・サブメニューの数）を超えたときも一覧を null にし、「表情メニューを読み取れないためVRMに入らない項目を確認できません」を出す。記録して書き出す経路は、このときもボードに無い項目を実際に落とすため。**感情** の見出しの右の「項目名から感情を選んでいません・…」（develop の #303）は、そのまま出る。読み取りは `ReadMenuLinks` 1 か所で、上限の例外を受けたときに上限の件数も返す。
- **その他の表情** の本文の一番上に、高さ固定（22px）の 1 行を出す。出すのは記録して書き出す経路で、ボードに無い項目が 1 つ以上あるか、読み取れなかったときだけ。文言は「表情メニューの{0}項目はVRMに入らないことがあります」と「表情メニューを読み取れないためVRMに入らない項目を確認できません」。左に小さい警告アイコンを置き、文字は控えめな色で、入りきらないときは末尾を省く。ツールチップに全文と項目のパスを出す（20 件まで、それより多いときは「ほか{0}項目」）。
- 右側の見出しの補足（「この一覧を記録して書き出し」）は変えない。保存時の確認ダイアログは出さない。

UI 文言のレビュー（Codex）で採ったもの:

- 項目名の後ろに件数を付ける案（A）ではなく、タイルの上の 1 行（B）にした。タイルの位置は、この行が出るか消えるときだけ動く。
- 件数は静的に読んだ見込みなので「入らないことがあります」とし、「約」や「最大」は付けない。
- 読み取れなかった状態を 0 件と分けた。
- 保存時のダイアログは出さない。

## 採らなかったもの

- (a) クリックで開く固定の詳細一覧。このウィンドウは詳細をツールチップで出していて、詳細を出す欄を持たない。
- (b) 右側の補足を「〜ます」の形にすること。見出しと補足は辞書形でそろえているため。
- (c) 元に戻す操作。ウィンドウに取り消しの履歴が無く、外した表情を戻すか **割り当てをリセット** を押せば表情メニューをそのまま書き出す経路に戻るため。
- (d) Modular Avatar の Menu Installer などで書き出し時に足されるメニュー。アバターに置かれた表情メニューだけを読む `MenuClipPaths` と同じ範囲にそろえたので、それらの項目は数えない（行に出ない）。

## 確認したこと

- develop を取り込んだあとの EditMode のテスト（`RecordRouteMenuLossTests`・`ExperimentalExpressionCaptureTests`・`ExpressionBoardTests`・`ExpressionPresetTests`・`VrChatMenuExpressionTests`・`BoardMenuOverLimitTests` の 342 件）で 337 件が通った。失敗した 5 件のうち 4 件は `RegisteredAndManualBodyPosesSurviveWithOrWithoutRecordedFaces` の "APL" のケースで、この変更の前から失敗している既知のもの。残り 1 件の `SavedExcludedObjectsThatLeaveNoPreviewWaitInTheList` は設定ファイルの置き換えに失敗したもので、単独で流し直すと通った。
- 共通のリセット用の顔（`Face NotEqual 0`）を数えないこと、クリップと Blend Tree の両方へ切り替わる項目を数えないこと、読み取りで例外が出たときと上限を超えたときに読み取れない状態になり、上限のときは **感情** の横の文言の元（上限の件数）も残ることを、追加したテストで確かめた。
- 最初に追加したテスト（9 件）で、1 つのクリップに対応する項目が数えられないこと、レイヤーに分かれた顔・Blend Tree・入れ子のサブステートマシンが数えられること、服の Toggle とパペットが数えられないこと、`MenuClipPaths` の結果が変わらないこと、表情メニューの無いアバターが 0 件になること、表示する条件とツールチップの件数の上限、4 言語の訳があることを確かめた。
- 合成したアバター（実在のアバターは使っていない）で、修正前（develop の 81c1353）と修正後の **その他の表情** をウィンドウ幅 600 と 1000 で撮り、行がタイルの上に 1 行で出ること、読み取れない状態の文言、右側の補足が変わらないことを目で確かめた。項目がある状態と読み取れない状態は、セッションの読み取り結果をスクリーンショット用のスクリプトから設定して作った。
