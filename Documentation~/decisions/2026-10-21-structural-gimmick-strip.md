# VRChat の中でだけ動くギミックを構成で判定して外し、空のオブジェクトを VRM に入れない

- 日付: 2026-10-21
- 対象: `Editor/ExportGimmickDetection.cs`・`Editor/ExportGimmickRules.cs`・`Editor/ExportEmptyNodes.cs`・`Editor/UniVrmOneClickExporter.cs`・`Editor/Locales/*.json`・`Tests/Editor/ExportGimmickTests.cs`・`README.md`・`README.en.md`・`CHANGELOG.md`
- 前提: `2026-10-18-gimmick-rule-table.md` の判定表と `2026-10-18-render-texture-camera-rule.md` の入れ子の扱い

## 背景

判定表の行は、ギミックごとの構成（カメラの映像を自身のメッシュに映す組など）を 1 つずつ書いたもので、表にない構成のギミックはそのまま VRM に入る。VRM にはカメラ・音・パーティクル・接触がないので、こうしたギミックは VRM の中では動かず、見た目のメッシュだけが残る。

もう 1 つ、Modular Avatar の Platform Filter で作者が「VRChat 向けだけに入れる」と指定したオブジェクトがある。書き出しの前の処理は VRChat 向けに走るので、この指定は VRM では効いていなかった。

また、UniVRM はコピーのすべての Transform をノードとして書く。VRChat のメニューや PhysBone の設定だけを持っていたオブジェクトも、中身のないノードとして VRM に残っていた。

## 決定

- 判定表とは別に、構成による判定を 2 つ足した。どちらも名前・GUID・シェーダー名の一覧は使わない。
- Platform Filter（ルール ID `platform-filter`）: 同じオブジェクトに付いた Platform Filter をまとめて読み、Modular Avatar と同じ規則で汎用のプラットフォーム（`nadena.dev.ndmf.generic`）に入らないオブジェクトを丸ごと外す。含める指定と外す指定が混在しているものと、設定を読めないものは「確認が必要」にして残す。構成の判定より先に行う。
- VRChat の中でだけ動くギミック（ルール ID `vrchat-only-structure`）: 候補は、アバターの中で有効な、ルートでないオブジェクトのうち、Modular Avatar のアニメーターの統合かメニューの追加が付いたもの。次の順に見る。
  - 階層の中に、有効で、メッシュのある MeshRenderer か SkinnedMeshRenderer がなければ候補にしない。メッシュのない設定だけの階層は、表情やポーズの取り込みが読むため。
  - ボーンを持つ SkinnedMeshRenderer か、Merge Armature・Mesh Settings があれば、体に付く衣装として候補にしない。
  - 階層の中の Renderer（無効なものも含む）が、lilToon と見なせる材質・MToon・MToon10、または候補の外にあるボーン付きのメッシュと同じシェーダーを 1 つでも使っていれば、アバターの小物（ぬいぐるみなど）として候補にしない。
  - メッシュか材質かシェーダーが欠けていれば「確認が必要」。
  - カメラ・AudioSource・ParticleSystem・Light・接触・コンストレイントのどれかがあれば丸ごと外す。どれもなければ「確認が必要」。
  - 外す前に、判定表と同じ共通の安全確認を行う。ギミックの外から参照されている階層などは「確認が必要」にして残す。
- 候補は外側から順に見る。すでに外すと決めた階層と、「確認が必要」にした階層の中の候補は見ない。外すと決めた階層の中にある判定表の結果（コンポーネント単位のものを除く）は、その階層の結果に置き換える。判定表がギミックの内側だけを外していた場合も、外側の階層ごと外れる。
- 空のオブジェクトの省略: 書き出し用のコピーから、ルート・ヒューマノイドのボーン・すべての MeshRenderer と SkinnedMeshRenderer・UniVRM と書き出しの印のコンポーネントを残し、それらが参照しているもの（ボーン・ルートボーン・Probe Anchor・揺れ物の関節とコライダー・コンストレイントのソース）をたどって残す。残すものの親も残し、それ以外の子を消してから VRM を書く。消した数は Console に出す。
- 3 つとも **補助ギミックを自動除外** がオンのときだけ行う。オフのときの出力は変わらない。

## 確認したこと

- テストで、メニューとパーティクル・カメラ・音を持つギミックが丸ごと外れ、ルートか中のメッシュを「この対象は含める」にすると残ることを確かめた。
- lilToon の材質の小物（無効なものも含む）と、体と同じシェーダーの小物は残り、体のボーンに付く衣装・Merge Armature の付いた衣装は候補にならないことを確かめた。
- VRChat の中でだけ動く部分がないもの、材質が欠けたもの、ギミックの外から参照されているものは「確認が必要」になることを確かめた。
- 判定表のレンズの行が一致するギミックを外側のメニューのまとまりが含むとき、外側の 1 件に置き換わること、外側が「確認が必要」のときは判定表の結果が残ることを確かめた。
- Platform Filter の含める・外す・混在の組み合わせと、自動除外をオフにしたときに何も外れないことを確かめた。
- 書き出したアバターの VRM で、空のオブジェクトが消え、メッシュ・ボーン・揺れ物の関節とコライダー・Spring の Center が残ることを確かめた。

Unity での実行は CI に任せている。

## 検討した代替案と不採用理由

- 判定表をやめて構成の判定だけにする: 構成の判定はメッシュのある階層しか見ないので、メッシュのない設定だけの階層（接触だけのもの・カメラだけのもの）を拾えない。Modular Avatar の統合の設定を持たないギミックも拾えない。判定表の行は残し、構成の判定が外すと決めた階層の中だけ置き換える。
- シェーダー名の一覧でギミックの材質を見分ける: 配布元・版ごとに名前が違い、一覧を追い続けることになる。アバターと同じ系統の材質かどうかだけを見る。

## 残る制約

- lilToon・MToon でも体と同じシェーダーでもない材質の小物に、Modular Avatar のメニューとパーティクルなどが付いていると、ギミックとして外れる。書き出し画面の補助ギミックの一覧に出るので、「この対象は含める」で残せる。
- アバターと同じ系統の材質かどうかは、lilToon・MToon 以外では体のメッシュとシェーダーが同じかどうかで見ている。体と別のトゥーン系シェーダーを使う小物は、アバターの小物と見なせない。
- 空のオブジェクトの省略は、参照をたどれる形で残っているものだけを守る。名前やパスだけで後から探すコンポーネントがあると、そのオブジェクトは消える。

## 影響

- VRChat の中でだけ動くギミックや Platform Filter で VRChat 向けだけにしたオブジェクトを持つアバターの VRM から、その階層が外れる。
- メニューや設定だけを持っていたオブジェクトがノードとして VRM に入らなくなり、ノード数が減る。
- **補助ギミックを自動除外** をオフにしたときの出力は変わらない。
