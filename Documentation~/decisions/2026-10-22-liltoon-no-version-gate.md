# lilToonのバージョンで書き出しを止めない

- 日付: 2026-10-22
- 対象: `Editor/Compatibility/DependencyPolicy.cs`・`Editor/LilToonStructureCheck.cs`・`Editor/LilToonStructureCheck.Unity.cs`・`Editor/LilToonFullSnapshot.cs`・`Editor/UniVrmOneClickExporter.cs`・`Editor/LilToonExporterWindow.cs`・`Compatibility/dependencies.json`・`Compatibility/liltoon-structure.json`・`Tools/check-liltoon-structure.py`ほか
- 配信: 0.12.0-beta.4（プレリリース）。安定版0.11.15は変えない
- 一部を置き換える記録: [2026-10-14-liltoon-version-range.md](2026-10-14-liltoon-version-range.md)・[2026-10-14-liltoon-structure-check.md](2026-10-14-liltoon-structure-check.md)・[2026-10-14-liltoon-structure-hash.md](2026-10-14-liltoon-structure-hash.md)・[2026-10-18-liltoon-range-review.md](2026-10-18-liltoon-range-review.md)

## 背景

0.12.0-beta.1〜beta.3は、導入済みのlilToonが2.0.0〜2.3.4の正式版でなければ書き出しの前に止めていた（2026-10-14の決定）。範囲内でも、アバターが使うシェーダーの構成が2.3.4のカタログと違えば止めていた。

lilToon 2.4.0と2.4.1が公開され、新しいlilToonを入れたプロジェクトでは書き出しがまったくできなくなった。1.xのプロジェクトも同じで、lilToonを更新するまで書き出せなかった。一方で、構成ハッシュは2.0.0〜2.4.1の21タグで2.3.4と同じだった。アプリはもともと、導入済みのバージョンにかかわらず内蔵の2.3.4のシェーダーで描画している。

## 決定

mk（2026-10-22）:「lilToonのバージョンは上限も下限もなくして、可能な限り止めずに書き出す」

- 導入済みのlilToonのバージョンでは止めない。1.x、2.3.4より新しいバージョン（2.4.0・2.4.1・3.xなど）、プレリリース、番号を読めないバージョンも書き出す。2.3.4以外では書き出し結果に「アプリではlilToon 2.3.4として描画します（導入済みのバージョンは{0}）」を出す。
- 止めるのは2つだけ。
  - lilToonが入っていない:「lilToonが見つかりません（VCC／ALCOMでlilToonを追加）」
  - ベイク用シェーダー`Hidden/ltsother_baker`が無いか、2.3.4と違う（プロパティが足りない・型が違うなど）:「lilToon {0}のベイク用シェーダーが2.3.4と違うため書き出せません」、対処「VCC／ALCOMでlilToonを入れ直すか2.3.4に切り替える」。メインカラーのレイヤーをこのシェーダーで焼き込むので、ここが違うと正しい画像を作れない。ベイク用シェーダーに増えたプロパティだけなら止めない。
- アバターが使うシェーダーの2.3.4との違いは、書き出し画面に警告として一覧で出し、書き出しを続ける。

| 違い | 書き出しでの扱い |
| --- | --- |
| 2.3.4にないプロパティ | 書き出さない（「lilToon 2.3.4にないプロパティは書き出しません」） |
| 2.3.4のプロパティが足りない、または型・画像の種類（2D／Cube）が違う | そのマテリアルはlilToonではなくMToonの近似で書き出す。書き出し結果の一覧に理由「lilToon 2.3.4とプロパティが合わないためMToonで近似します」を付けて出す |
| 2.3.4のパスが足りない | 2.3.4のパスとして書き出す |
| 2.3.4にないパス | 書き出さない |
| LightModeが違うパス | 2.3.4のLightModeで書き出す |

- 警告の最後に、Unityの見た目をアプリにそろえる方法を1行出す。ForwardAddのパスが足りないときは「ForwardAddパスを使用」、SHADOW_CASTERの名前が違うときは「Fix for Deffered」のシェーダー設定の案内、それ以外は「lilToon 2.3.4に切り替えるとUnityでもアプリと同じ見た目になります」。
- 書き出したファイルは今までどおり`sourceLilToonVersion`を2.3.4にし、完全なlilToonの契約（`LilToonFullContract`）を満たす。導入済みのバージョンは`asset.extras.VRVLOG_lilToonInstalledVersion`に記録する。アプリは変えない。
- `Compatibility/dependencies.json`の`lilToon.supported`を`lilToon.verified`（2.0.0〜2.4.1）に名前を変える。構成ハッシュが2.3.4と一致すると確かめた範囲の記録で、Exporterはこれで止めない。`DependencyPolicy.LilToonMinimum`／`LilToonMaximum`・`AcceptsNewerLilToon`はなくした。`Tools/check-liltoon-structure.py`は、この範囲のタグの構成ハッシュが2.3.4と違えば検証を失敗にする（記録の誤りを見つけるためで、Exporterの動作は決めない）。
- `Tools/run-liltoon-version-parity.py`による書き出しの一致の確認は残すが、受け付けるバージョンを決めるものではなく、確かめた範囲の根拠として扱う。

## 理由

- 2.4.xや1.xのプロジェクトでは、何も書き出せなかった。止めたときはlilToonのバージョンを変える手順を案内していたが、書き出しのためだけにプロジェクトのlilToonを変えることになる。
- 構成ハッシュ（シェーダー名・プロパティ名・型・画像の次元・パス名・LightMode）は2.0.0〜2.4.1で2.3.4と同じ。構成で止める理由が2.4.xには無かった。
- アプリは導入済みのバージョンを見ずに2.3.4で描画する。止めても止めなくても、アプリでの見た目は2.3.4のものになる。違いで変わるのはUnityでの見た目のほうで、書き出しを止めるより、何が違うかを出すほうが利用者の役に立つ。

## 欠点

- Unityでの見た目がアプリと違っても止まらない。知らせるのは書き出し画面の警告の行と、書き出し結果の「アプリではlilToon 2.3.4として描画します」だけで、読まずに進めると違いに気づかない。
- 2.3.4にないプロパティ・パスで作った効果は書き出さない。新しいlilToonで足された機能は、使っていてもアプリには出ない。
- 2.3.4のプロパティが足りない、または型が違うシェーダーのマテリアルは、lilToonではなくMToonの近似になる。見た目は大きく変わる。
- 構成が同じでも、シェーダーの計算の変更（2.4.1のライトプローブの向きなど）は検出しない。今後のlilToonが計算や構成を大きく変えても、手がかりは警告と構成ハッシュの検証だけになる。

## 既知の差（lilToon 2.4.x）

公式の2.3.4→2.4.0→2.4.1のソースの差分を読んで分かったこと。Exporterはどれも補正しない。

- 2.4.0で`Hidden/lilToonMultiOutline`（ltsmulti_o）のSubShaderのQueueがTransparent-100（2900）からGeometry（2000）に変わった。2.4.xで書き出した輪郭線付きの不透明なlilToonMultiのマテリアルは、renderQueueが2900ではなく2000になる。アプリは記録された値を使うので、Unityの2.4.xと同じ順で描画する。Queueは構成ハッシュに入っていない。
- 2.4.1で`ShadeSH9ToonDouble`のライトプローブの向きが変わった。変わるのはライトプローブの下でのUnityの見た目だけで、書き出すファイルは変わらない。「アプリでの見え方」の画面は導入済みのシェーダーで描画するので、陰影がアプリとわずかに違うことがある。
- APVのサンプリング（URPだけ）とVRC Light Volumes 3.0への対応は、Unity側の描画だけの変更で、ファイルは変わらない。
- エディタ側の修正（使っていない画像の削除、lilToon2Rampなど）はExporterが使わない。`lilConstants.currentVersionValue`は45のままなので、2.4.xを入れてもマテリアルの移行処理は走らない。

実機での書き出しの比較（2.3.4・2.4.1・1.10.3）:

同じプロジェクトのコピーに入れるlilToonだけを替え、同じ14体を同じExporter（このブランチ）で書き出した。Unity 2022.3.22f1、UniVRM 0.131.0。比較は`Tools/compare-liltoon-version-exports.py`（2.3.4の書き出しが基準）。1.10.3はプロジェクトのマテリアルを2.3.4で保存したまま入れ替えたもので、1.xで作ったマテリアルを2.3.4へ移行する場合の確認ではない。

| 入れたlilToon | 2.3.4と同じファイル | 違ったところ | 書き出し結果に増えた警告 |
| --- | --- | --- | --- |
| 2.4.1 | 10体 | 2体の輪郭線付きのlilToonMultiのマテリアル7個でrenderQueueが2900→2000（上のQueueの変更どおり） | 14体とも「アプリではlilToon 2.3.4として描画します（導入済みのバージョンは2.4.1）」だけ。構成の違いの警告は無し |
| 1.10.3 | 12体 | 無し | 14体に導入済みのバージョンの行、11体に「lilToon 2.3.4にないプロパティは書き出しません」（`_IgnoreEncryption`・`_Keys`・`_BitKey0`〜`_BitKey31`、ファーは`_FurMeshType`も）と「lilToon 2.3.4に切り替えるとUnityでもアプリと同じ見た目になります」 |

- どのバージョンでも、止まったアバターとMToonで近似したマテリアルは無かった。
- 「2.3.4と同じファイル」に数えなかった残りの2体は、発光の画像と揺れもののノードの名前に書き出しごとに変わるGUIDが付くもので、lilToonのバージョンと関係ない（2.4.1と1.10.3で同じ2体、同じ名前だけが違う）。
- 1体はメッシュにマテリアルの無い部分があり、lilToonの記録を省略してMToonだけで書き出した（「書き出しの一部を省略しました: マテリアル: lilToonの表現 — Missing material」）。lilToonのバージョンと関係なく、3つとも同じファイルだった（上の「同じファイル」に含む）。

## 検討した代替案と不採用理由

- 範囲の上限を2.4.1に上げるだけにする: 構成ハッシュは一致するので2.4.xは通せるが、1.xと次のlilToonはまた止まる。新しいバージョンが出るたびにExporterの公開を待つことになる。
- 構成が違うシェーダーを今までどおり止める: 2.3.4にないプロパティが1つ足されただけで、アバター全体が書き出せなくなる。アプリが使わないプロパティなので、書き出さずに続けても結果は変わらない。
- バージョンごとに値を2.3.4へ変換する: 2026-10-14の決定と同じく、このプロジェクトでは保守しない。

## 影響

- 0.12.0-beta.4から、lilToonの入っているプロジェクトはどのバージョンでも書き出せる。2.3.4では今までと同じファイルになる。
- 安定版0.11.15は変わらず、2.3.4でだけ書き出せる。
- README・互換性ガイド（`Compatibility/README.md`の Supported lilToon versions）・インストールページの表記を「lilToon 2.3.4推奨」に直した。
