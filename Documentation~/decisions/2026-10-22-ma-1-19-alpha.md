# Modular Avatar 1.19.0-alpha.2 でも表示を固定し、表情を取り込む

- 日付: 2026-10-22
- 対象: `Editor/MaAppearanceSnapshot.cs`・`Editor/VrChatFxExpressions.cs`・`Editor/Compatibility/DependencyPolicy.cs`・`Editor/NdmfExportPreparation.cs`・`Compatibility/dependencies.json`・`Tools/generate-compatibility.py`・`Editor/Locales/*.json`・`Tools/DependencyCompatibilityTests.cs`・`Tests/Editor/NdmfPreparationTests.cs`

## 背景

表示の固定（`MaAppearanceSnapshot`）は、MA の `ReactiveObjectAnalyzer.Analyze` が返す `InitialStates`（`TargetProp` →初期値）を読んで、その値をコピーに書き込む。対応範囲は 1.18.0 以上 1.19.0 未満で、プレリリースは版を読めないものとして API を試していた（2026-10-21-ma-unknown-version）。

1.19.0 の公開ソース（タグ `1.19.0-alpha.0`〜`1.19.0-alpha.2`。2026-10-22 時点で alpha.2 が最新）を読んだ結果は次のとおり。

- alpha.0 は 1.18.7 と同じ解析結果の形で、固定に使う型・メンバーはすべて同じ。
- alpha.1 で解析結果が `InitialStates` から `Shapes`＋`InitialActions` に変わった。キーは `TargetProp` ではなく型つきの対象（`ObjectActiveTarget`・`ShapeKeyTarget`・`MaterialSlotTarget`・`MeshSectionTarget`・`PropertyTarget`・`ReactiveMoveTarget` など）、値は最初から効いている動作（`DriveActiveState`・`SetShapeKey`・`SetMaterial`・`HideMeshSection` など）になった。`InitialActions` には最初から効いているルールがある対象だけが入る。
- それ以外に固定が使うもの（`ReactiveObjectAnalyzer` のコンストラクタ・`OptimizeShapes`・`ForcePropertyOverrides`・`ForceMenuItems`・`GetGameObjectStateProperty`、`AnimatedProperty.actionGroups`、`ReactionRule.ControllingObject`・`ControllingConditions`、`ControlCondition` の 3 フィールド、`ROSimulator` の 2 つの上書き、`ParameterAssignerPass.AssignMenuItemParameter`、`RemoveVerticesFromMesh.FilterPrimitivesOnly`、`IMeshSelector`・`IMeshSelectorBehavior`）は alpha.2 まで変わっていない。
- 1.19 の Reactive Components は FX を BlendTree で作る。メニューのパラメーターごとに、`Apply` ステートの Direct BlendTree の下へ「オフの値（`Threshold`）とオンの値（その次に大きい float）」の 1D の枝を置き、Direct の重みには常に 1 の `$$MA/RC/AlwaysOne` を使う。パラメーターは `$$MA/RC/` で始まる（`AlwaysOne`・`ObjActive/`・`DELAY/` など）。1.18 の FX は `__MA/` や `__ActiveSelf` で始まるパラメーターのステートマシンで、`$$MA/` は出てこない。
- alpha.0・alpha.1 では、非アクティブの Reactive Component が Merge Motion の効果を上書きする（MA の CHANGELOG の #2162。alpha.2 で直った）。Merge Motion で 100 にするはずのシェイプが 25 になるなど、1.18 と書き出しの結果が変わる。
- alpha.2 は NDMF 1.15.0-beta.1 以上を要求する。NDMF の橋渡し（`NdmfExportPreparation.Bridge.Resolve`）は `-` を含む版をすべて止めていたので、MA を入れても書き出せなかった。NDMF 1.15.0-beta.2 までで、書き出しが使う NDMF の API は 1.14.8 と同じ。

alpha.2 で `MaReactiveExpressionExport` の 6 ケース（メニューから Shape Changer を切り替えるもの）が落ちた原因は、表情の自動探索（`VrChatFxExpressions`）が `$$MA/RC/AlwaysOne` を利用者が選べるパラメーターとして扱ったことだった。Direct BlendTree の重みがすべて選べるパラメーターに見えるので、探索は「`AlwaysOne`=1 でメニューの値がオフのとき」の顔を基準の顔との比較なしに別の表情として登録し、メニューの表情 1 つのところに 2 つ並んだ。

## 決定

- 解析結果を 1.18 の形に読み替える。`InitialStates` があればそのまま使い、無ければ `InitialActions` を読む。対象は 1.18 の（オブジェクト, プロパティ名）に、動作は 1.18 の値（表示は 1/0・BlendShape は重み・マテリアル・削除は `IMeshSelector`、残すときは null）に直す。`MeshSectionTarget` はシェイプなら `deletedShape.<名前>`、Mesh Cutter なら `deletedMeshByMask.<セレクタ>` と 1.18 と同じ名前にする。Reactive Move（alpha.1 で追加）と内部パラメーターは固定しないので読まない。分岐は型やメンバーがあるかどうかで決め、ビルドの種類や版の文字列では決めない。
- 表情の自動探索では、`$$MA/` で始まるパラメーターを `__MA/`・`__ActiveSelf` と同じく MA が作ったものとして扱い、利用者が選ぶ入力にしない。これで `AlwaysOne` は今の値のまま残り、オフの値の顔は基準の顔と同じとして落ち、オンの値の顔はメニューの表情と同じとして 1 つにまとまる。1.18 の FX には `$$MA/` が無いので、1.18 の結果は変わらない。
- 実物で動くと確かめたプレリリースだけを通す。MA は `modularAvatarPrereleases`（1.19.0-alpha.2 だけ）、NDMF は `ndmfPrereleases`（1.15.0-beta.1・beta.2）を `Compatibility/dependencies.json` に書き、`DependencyPolicy.ModularAvatarPrereleases`・`NdmfPrereleases` に生成する。alpha.0・alpha.1 は MA 自身の不具合で結果が 1.18 と違うので通さない。
- 一覧とは文字列が完全に一致したときだけ通す。`1.19.0-alpha.2+local` のようにビルドメタデータが付いたものは確かめていない版として止める。
- 一覧に無い `X.Y.Z-pre` は、数字の部分が読めるので「読めた版」として扱い、範囲外の版と同じく固定の前に止める。2026-10-21 の決定のうち、プレリリースを「読めない版」として試す部分をこれで置き換える。`+build` だけが付く版や `Assets` の下の MA など、本当に読めないものはこれまでどおり試す。
- NDMF は `DependencyPolicy.SupportsNdmf` で判定する。1.x の `ndmfMinimum` 以上の正式版と、一覧のプレリリースを通す。
- 止めるときの文は、対応範囲に「確認済みのプレリリース」と一覧を足す。4 つの言語のファイルも直した。
- 正式版の 1.19.0 が出ても、この変更では通らない。`modularAvatarBelow` が 1.19.0 なので、1.19.0 は範囲外の版として止まる。正式版を実物で確かめてから `modularAvatarBelow` を上げる。そのとき alpha.2 を一覧に残すかは、正式版で解析結果や FX の形が alpha.2 から変わったかで決める。

## 理由

- alpha.1 では、型の名前が変わっただけでなく、値の入り方（最初から効いているルールがある対象だけ）も変わった。今回は読み替えで同じ結果になるが、確かめていないプレリリースでは API がそろっていても値の意味が変わって、間違った表示で固定されるおそれがある。API が無くて止まる場合と違い、これは書き出しの結果を見ないと気付けない。そのため、プレリリースは実物で確かめたものだけを通す。
- `InitialActions` に入らない対象は、どのルールも効いていないので今の値のまま。1.18.7 の `InitialStates` はこの対象に今の値を入れていて、固定で書き込んでも何も変わらなかった。どちらでも結果は同じ。ただし BlendShape の今の重みが 0〜100 の外にあるときは、1.18 では固定が 0〜100 に丸めて書き戻し、alpha.2 では書き戻さないので、そのままの値が残る。
- `$$MA/` は MA が予約している名前で、利用者がメニューに置くパラメーターには使われない。探索の側で MA の BlendTree の形を読み解く処理を足すより、既にある「MA が作ったパラメーター」の判定に 1 つ足す方が、1.18 の経路に触れずに済む。

## 残したこと

- 同梱ポーズの判定（`PoseMenuResolver`）は、1.19 の FX でメニューのパラメーターが Float になることを Expression Parameters との型の違いとして警告に出す（「ポーズ未対応: … 型が一致しません」）。警告と、体のポーズの候補の一覧だけに出て VRM の中身は変わらない。直すと 1.18 の経路に手が入るので、今回は直さない。

## 検証

- `Tools/run-compatibility-tests.ps1`: 一覧のプレリリース（alpha.2）は通り、一覧に無いもの（`1.19.0-alpha.0`・`1.19.0-alpha.1`・`1.19.0-alpha.3`・`1.19.0-beta.0`・`1.18.7-beta.1`・`1.18.0-rc.1`）は版を名指しして止まり、`1.18.7+local` などは読めない版のまま試すことを確かめた。NDMF の判定も同じ形で確かめた。
