# Modular Avatar 1.19.0-alpha.0〜alpha.2 でも表示を固定する

- 日付: 2026-10-22
- 対象: `Editor/MaAppearanceSnapshot.cs`・`Editor/Compatibility/DependencyPolicy.cs`・`Editor/NdmfExportPreparation.cs`・`Compatibility/dependencies.json`・`Tools/generate-compatibility.py`・`Editor/Locales/*.json`・`Tools/DependencyCompatibilityTests.cs`・`Tests/Editor/NdmfPreparationTests.cs`

## 背景

表示の固定（`MaAppearanceSnapshot`）は、MA の `ReactiveObjectAnalyzer.Analyze` が返す `InitialStates`（`TargetProp` →初期値）を読んで、その値をコピーに書き込む。対応範囲は 1.18.0 以上 1.19.0 未満で、プレリリースは版を読めないものとして API を試していた（2026-10-21-ma-unknown-version）。

1.19.0 の公開ソース（タグ `1.19.0-alpha.0`〜`1.19.0-alpha.2`）を読んだ結果は次のとおり。

- alpha.0 は 1.18.7 と同じ解析結果の形で、固定に使う型・メンバーはすべて同じ。
- alpha.1 で解析結果が `InitialStates` から `Shapes`＋`InitialActions` に変わった。キーは `TargetProp` ではなく型つきの対象（`ObjectActiveTarget`・`ShapeKeyTarget`・`MaterialSlotTarget`・`MeshSectionTarget`・`PropertyTarget`・`ReactiveMoveTarget` など）、値は最初から効いている動作（`DriveActiveState`・`SetShapeKey`・`SetMaterial`・`HideMeshSection` など）になった。`InitialActions` には最初から効いているルールがある対象だけが入る。
- それ以外に固定が使うもの（`ReactiveObjectAnalyzer` のコンストラクタ・`OptimizeShapes`・`ForcePropertyOverrides`・`ForceMenuItems`・`GetGameObjectStateProperty`、`AnimatedProperty.actionGroups`、`ReactionRule.ControllingObject`・`ControllingConditions`、`ControlCondition` の 3 フィールド、`ROSimulator` の 2 つの上書き、`ParameterAssignerPass.AssignMenuItemParameter`、`RemoveVerticesFromMesh.FilterPrimitivesOnly`、`IMeshSelector`・`IMeshSelectorBehavior`）は alpha.2 まで変わっていない。alpha.1 と alpha.2 の間で、対象と動作の型は同じ。
- alpha.1 と alpha.2 は NDMF 1.15.0-beta.1 以上を要求する。NDMF の橋渡し（`NdmfExportPreparation.Bridge.Resolve`）は `-` を含む版をすべて止めていたので、MA を入れても書き出せなかった。NDMF 1.15.0-beta.2 までで、書き出しが使う NDMF の API は 1.14.8 と同じ。

## 決定

- 解析結果を 1.18 の形に読み替える。`InitialStates` があればそのまま使い、無ければ `InitialActions` を読む。対象は 1.18 の（オブジェクト, プロパティ名）に、動作は 1.18 の値（表示は 1/0・BlendShape は重み・マテリアル・削除は `IMeshSelector`、残すときは null）に直す。`MeshSectionTarget` はシェイプなら `deletedShape.<名前>`、Mesh Cutter なら `deletedMeshByMask.<セレクタ>` と 1.18 と同じ名前にする。Reactive Move（alpha.1 で追加）と内部パラメーターは固定しないので読まない。版ごとの分岐はこの読み替えの 2 か所だけで、固定そのものの処理は 1.18 と共通にする。
- 実物で動くと確かめたプレリリースだけを通す。MA は `modularAvatarPrereleases`（1.19.0-alpha.0・alpha.1・alpha.2）、NDMF は `ndmfPrereleases`（1.15.0-beta.1・beta.2）を `Compatibility/dependencies.json` に書き、`DependencyPolicy.ModularAvatarPrereleases`・`NdmfPrereleases` に生成する。
- 一覧に無い `X.Y.Z-pre` は、数字の部分が読めるので「読めた版」として扱い、範囲外の版と同じく固定の前に止める。2026-10-21 の決定のうち、プレリリースを「読めない版」として試す部分をこれで置き換える。`+build` だけが付く版や `Assets` の下の MA など、本当に読めないものはこれまでどおり試す。
- NDMF は `DependencyPolicy.SupportsNdmf` で判定する。1.x の `ndmfMinimum` 以上の正式版と、一覧のプレリリースを通す。
- 止めるときの文は、対応範囲に「確認済みのプレリリース 1.19.0-alpha.0, 1.19.0-alpha.1, 1.19.0-alpha.2」を足す。4 つの言語のファイルも直した。

## 理由

- alpha.1 では、型の名前が変わっただけでなく、値の入り方（最初から効いているルールがある対象だけ）も変わった。今回は読み替えで同じ結果になるが、確かめていないプレリリースでは API がそろっていても値の意味が変わって、間違った表示で固定されるおそれがある。API が無くて止まる場合と違い、これは書き出しの結果を見ないと気付けない。そのため、プレリリースは実物で確かめたものだけを通す。
- `InitialActions` に入らない対象は、どのルールも効いていないので今の値のまま。1.18.7 の `InitialStates` はこの対象に今の値を入れていて、固定で書き込んでも何も変わらなかった。どちらでも結果は同じ。

## 検証

- `Tools/run-compatibility-tests.ps1`: 一覧のプレリリースは通り、一覧に無いもの（`1.19.0-alpha.3`・`1.19.0-beta.0`・`1.18.7-beta.1`・`1.18.0-rc.1`）は版を名指しして止まり、`1.18.7+local` などは読めない版のまま試すことを確かめた。NDMF の判定も同じ形で確かめた。
- Unity 2022.3.22f1 の実プロジェクトでの結果は `Compatibility/Evidence/ModularAvatarRange` に書く。
