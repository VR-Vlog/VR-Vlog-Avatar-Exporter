# 表情ボードの3ページ目を「VRMの保存と転送」の1ページにする

- 日付: 2026-10-22
- 対象: `Editor/ExperimentalExpressionCaptureWindow.cs`・`Editor/StepIndicator.cs`・`Editor/LilToonExporterWindow.cs`・`Editor/LanTransfer/AppTransferPanel.cs`・`Editor/LanTransfer/AppTransferWindow.uxml`・`Editor/LanTransfer/AppTransferWindow.uss`・`Editor/LanTransfer/AppTransferFlow.cs`・`Editor/Locales/*.json`・テスト

## 背景

転送の画面に **VRMをPCに保存** を置いた（[2026-10-22-save-from-transfer.md](2026-10-22-save-from-transfer.md)）ので、**アプリに転送（通常）** の3ページ目では保存も転送もできるようになった。一方で **VRMを書き出す** の3ページ目は「3 VRMの情報」のままで、作者名・ライセンス設定と下のバーの **VRMを保存** だけがあり、QRは保存したあとの **QRコードでスマホに送る** から別の画面で作っていた。同じ表情ボードの3ページ目が入口によって別の画面になり、保存のボタンも2か所（表情ボードの下のバーと転送の画面の下）にあった。

3つの案のモックを作り、案C（どちらの入口でも3ページ目を転送の画面にし、保存と転送のボタンを1つの行に並べる）を採った。

## 決定

- 3ページ目は、転送のモジュールがあって有効なとき（`LilToonExporterWindow.EmbeddedTransferMethod()` が見つかるとき）は、**VRMを書き出す** でも **アプリに転送（通常）** でも転送の画面（`AppTransferPanel.CreateEmbedded`）にする。名前の欄は残す。転送で送る名前で、**VRMを保存** で保存するVRMの名前（メタ情報のタイトル）にも使うため。保存先のファイル名の初期値はこれまでどおり「<アバター名>-expressions」。作者名と **VRMの利用条件** も転送の画面で聞く。表情ボードの「3 VRMの情報」の作者名・ライセンス設定はこのとき出さないので、表情ボードの既定のライセンスを転送に渡さず、アバターごとに覚えている利用条件から始める（`ShowsOwnInfo`）。
- 転送のモジュールが無い・無効なときの **VRMを書き出す** は、これまでどおり「3 VRMの情報」（作者名・ライセンス設定・保存の結果・下のバーの **VRMを保存**）。**アプリに転送（通常）** でモジュールが無いときは、これまでどおりエラーの枠を出す。
- 工程の名前は、転送の画面を出せるとき（と、モジュールが無いと案内する **アプリに転送（通常）**）は「3 VRMの保存と転送」、2ページ目のボタンは **次へ：VRMの保存と転送** にする。出せないときは「3 VRMの情報」と **次へ：VRMの情報** のまま。見出しが中身と合うようにするため。
- 保存のボタンをフォームの画面とQRの画面で共通の行に移した。行は左から **戻る**、空き、**VRMを保存**、**QRコードを作る**。QRの画面では **QRコードを作る** の場所に **QRを作り直す** を出す（QRを作り直せないあいだも場所は空けておく）。保存の結果と **保存先を開く** はボタンの下の1行に出す。どの状態でも **VRMを保存** は同じ場所にある。
- **VRMを保存** と **QRコードを作る** の並びはどこでも同じで、青いボタン（`primary`）だけが入口で変わる。**VRMを書き出す** から開いたときは **VRMを保存**、**アプリに転送（通常）** と **アプリに転送（かんたん）** から開いたときは **QRコードを作る** が青い。フォームの青いボタンはいつも1つ。QRの表示中の **QRを作り直す** は青くしない（そこでの主な操作はスマホでの読み取り）ので、**アプリに転送** から開いたQRの画面には青いボタンが無い。表情ボードは入口を `Func<bool>` で渡し、パネルは表示を更新するたびに読み直す（表情ボードのモードはメニューで変わるため）。`CreateEmbedded(GameObject)` は残し、`CreateEmbedded(GameObject, Action, Func<bool>)` を足した。
- **戻る** は表情ボードの中だけに出す。かんたんのウィンドウには **戻る** を出さず、QRの画面の右端の **閉じる** はこれまでどおり。そのため、かんたんのQRの画面だけは **VRMを保存** が **閉じる** の分だけ左に寄る。
- 転送の画面を出している3ページ目では、表情ボードの下のバーを描かない。**戻る** と押せない理由はパネルの中にある。
- 利用規約の同意の下に「VRMの保存に同意は要りません」を、ほかの補足の行と同じ灰色の小さい文字で出す。同意の欄があると保存にも同意が要るように見えるため。利用規約・プライバシーポリシーの文言とリンクは変えていない。
- アップロード中とQRの表示中（`Transferring`）に **戻る** を押したとき、およびメニューの **VRMを書き出す...**・**アプリに転送（通常）...** で別のアバターに替えて3ページ目を離れるときは、どちらのモードでも確認を出す。
  - メニューの **VRM書き出し**（と同じアバターの **VRMを書き出す...**）は、確認も中止もせずに青いボタンだけを **VRMを保存** に移す。3ページ目はどちらのモードでも同じパネルなので、ページを離れず、表示中のQRもそのまま使える。[2026-10-14-app-transfer.md](2026-10-14-app-transfer.md) の「同じアバターでメニューを開いたときは転送を続ける」と同じ扱い。
  - タイトル「転送を中止」、本文「このQRコードは使えなくなります」、ボタンは **中止して移動**（OK）と **転送を続ける**（キャンセル）。何が起きるかをボタンの名前だけで分かるようにし、「はい」「いいえ」は使わない。
  - 書き出し・アップロード前のフォーム、期限切れ、受け取り完了のあとは確認しない。失うものが無いため。
  - **中止して移動** で消すのは転送用の一時VRMだけ。**VRMを保存** で保存したファイルは、送るときに一時VRMへコピーしてから使うので消えない。メニューで別のアバターに替えたときは転送の画面を作り直すので、名前と同意はフォームの初期値に戻る。**戻る** で中止したときは同じアバターのままなので、名前と同意は残る。
  - 表情ボードを閉じたときは、これまでどおり確認せずに中止する。Unityの `hasUnsavedChanges` を使うと、閉じるときのダイアログのボタンがUnityの「Save」「Discard」になり、転送には合わないため。QRの近くの「ページを移るかボードを閉じると転送を中止します」は変えていない。
- PR #372 の、保存したファイルを転送に使い回す仕組み（`savedWritten`・`sentWritten`・`ReuseSavedCopy`）は変えていない。

## 変えた文言

| 前 | 後 | 理由 |
| --- | --- | --- |
| VRMをPCに保存 | VRMを保存 | 表情ボードの保存のボタンと1つにしたので、同じ名前にした |
| 3 名前と利用条件 | 3 VRMの保存と転送 | 3ページ目で保存も転送もできるため。転送の画面を出せないときは「3 VRMの情報」 |
| 次へ：名前と利用条件 | 次へ：VRMの保存と転送 | 同上。出せないときは「次へ：VRMの情報」 |
| （なし） | VRMの保存に同意は要りません | 保存に同意が要らないことを同意の欄の下で言う |
| 進行中の転送を中止します。表示中のQRは使えなくなります。（表情ボードの確認と、パネルの「アバターを変更」「QRを作り直す」の確認） | このQRコードは使えなくなります | 句点と重複をなくした。3つの確認で同じ本文にした |
| はい・いいえ相当のOK・キャンセル（中止・戻る） | 中止して移動・転送を続ける | ボタンの名前で結果が分かるようにした |
| 戻る（パネルの「アバターを変更」「QRを作り直す」の確認のキャンセル側） | 転送を続ける | 3ページ目の **戻る**（2ページ目へ）と同じ名前で別の意味になっていたため。OK側の **変更する**・**作り直す** は変えていない |
| Playモードを終了すると編集できます。 | Playモードを終了すると編集できます | 句点をなくした（表情ボードと転送の画面の両方） |

en・ko・zh-Hans・zh-Hantの訳を入れ、使わなくなった「3 名前と利用条件」「次へ：名前と利用条件」「VRMをPCに保存」「進行中の転送を中止します。表示中のQRは使えなくなります。」を4言語から消した。

## 検討して採らなかったもの

- 同意をQRのボタンを押したあとのダイアログに移す案。フォームから同意の欄が消えて保存と転送の違いは分かりやすくなるが、利用規約の同意を求める場所と見せ方が変わる。同意の文言と見せ方は変えない方針なので採らず、同意の欄の下に「VRMの保存に同意は要りません」を足すことにした。
- 保存と転送を切り替えるトグルを置き、青いボタンを1つだけにする案。押す前に切り替えが1回増え、保存と転送の両方を使うとき（PR #372 で書き出しを1回にした使い方）に向かないので採らなかった。
- 入口ごとにボタンの並びを入れ替え、青いボタンをいつも右に置く案。入口で **VRMを保存** の場所が変わるので採らず、並びを固定して色だけ変えた。
- 確認を出さずに **戻る** で中止する案。QRを読み取らせている途中に押すとそのQRが使えなくなるので、転送中だけ確認する。

## 確かめたこと

- CLIのテスト（`Tools/run-lan-transfer-tests.ps1`）を `-CloudAvailabilityMode` の Default・EditorOnly・DevelopmentOnly・DevelopmentEditor の4つで回した。
- Unity 2022.3 と互換の対象のコンパイル（`compile_all.py`）で全件コンパイルできることを確かめた。
- EditModeテストを足した。青いボタンが入口に従って1つだけになり読み直しで切り替わること、**戻る** が表情ボードの中だけに出ること、3ページ目が転送の画面になる条件、**戻る** の確認（転送を続けると残り、中止すると2ページ目へ進む）、確認の文言が4言語にあること、`EmbeddedTransferMethod` が3引数の `CreateEmbedded` を指すこと。
- Unityを起動しての画面の確認とスクリーンショットはこの変更ではまだ撮っていない。
