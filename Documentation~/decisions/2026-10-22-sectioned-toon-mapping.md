# 区画を切り替えて使うトゥーンシェーダーを、区画ごとに公式 lilToon へ写す

- 日付: 2026-10-22
- 対象: `Editor/UnsupportedShaderSubstitution.cs`（`Create`・`Apply`）・`Editor/UnsupportedShaderSubstitution.Toon.cs`・`Editor/Locales/*.json`・`Tests/Editor/SectionedToonSubstitutionTests.cs`・`Tests/Editor/SectionedToonProbe.shader`・`README.md`・`README.en.md`・`CHANGELOG.md`

## 背景

- 非対応シェーダーの材質は、公式 lilToon に置き換えるときに共通して読めるもの（主画像と主色・カットアウトと半透明・ノーマルマップ・発光・影色）だけを写していた（2026-10-18、2026-10-20 の決定）。
- 照明の種類（`_LightingMode`）を選び、マットキャップ・リム・アウトラインなどを区画ごとに有効にして使うトゥーンシェーダーは、VRChat 向けのアバターで広く使われている。このシェーダーの材質は次のように見た目が変わっていた。
  - 照明が Flat（影を出さない）でも、lilToon の既定の影が出る。
  - マットキャップ・リムライト・アウトラインが消える。
  - 明るさの上限（`_LightingCap`）が無視され、明るいワールドで白飛びする。
  - ステンシルの設定が消え、髪越しに眉を見せるような重ね方が崩れる。
- このシェーダーは区画の大半が lilToon に同じ役割の項目を持つ。区画ごとに対応を決めれば、汎用の写し方よりかなり近い見た目にできる。

## 決定

### 1. 判定と入口

- 材質のプロパティだけで判定する。`_LightingMode` があり、`_ShadingEnabled`（現行の版）か `_LightingRampType`（古い版）もあるもの。シェーダー名では分けない。シェーダーが見つからない材質も、保存された値で同じように判定できる。
- 分岐は `Create` の 1 か所だけにする。lilToon とその派生版は従来どおり `FromDerived`、判定に当たらない材質は従来どおり `FromGeneric` を通る。判定に当たる材質は `FromGeneric` で共通の部分を写したあと、区画ごとの処理が自分の担当する lilToon の値を上書きする。
- 書き込むのは公式 lilToon 2.3.4 のプロパティだけにする。元のシェーダーのコードは写さず、プロパティ名と、公開されている式の意味だけを対応させる。

### 2. 区画ごとの対応

| 区画 | lilToon の項目 | 写し方 |
|---|---|---|
| 色調補正 | `_MainTexHSVG`・`_MainGradationTex` | 色相・彩度・明るさ・ガンマを x・y・z・w に入れる（下の 3 を参照）。グラデーションは強さと画像をそのまま渡す |
| 主画像のスクロール | `_MainTex_ScrollRotate` | `_MainTexPan` の x・y |
| 描画モード | `_Cutoff`・`_SrcBlend`・`_DstBlend`・`_AlphaToMask`・`_AlphaMask*` | 切り抜き付きの半透明はしきい値を残す。加算・乗算のプリセットはブレンド係数を残す。アルファマスクは R チャンネルだけを使う単純な形のときだけ写す |
| 照明 Flat | `_UseShadow` = 0 | 影を出さない |
| 照明 Multilayer Math | 影 3 段の各プロパティ | 同じ名前・同じ式なのでそのまま写す。1 影の画像に主色を掛けるため `_ShadowMainStrength` を 1 にし、画像の無い 2 影が見えるときは報告する（下の「成り立たない場合」） |
| 照明 Shade Map | 1 影・2 影の境界・ぼかし・色・画像 | 境界は step − feather/2、ぼかしは feather。画像のない Replace の影色は主色との比にする（lilToon は影色に主色を掛け直す）。乗算で主画像を掛け直す要否が 1 影と 2 影で違うときは報告する |
| 照明 Wrapped | 1 影 | グラデーションの始点と終点の中央を境界、幅をぼかしにする。影色は黒 |
| 照明 Texture Ramp | 1 影 | ランプ画像の中央の行を GPU で読み、暗い端の色・明るさが半分になる位置・10% と 90% の幅から 1 段の影に当てはめる |
| 照明 Realistic・Cloth | 1 影 | Lambert の N·L に合わせ、境界 0.75・ぼかし 0.5（lilToon の半ランバートの軸）。影色は黒 |
| 照明 Skin | 影なし | 既定の参照テクスチャが白で影が付かないため Flat と同じに扱い、照明の種類の名前を報告する |
| 照明 Cloth | Realistic と同じ | 近似で写し、照明の種類の名前を報告する |
| 照明 SDF | なし | 影を出さず、報告する |
| 明るさの上限・下限・モノクロ | `_LightMaxLimit`・`_LightMinLimit`・`_MonochromeLighting` | 上限を切っているときは 10（lilToon の上限） |
| マットキャップ 1・2 | `_UseMatCap`・`_UseMatCap2nd` の各項目 | 置換・乗算・加算・スクリーンの重みのうち最大のものを lilToon の合成方法に選ぶ。強さは `_MatcapIntensity` を色に掛ける。滑らかさはミップの段（`Lod`）にする。マスクは表の下の注を参照 |
| リムライト | `_UseRim` の各項目 | lilToon 形式のリムは同じ名前なのでそのまま写す。それ以外は幅・鋭さ・べき乗から lilToon の境界とぼかしを求める。発光として足す分はライトの影響を受けない割合にする。マスクは表の下の注を参照 |
| アウトライン | アウトライン付きのシェーダーと `_OutlineWidth`・`_OutlineFixWidth`・`_OutlineColor`・`_OutlineTex`・`_OutlineWidthMask` | 主色を混ぜる設定は主画像と主色を掛けて渡す |
| 発光 | `_EmissionBlendMask`・`_EmissionMap_ScrollRotate`・`_EmissionBlink` | 点滅は両方とも sin(時間 × 速さ + 位相) なので、最大値を色に掛け、最小値を lilToon の振れ幅にする。マスクは表の下の注を参照 |
| ステンシル | `_Stencil*`・`_OutlineStencil*` | 意味が同じものを lilToon の名前で書く |

lilToon に無い区画（デカール・ディゾルブ・グリッター・AudioLink・頂点の変形・反射とスペキュラー・3 番目以降のマットキャップなど 50 余り）は、有効になっていれば書き出さずに報告する。対応表は `ToonDroppedSections` に置き、区画の名前は元のシェーダーのインスペクターの表記にする。

マットキャップ・リム・発光のマスクについて: 元のシェーダーはマスクの 1 チャンネルを読むが、lilToon はマットキャップのマスクを RGB、リムと発光のマスクを RGBA で掛ける。R チャンネルを選んだマスクは、画像を GPU で 32×32 に縮めて読み、灰色で不透明なときだけ写す。色や透明のあるマスク、R 以外のチャンネル、反転したマスクは写さずに報告する（効果はマスク無しで掛かる）。グラフィックスデバイスが無くて読めないときは写す。輪郭線の幅のマスクとアルファマスクは lilToon も R だけを読むので、R を選んでいればそのまま写す。

### 3. 色調補正の色相と彩度（2026-10-20 の決定を、このシェーダーに限って改める）

2026-10-20 の決定では、色相と彩度は lilToon の HSV の式と結果が違うので写さず報告するとした。このシェーダーでは次の理由で `_MainTexHSVG` の x・y に近似して入れる。

- このシェーダーで色相・彩度を使う材質は、髪や服の色違いを作るために色相を大きく回していることが多い。写さないと元の色（たとえば青い髪が赤い髪）で書き出され、報告を読んでも利用者には直す手段がない。近似でも色の系統が合うほうが元に近い。
- `LilToonMainTextureBaker` が `_MainTexHSVG` を主画像に焼き込むので、近似の結果はアプリでもそのまま見える。

写し方は次のとおり。

- 色相: 元のシェーダーは OKLab の色相を回す。lilToon は HSV の色相に足す。`_MainHueShift`（0〜1 で一周）を -0.5〜0.5 に直して x に入れる。色を選んで置き換える設定・時間で回す設定・置き換えない設定（`_MainHueShiftReplace` が 0）は写さず報告する。
- 彩度: 元は輝度との線形補間、lilToon は HSV の彩度の倍率。y = max(0, 1 + `_Saturation`) とする。
- 明るさとガンマは 2026-10-20 の決定と同じ。
- 区画ごとのマスク（`_MainColorAdjustTexture`）、明るさのグローバルマスク、グラデーションのマスク、`_MainChromatize`、`_MainTintColor` は写さず、効果の名前（Color Adjust Mask・Brightness Mask・Gradation Mask・Chromatize・Tint。写せない色相の設定は Hue Shift）で報告する。この経路では汎用の置き換えの通知（色相・彩度などを反映していない）は出さない。写した項目まで写していないように読めるため。
- lilToon は主画像に補正を掛けてから `_Color` を掛け、元のシェーダーは主色を掛けたあとに補正する。明るさは順番によらず同じになるが、色相・彩度・ガンマ・グラデーションは `_Color` が白のときだけ一致する。白でないときは写したうえで「Color Adjust with Main Color」として報告する。

ほかのシェーダーの色相・彩度は従来どおり写さない。

### 変わらないことの保証

- 判定に当たらない材質は `FromGeneric` だけを通り、書き出す結果は従来と同じ。lilToon の材質と派生版は対象外。
- 区画が無効（トグルが 0）なら、その区画の lilToon の項目は `FromGeneric` の結果か lilToon の既定値のまま。

## 成り立たない場合

- Texture Ramp は画像の中央の行だけを読む。縦方向に色が変わるランプや、影の段が 2 つ以上あるランプは 1 段に丸める。グラフィックスデバイスの無いバッチ実行（`-nographics`）では読めないので、lilToon の既定の影になる。
- 色相の回転は OKLab と HSV で色ごとに結果が違う。彩度の高い色ほど差が大きい。
- マットキャップは合成方法を 1 つしか選べないので、置換と加算を混ぜて使う材質は重みの大きいほうだけになる。
- リムの位置は元の式の両端の中央に置くので、べき乗が大きい材質ではぼかしの形が違う。
- Shade Map の置換（既定）で影の画像が無いとき、元のシェーダーは影色をそのまま塗るが、lilToon は影の画像が無いと影色に主画像を掛けるので、影の中に模様が残る。白い影の画像を割り当てれば主画像から切り離せるが、lilToon は影を明るい側の色より明るくしない（`min(indirectCol, directCol)`）ので、暗い模様を明るい影色で覆う置換はそれでも再現できない。色は主色との比で写すだけにした。
- 元のシェーダーの Multilayer Math と Texture Ramp は、`_LightingIgnoreAmbientColor` が 1 未満だと影をシーンの環境光で照らす。lilToon は影にも主ライトの色を掛けるので、環境光の暗いシーンでは影が浅くなる。シーンで決まる値なので材質では合わせられず、「Indirect Shadow Color」として報告する。
- lilToon の `_ShadowMainStrength`（影色に主画像を掛け直す強さ）は 1 影・2 影で共通。乗算の Shade Map で片方の層だけが画像（または主画像）を使うとき、Multilayer Math で 1 影だけに画像があり 2 影が見えるときは、片方の層の影の濃さが元と違う。「Multiplied Shadow Layers」として報告する。
- 加算・乗算の描画プリセットはアルファを書かないので、透明の背景に描いた画素の差では比べられない。合成の係数を写したことだけを確かめた。

## 確認したこと

- EditMode テスト `SectionedToonSubstitutionTests`（21 件）で、色や透明のある R チャンネルのマスクを写さずに報告し灰色のマスクは写すこと、白でない主色の下での色調補正の報告と明るさだけなら報告しないこと、乗算の影の層の食い違いの報告、Skin の照明が影を出さずに報告されること、環境光で照らす影の報告、Flat の照明が影を出さず明るさの上限を残すこと、上限を切ると 10 になること、Shade Map・Wrapped の境界とぼかし、乗算の Shade Map、照明を切ったときに影が出ないこと、切り抜き付き半透明のしきい値、色調補正の 4 値、時間で回す色相を効果名で報告すること、マットキャップの合成方法の選び方、リムの境界とぼかし、アウトラインのシェーダーと幅、ステンシルの名前の対応、警告の文面を確かめた。
- 評価（リポジトリの外）: 球とアバターを、このシェーダーで描いた画像・従来の置き換え・今回の置き換えの 3 通りで Built-in の Unity 2022.3.22f1 で描き、ΔE（CIEDE2000）と SSIM を比べた。設定を決めるのに使った標本と、数値を出す標本を分けた。結果は次のとおり。

| | ΔE00 の平均 | 画像ごとの 95 パーセンタイルの平均 | SSIM（L*） |
|---|---|---|---|
| 従来の置き換え | 10.64 | 24.48 | 0.899 |
| 今回の置き換え | 4.00 | 9.18 | 0.971 |

評価用の 39 材質 × 2 形状 × 4 ライト（312 組）の値。ΔE は 2 枚のどちらかが覆う画素だけで平均し、背景は数に入れない。材質ごとに平均すると、39 材質のうち 38 が改善し、悪化は 1（影を環境光で照らすプリセット、+0.52）。材質単位で差の平均は -6.64、ブートストラップの 95% 区間は -8.76〜-4.96。区画別の平均は、色相・彩度 21.9 → 2.8、マットキャップ 14.7 → 4.0、Multilayer の影 9.4 → 2.2、ノーマル 10.9 → 2.4、リム 8.5 → 3.1、ランプ 5.8 → 2.7、半透明 7.2 → 2.6、プリセット 10.1 → 5.0、Shade Map 12.5 → 12.1（上の置換の制約による）。

調整用の標本で見つけた Skin の照明（黒い影が付いて 3.8 → 30.2）を直したあとに評価用の数値を出し直し、評価用の数値が変わらないことを確かめた。評価用の標本を見てから入れた変更は「Indirect Shadow Color」の報告だけで、写し方は変えていない。

## 検討した代替案と不採用理由

- 汎用の写し方（`FromGeneric`）を広げて、このシェーダーのプロパティも読む: 区画のトグルと照明の種類で意味が変わる値が多く、汎用の処理に分岐が増える。入口を 1 か所にして区画ごとの処理にまとめたほうが読みやすい。
- 元のシェーダーの式で主画像や影を焼き込む: 2026-10-18 の「シェーダーごとの個別変換は書かない」に反し、元のシェーダーのコードを写すことにもなる。lilToon のプロパティに置ける範囲に留めた。
- 色相・彩度は 2026-10-20 の決定どおり報告だけにする: 上の 3 のとおり、色違いの材質が元と違う色になる。評価で近似のほうが元に近いことを確かめたうえで改めた。
