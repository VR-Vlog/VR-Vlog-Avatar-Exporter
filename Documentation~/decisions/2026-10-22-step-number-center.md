# 手順の丸の番号を丸の中心に置く

- 日付: 2026-10-22
- 対象: `Editor/StepIndicator.cs`・`Editor/ExperimentalExpressionCaptureWindow.cs`・`Tests/Editor/StepIndicatorTests.cs`

## 背景

表情ボードの上の手順の行（2026-10-22-step-indicator.md）で、丸の中の番号が丸の中心から左にずれて見えると mk から指摘があった。今の手順の塗った丸も、まだの手順の輪も同じようにずれていた。

## 原因

番号は `GUI.Label` に `TextAnchor.MiddleCenter` のスタイルで丸の Rect を渡して出していた。IMGUI が中央に置くのは文字の送り幅と行の高さの箱で、字形そのものではない。さらに描く位置を整数pxに切り捨てる。数字の字形は送り幅の中で左右の余白が均等でなく、その差と切り捨てが重なって、横に最大で2px（UIスケール300%では3px）左にずれていた。縦のずれは0.5px以内だった。

## 決定

- 番号と「!」は `GUI.Label` を使わず、`EditorStyles.miniBoldFont` から字形を取り出して GL で直接描く（`DrawStepGlyph`）。字の大きさとフォントは今までのスタイル（`miniBoldLabel`）と同じで、色も `stepMarkerText`・`stepMarkerDim` の文字色をそのまま使う。
- 字形は `EditorGUIUtility.pixelsPerPoint` を掛けた大きさで取り出し、拡大で滲ませない。
- 横は字形の箱（`CharacterInfo` の minX〜maxX）の中心を丸の中心に合わせる。
- 縦は「1」の箱が丸の中心に来る位置にベースラインを置き、どの字もそのベースラインに立たせる。数字と「!」は高さが同じだが、箱の上下の余白が字ごとに違う（「!」は下に1px多い）。字ごとに箱の中心で合わせると、UIスケール150%で「!」が1.5px上に浮いた。
- 字形の端は整数のデバイスpxに揃える（`StepIndicator.GlyphRect`）。半端な位置に置くと字がぼやける。
- フォントや字形が取れないときは今までどおり `GUI.Label` で描く。

## 修正前と修正後のずれ

丸の中心と字形の描かれた範囲の中心の差を、画面のスクリーンショットから測った（デバイスpx・右と下が正）。幅1000の1ページ目（1は塗った丸、2と3は輪）と3ページ目（3は塗った丸）。

| UIスケール | 修正前 1 / 2 / 3 / 塗った3（横） | 修正後（横） | 修正前（縦） | 修正後（縦） |
| --- | --- | --- | --- | --- |
| 100% | -2.0 / +0.5 / -1.5 / -2.0 | 0.0 / +0.5 / +0.5 / 0.0 | +0.5以内 | +0.5以内 |
| 150% | -0.5 / -1.5 / -2.0 / -2.0 | +0.5 / +0.5 / 0.0 / 0.0 | +0.5以内 | -0.5以内 |
| 200% | -1.0 / 0.0 / -0.5 / -0.5 | 0.0 / 0.0 / +0.5 / +0.5 | -0.5以内 | +0.5以内 |
| 300% | -3.0 / +0.5 / -2.0 / -2.0 | 0.0 / +0.5 / 0.0 / 0.0 | 0.0 | 0.0 |

修正後は横も縦も0.5px以内になった。0.5pxは丸の直径と字形の幅の偶奇が合わないときの残りで、これ以上は寄せられない。例外は150%・幅600の輪の3で、丸そのものが半端な位置にあるため+1.0pxになる。比べた画像は `Documentation~/Verification/step-number-center.png`（丸の周りを拡大し、赤線が丸の中心）。

## 相談した意見

描き方を別のモデルに相談した。

採ったもの:

- `SetPass` に失敗したときも `GUI.Label` に戻して、番号を消さない。
- 文字色に `GUI.color` と `GUI.contentColor` を掛け、`GUI.Label` と同じ色の扱いにする。
- 字形の幅と高さは変えず、左端とベースラインだけを整数pxに丸める（`GlyphRect` は初めからそうしている）。

採らなかったもの:

- GL の描画をスクロールやグループのクリップに合わせる処理。手順の行はスクロールの外にあり、クリップされる位置に来ない。描くのは Repaint のときだけ。

## 入れなかったもの

- `GUIStyle.contentOffset` で字ごとに位置をずらす方法。ずれは字・UIスケール・丸の位置で変わるので、固定のずらし量では直らない。
- 番号を画像にして描く方法。言語やフォントを変えたときに追従しない。

## 確認したこと

- EditMode テスト `StepIndicatorTests` に3つ足した。字形の箱が丸の中心に0.5デバイスpx以内で置かれ端が整数pxに揃うこと（UIスケール100・150・200・300%）、箱の余白が違う字も「1」と同じベースラインに立つこと、エディタのフォントから取った「1」「2」「3」「!」が実際のウィンドウの丸の中心に置かれ丸からはみ出さないこと。22件すべて通った。
- UIスケール100・150・200・300%で、1ページ目・3ページ目・2ページ目の除外のエラー（「!」）を撮って測った。幅600・1000・1400で撮り、丸の位置によらず中心に来ることを確かめた。
- 日本語・英語・韓国語・簡体字・繁体字で撮り、番号の位置が言語で変わらないことを確かめた。
- 字の色・濃さ・太さが修正前と同じことを、丸の中の最も明るい色と字の面積で比べた。
- 色空間が Gamma と Linear のプロジェクトで、輪の番号と、同じ色で `GUI.Label` が描く隣の手順名の最も明るい色を比べた。Gamma では番号154・名前151〜152、Linear では番号204・名前202〜203で、どちらでも同じ扱いになる。
