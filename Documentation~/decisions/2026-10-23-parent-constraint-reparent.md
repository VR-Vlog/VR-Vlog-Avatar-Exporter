# Parent Constraintで追従する小物をソースの子に移して書き出す

- 日付: 2026-10-23
- 対象: `Editor/ConstraintExport.cs`・`Editor/Locales/ExporterLocale_*.json`・`Tests/Editor/ConstraintExportTests.cs`

## 背景

アバターのルート直下などに置いた小物を、Parent Constraint（VRChatの VRC Parent Constraint と Unity の Parent Constraint）で手や頭のボーンに追従させる作りはよくある。VRMの `VRMC_node_constraint` が持つのは rotation・roll・aim の3種で、位置ごと追従させるものがない。そのためこれまでは Parent Constraint を「VRMに同じ働きのコンストレイントがない」として省き、今の姿勢のまま書き出していた。アプリでは手を動かしても小物がその場に残り、追従しない。

## 決定

- 次をすべて満たす Parent Constraint は、ワールドの位置・回転・拡大縮小を変えずに対象をソースの子へ移す。親子関係なら VRM でもソースと一緒に動く。
  - ソースが1つ（強さ0のソースは数えない）で、FreezeToWorld がオフ
  - 位置と回転の全軸が対象で、ローカル空間ではない
  - 強さ（全体の強さ×ソースの強さ）が1
  - 対象とその子に人型のボーンがない（骨格の親子を変えない）
  - 対象がほかのコンストレイントのソースでも対象でもない（移すとそちらの基準の向きが変わる）
  - ソースが対象の中にない
- 移すと拡大縮小で形が崩れる（親の非一様な拡大縮小でせん断が出る）ときは移さない。判定と巻き戻しは小物の付け替えと同じ `ExportAttachmentSession.ReparentPreservingPose` を使う。
- 移すのは回転などのコンストレイントを VRM に変換し終えたあとにする。VRM の回転コンストレイントはローカルの向きを読むので、先に親を変えると基準が変わる。
- 移せなかったものは、これまでどおり今の姿勢のまま書き出し、結果の一覧に「ソースの子に移すと動きが変わる設定（…）」と理由を出す。
- Parent Constraint どうしが連なる場合（小物の上にさらに小物）は、どちらの順でも両方移す。

## 確認

- `ConstraintExportTests` に、移す・連なる・移さない各条件（軸・強さ・ソースの強さ・別のコンストレイントが参照・複数ソース・ソースが対象の中・人型のボーン）・書き出したglTFで小物の親が手のノードになることのテストを足した。
- 手元のアバターで、トラッカー経由で手に追従する小物を書き出し、修正前は省かれ、修正後は手側のノードの子になることを見た。

## 欠点

- Parent Constraint はソースの拡大縮小に追従しないが、子にすると追従する。ソースの拡大縮小をアニメーションで変えるアバターでは、アプリでの大きさが VRChat と変わる。
- 書き出し時の今の位置関係をそのまま親子にするので、コンストレイントのオフセットと今の位置がずれているアバターでは、そのずれも残る（これまでの「今の姿勢のまま」と同じ前提）。
- 複数のソースを切り替える作り（FXで強さを入れ替える）は、強さが1のソースが1つだけのときに移す。入れ替えた先のソースには追従しない。
