# アバターのポーズを付ける仕組みを働きで判定して外し、ボーンの親子が崩れた VRM を書かない

- 日付: 2026-10-23
- 対象: `Editor/ExportGimmickDetection.cs`・`Editor/ExportGimmickRules.cs`・`Editor/ExportGimmickChoices.cs`・`Editor/UniVrmOneClickExporter.cs`・`Editor/LilToonGlbExtension.cs`・`Editor/Locales/*.json`・`Tests/Editor/ExportGimmickTests.cs`・`Tests/Editor/PhysBoneSpringExportTests.cs`・`Tests/Fixtures/PoseMotionProbe.cs`・`Tools/run-unity-compatibility.py`・`README.md`・`README.en.md`・`CHANGELOG.md`
- 前提: `2026-10-21-structural-gimmick-strip.md` の構成による判定と、共通の安全確認（`SharedUnsafeReason`）

## 背景

VRChat 向けのポーズの仕組み（座る・寝るなどのポーズをメニューから付けるもの）を入れたアバターを書き出すと、アプリでポーズが付かず T ポーズのままになることがあった。

入れたものと入れていないものを同じアバターで書き出して比べた。

- ある仕組みは、書き出しの前の処理（NDMF）で Modular Avatar の World Fixed Object と Bone Proxy を使い、体のボーンをワールドに固定したオブジェクトの下へ付け替える。ボーンごとに同じ名前の複製を作り、元のボーンをその子にする。
- この形で書き出した VRM は、ヒューマノイドのボーンが全部割り当てられているのに、各ボーンの親のボーンがノードの祖先にならない。読み込むと Unity のヒューマノイドとして組めず（`isHuman` が false）、アプリはポーズを当てられない。
- 別の仕組みは、胴や脚の muscle を動かすアニメーションを多数持つが、ボーンを付け替えない。書き出した VRM は入れていないものと骨・スキンが同じで、ポーズは付く。ただし VRM の中では働かず、ポーズはアプリで付けるので、入れておく理由がない。
- ポーズのライブラリの仕組みは、もともと `PoseExportSession` が書き出し用のコピーから外し、そのポーズをアプリのポーズとして取り込んでいる。出力は入れていないものとバイト単位で同じ。

## 決定

- 構成による判定に、ポーズを付ける仕組みの判定を 2 つ足した。どちらも名前・GUID の一覧は使わない。**補助ギミックを自動除外** がオンのときだけ行い、外したものは既存の **含める** で残せる。
- ボーンの付け替え（ルール ID `skeleton-takeover`）: World Fixed Object を持つ階層の中に、Hips を対象にした Bone Proxy（`boneReference` が Hips で `subPath` が空、または参照先がアバターの Hips）があれば、その階層を丸ごと外す。
- ポーズのアニメーション（ルール ID `pose-motion`）: コンポーネントのシリアライズされた参照から AnimationClip・AnimatorController・BlendTree をたどり、胴（Spine・Chest・UpperChest）か脚（UpperLeg・LowerLeg・Foot・Toes）の muscle カーブを持つものを参照していれば、その階層を丸ごと外す。手・指・頭・目・顎は、ジェスチャー・表情・手に持つ小物・頭の向きでも動くため数えない。
  - アバターのルートのコンポーネント・VRChat の SDK のコンポーネント（Avatar Descriptor・Station など）は見ない。座りや移動のアニメーションはそこにもあるため。
  - ポーズのライブラリのコンポーネントは見ない。外すとポーズの取り込みが消えるため。
  - 階層の中にボーンを持つ SkinnedMeshRenderer か Merge Armature・Mesh Settings があれば、体に付く衣装として外さない。
- 外す単位は、そのコンポーネントを含む最も外側の prefab インスタンス（アバターのルートより下）、なければアバターのルートの直下の子。仕組みは prefab で配布され、設定の prefab を入れ子にしていることが多いため。
- 外す前に、ほかの構成による判定と同じ共通の安全確認を通す。ヒューマノイドのボーンを含む階層や、外から参照されている階層は「確認が必要」にして残す。
- 安全網として、書き出しの前の処理のあとのコピーで、各ヒューマノイドのボーンがヒューマノイド上の親のボーン（割り当てのある最も近いもの）の子孫かを確かめる。外れていれば書き出しを止め、崩れたボーンの名前を出す（`MovedHumanBones`）。**含める** で付け替えの仕組みを残したときや、判定に掛からない別の仕組みで T ポーズの VRM ができるのを防ぐ。
- 同じ確かめを、UniVRM が書いた VRM のヒューマノイドのノードでも行う（`ValidateOutputHumanoid`）。付け替えの仕組みを **含める** で残して書き出すと、コピーの確かめの時点では Animator のボーンは元の並びのままで、UniVRM が書き込むときには Animator が同じ名前の複製のほうを返し、親子の崩れた VRM が保存されていた。保存の前の検査（`LilToonGlbExtension.Validate`）にも同じ確かめがあるが、lilToon の全項目を持つファイルでは通らない。

## 確認したこと

- テストで、胴か脚のポーズを持つ仕組みが丸ごと外れ、**含める** で残ること、AnimatorController と BlendTree の中のポーズも見つかること、手・頭・顎・指だけのアニメーションでは外れないこと、体のボーンに付く衣装は外れないことを確かめた。
- テストで、World Fixed Object と Hips の Bone Proxy を持つ階層が丸ごと外れ、Head の Bone Proxy だけなら外れないことを確かめた（Modular Avatar が入っているときだけ回る）。
- テストで、コピーの Spine を別のオブジェクトの下へ移すと書き出しが止まり、メッセージに Spine が出ることを確かめた。書いた VRM で Spine のノードが Hips の子孫でないときも同じメッセージで止まることを確かめた。
- 無料のアバター 2 体に、ポーズの仕組み 3 種を 1 つずつ入れて書き出し、UniVRM で読み込んで比べた（結果は PR に書く）。

## 検討した代替案と不採用理由

- 仕組みの名前・GUID の一覧で外す: 配布元・版ごとに変わり、一覧を追い続けることになる。働きで見分ける。
- 付け替えのあとのボーンを元の親子に戻して書き出す: 付け替えは複製のボーンを挟む形で、どの複製を消してよいかは仕組みごとに違う。ポーズはアプリで付けるので、仕組みごと外せば足りる。
- ポーズのアニメーションを持つものも「確認が必要」にとどめる: 既定で外す指示に合わない。ポーズはアプリで付けるので、VRM の中で働かないものを残す理由がない。

## 残る制約

- 外した仕組みのポーズは、アプリのポーズとして取り込まれない（ポーズのライブラリの仕組みは対象外なので取り込まれる）。
- 胴や脚のアニメーションを持つが、ポーズのためでない仕組み（ダンス・移動の差し替えなど）も外れる。どれも VRM の中では働かない。
- World Fixed Object を使わずにボーンを付け替える仕組みは判定に掛からない。安全網が書き出しを止める。
- ポーズのアニメーションを、シリアライズされた参照でなく名前やパスで後から読み込む仕組みは判定に掛からない。
