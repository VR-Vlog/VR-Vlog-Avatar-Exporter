# MA・AAO の型を持たない NDMF プラグインのコンポーネントでも書き出し用のビルドを走らせる

- 日付: 2026-11-01
- 対象: `Editor/NdmfExportPreparation.cs`・`Tests/Editor/NdmfPreparationTests.cs`

## 背景

書き出しは、複製したアバターに NDMF の `AvatarProcessor` をかけるかどうかを `NeedsProcessing` で決めていた。判定は「MA の `AvatarTagComponent`・AAO の `AvatarTagComponent`・NDMF の `INDMFEditorOnly` のどれかを持つコンポーネントがあるか」だけだった。

NDMF でビルド時に動くツールの中には、どれにも当たらないものがある。

- TexTransTool: `TexTransMonoBase : MonoBehaviour, ITexTransToolTag`（デカール・アトラス化）
- lilycalInventory: 独自の `AvatarTagComponent : MonoBehaviour`（トグル・マテリアルの変更）
- LAC: Avatar Compressor: `TextureCompressor : MonoBehaviour, IEditorOnly`（テクスチャの圧縮・縮小）

これらは VRChat 向けのビルドでは NDMF のプラグインとして適用されるのに、MA のコンポーネントが無いアバターでは書き出しのビルドが始まらず、何も適用されないまま書き出されていた。検証用の Unity プロジェクトで次を確かめた（develop の書き出しと、VRChat SDK のビルド前コールバックをかけた複製との比較）。

- デカール: VRChat では出るが、書き出しでは消える。
- アトラス化: VRChat では 34 枠のマテリアルが 1 つの共通のマテリアルにまとまるが、書き出しでは元のマテリアルのまま。
- マテリアルの色の変更: VRChat では色が変わるが、書き出しでは元の色のまま。
- テクスチャの圧縮: VRChat では 128／256 px に縮むが、書き出しでは元の大きさのまま。

## 決定

- `NeedsProcessing` に「NDMF のプラグインを出しているパッケージのコンポーネントがあるか」を足す。プラグインを出しているかは、読み込まれたアセンブリの `[assembly: ExportsPlugin]` で調べ、そのアセンブリのパッケージ名を集める。コンポーネントのアセンブリのパッケージ名がこの中にあればビルドを始める。
- VRChat SDK が入っているときは、そのコンポーネントが `VRC.SDKBase.IEditorOnly` を持つことも条件にする。上の 3 つのツールは、VRChat SDK があると設定のコンポーネントに `IEditorOnly` を付け、アップロード時に取り除かせる。同じパッケージにある実行時用のコンポーネント（`IEditorOnly` を持たない）だけでは、ビルドを始めない。VRChat SDK が無いプロジェクトでは、パッケージだけで決める。
- ツールの型名を並べた一覧は持たない。対象を NDMF のプラグインの登録から引くので、同じ作りのツールが増えても Exporter を直さずに済む。
- Exporter 自身のパッケージは集める対象から外す。テスト用のプラグインがあるとき、Exporter の同梱 UniVRM のコンポーネントでビルドが始まらないようにするため。
- パッケージは `PackageInfo.FindForAssembly` で引き、アセンブリごとに結果を覚えておく。集めたパッケージ名も覚えておく。スクリプトの変更やパッケージの追加ではドメインが読み直されるので、古い結果は残らない。

## 選ばなかったもの

- NDMF があれば常にビルドをかける: VRChat のアップロードと最も近いが、ツールの無いアバターの書き出しの時間と中身が変わる。仕様の変更になるので、今回は採らない。
- ツールの型を 1 つずつ登録する: 誤検知は最も少ないが、ツールが増えるたびに Exporter を直すことになる。

## 対象にしないもの

- `Assets` の下に置かれた（パッケージでない）ツールと、コンポーネントとプラグインが別のパッケージに分かれているツール。NDMF はこれらのプラグインも動かすが、この判定では拾わない。VRChat 向けのツールは VPM のパッケージとして入り、コンポーネントとプラグインを同じパッケージに入れるのが普通なので、今回はここまでにする。MA のコンポーネントを一緒に使っていれば、今までどおりビルドが走る。

## 影響

- MA・AAO・NDMF の型を持つアバターの判定は変わらない。ツールの無いアバターも変わらない。
- 上のツールを使っていて MA が無いアバターは、書き出しのビルドが走るようになる。MA のあるアバターと同じく、入っているすべてのプラグインのパスと、ウェイトの無いメッシュの保護（`SkinnedMeshFallbackWeights`）がかかり、書き出しの時間も同じ程度に増える。
- これまでビルドを飛ばしていたアバターでも、NDMF が対応範囲より古いときと、プラグインがエラーを出したときはビルドが失敗するようになる。VRChat のアップロードも同じ条件で止まる。既定の設定（失敗した段階を省いて続ける、`ExportStageGuard.ContinueByDefault`）では、ビルドの処理を省いた書き出しに切り替えて結果一覧に出すので、これまでと同じ中身で書き出せる。この設定を切っているときは書き出しが止まる。
- かんたん転送も同じ `Prepare` を通るので、通常の書き出しと中身は変わらない。
