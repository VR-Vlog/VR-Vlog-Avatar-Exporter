# 区画式のトゥーンシェーダーのデカールを lilToon のメイン2nd・3rd に写し、写せないものはメイン画像に焼き込む

- 日付: 2026-11-01
- 対象: `Editor/UnsupportedShaderSubstitution.Decal.cs`（`ToonDecals`）・`Editor/UnsupportedShaderSubstitution.Toon.cs`・`Tests/Editor/SectionedToonSubstitutionTests.cs`・`Tests/Editor/SectionedToonProbe.shader`

## 背景

複数のアバターの書き出しの見え方を確かめたところ、1 体で黒いレギンスが消え、脚が素肌の色で書き出されていた。以前の版から出ていた。

## 原因

- 体のマテリアルは、セクションを切り替えて組み立てるトゥーンシェーダー（`IsSectionedToon` で判定する系統）を使っている。レギンスはメイン画像には無く、このシェーダーのデカール 0 にタイル表示（位置 0.5・0.5、スケール 1、回転 0、置き換え）で載っていた。
- 置き換え（`FromSectionedToon`）はデカール 0〜3 を lilToon に無いセクションとして捨て、結果一覧に名前を出すだけだった。

## 決定

- 有効なデカールを番号順に読み、描けないものは `Decal N` として結果一覧に出す。描けないのは、UV0 以外の UV・左右の手（ミラー）による表示の切り替え・左右の反転コピー（Symmetry の Flip。版によって式が違う）・視差（Depth）・回転速度・パン・色相・色調整・テーマ色・動画・色収差・面のマスク・グローバルマスク・アルファの上書き・未定義の合成モードのもの。アルファの上書き（Alpha Override）の項目を持たない古い版のデカールも、合成モードの番号の意味が違うので描かない。アルファの強さ（Alpha Intensity）だけを持たない版は、強さ 1 と同じ式なので 1 として描く（実際のアバターで、強さの有無で判定したらデカールが消えたため 2026-11-01 に判定を直した）。
- 最後の 2 つまでの連続したデカールのうち、lilToon のレイヤーで同じに描けるものはメイン2nd・メイン3rd に写す（VRChat の Toon の Detail をメイン2nd に写すのと同じ）。同じに描ける条件は次のとおり。
  - 合成モードが置き換え・乗算・スクリーン・加算（lilToon の通常・乗算・スクリーン・加算）。
  - 左右コピー（Symmetry の Copy）が無い。
  - タイル表示か、デカールの画像のタイリングとオフセットが既定。lilToon はタイリングとオフセットのあとで範囲外を切るが、元のシェーダーはその前で切るため。
  - アルファの強さ×アルファ（0〜1 に切り詰め）×色のアルファが 1 以下。lilToon は 1 つのアルファを掛けるだけで、元のシェーダーのように掛けたあとで 0〜1 に切り詰めないため。
  - マスクがある場合、マスクのタイリングとオフセットがメイン画像と同じで、メイン画像がスクロールしない。lilToon のレイヤーのマスクはメイン画像の UV で読むため。
- 位置・回転・スケール・横方向のオフセット（Side Offset）・画像の縦横比の合わせ方（Aspect Ratio。Shrink to Fit は短い辺を縮め、Grow to Fit は長い辺を伸ばす）は、lilToon のタイリング・オフセット・角度に直す。元のシェーダーは中心 c を回して `(R(θ)(uv - c) / size + 0.5) × st.xy + st.zw`、lilToon は `(R(θ)(uv - 0.5) + 0.5) × S + T` で画像を読むので、`S = st.xy / size`、`T = 0.5 st.xy + st.zw - 0.5 S - S × R(θ)(c - 0.5)` で同じ点を読む。
- それより前のデカールは、メイン画像×メインカラーに番号順に重ねてメイン画像に焼き込み、メインカラーを白にする（アルファは元のまま）。メイン2nd・3rd はその上に重なるので、重なる順番は元と同じ。焼き込みの計算は線形の値で行い、元のシェーダーの合成式（比較（暗）・比較（明）・減算・オーバーレイ・Mixed を含む）をそのまま使う。
- 焼き込めないとき（メイン画像のタイリング・オフセットが既定でない、メイン画像がスクロールする、メイン画像の色相などの調整やグラデーションがある、画像を読めない）は、そのデカールを `Decal N` として結果一覧に出す。lilToon はこれらの調整をメインカラーを掛ける前のメイン画像にかけるが、元のシェーダーはデカールを重ねたあとに調整しないため、焼き込むと調整がデカールにもかかってしまう。
- 発光の強さ（Emission Strength）が 0 より大きいデカールは、色は写したうえで `Decal N Emission` として結果一覧に出す。

## 成り立たない場合

- 新しい版のシェーダーは、デカールが不透明に重なった部分のメイン側の発光を弱める。lilToon のレイヤーではこれを再現しないので、発光するメイン画像の上にデカールがあると、その部分の発光が元より強く出る。
- 焼き込んだメイン画像は、元の画像の大きいほうに合わせて最大 2048 にする。デカールはミップマップを使わずに読むので、小さく貼った細かい画像は元より粗く見えることがある。
- 焼き込みはメッシュの UV の 0〜1 の範囲で行い、メイン画像と同じ繰り返し方で並べる。UV が 0〜1 の外にあるメッシュでは、タイル表示でないデカールが繰り返して見える。
- 合成の途中で色が 1 を超えると（加算・スクリーンのデカールで白より明るくなると）、元と同じにならない。焼き込んだメイン画像は 8 bit なので 1 で切られ、そのあとに重なる乗算などの結果が変わる。lilToon のスクリーンは `max(a + b - ab, a)` で、下地が 1 を超えると元の `a + b - ab` と違う値になる。元のシェーダーでも 1 を超えた色は画面では白に飛ぶので、見た目が変わるのは、あとの乗算で暗くする場合と、暗い照明の下だけになる。
- デカールを持たないマテリアルの書き出す内容は変わらない。
