# VRChat の代替表示が Cutout のシェーダーを Cutout の lilToon に置き換える

- 日付: 2026-11-01
- 対象: `Editor/UnsupportedShaderSubstitution.cs`（`GenericMode`）・`Tests/Editor/ShaderAlphaFamilyTests.cs`

## 背景

複数のアバターの書き出しの見え方を確かめたところ、1 体でセーターの裾と背中に白い面が出ていた。元のアバターでは見えていない面で、以前の版から出ていた。

## 原因

- 体と髪のマテリアルのシェーダーは、フラグメントシェーダーの中でメイン画像のアルファが 0.5 未満の画素を `clip` で捨てている。白い面は、メイン画像のアルファが 0 の部分に塗られていた色だった。
- このシェーダーには透過のモードを示すプロパティ（`_Mode`・`_Cutoff` など）も、名前の `Cutout` もなく、描画順も 2000 なので、lilToon への置き換え（`GenericMode`）は不透明と判定していた。アルファで捨てていた画素がそのまま描かれていた。
- シェーダー自身は `Tags { "VRCFallback"="ToonCutout" }` を持っている。VRChat はシェーダーを表示できない相手に、このタグに従って Toon の Cutout で描く。

## 決定

- `GenericMode` で、プロパティ・キーワード・シェーダー名から透過の手がかりが得られなかったとき、`VRCFallback` タグ（マテリアルの上書きタグとシェーダーのタグ）に `Cutout` を含むなら Cutout にする。しきい値は lilToon の既定の 0.5（VRChat の Toon Cutout と同じ）。
- 判定の順番は、プロパティ・キーワード・名前より後、描画順による推定より前にした。マテリアルが自分の値で透過のモードを示しているときは、その値を優先する。
- タグの `Transparent`・`Fade` は使わない。不透明なマテリアルを半透明として書き出すと後ろが透けて見えるので、Cutout の判定違いより見た目への害が大きい。Cutout の判定違いでも、アルファが 1 のメイン画像では何も捨てない。

## 成り立たない場合

- メイン画像のアルファにほかの情報（光沢など）を入れていて、タグだけが `Cutout` のシェーダーでは、穴が開く。VRChat の代替表示でも同じ穴が開くので、作者が受け入れている見え方とみなす。
- メイン画像以外のマスクで捨てるシェーダーは、メイン画像のアルファで捨てる。
- シェーダーの `Cull Off`（両面描画）は、プロパティで示されていなければ置き換え先に写していない。このアバターでは見え方に差は出なかった。
