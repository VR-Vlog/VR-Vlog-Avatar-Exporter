# VRChat の代替表示が Cutout で、自分のコードで捨てているシェーダーを Cutout の lilToon に置き換える

- 日付: 2026-11-01
- 対象: `Editor/UnsupportedShaderSubstitution.cs`（`GenericMode`・`FallbackClips`）・`Tests/Editor/ShaderAlphaFamilyTests.cs`

## 背景

複数のアバターの書き出しの見え方を確かめたところ、1 体でセーターの裾と背中に白い面が出ていた。元のアバターでは見えていない面で、以前の版から出ていた。

## 原因

- 体と髪のマテリアルのシェーダーは、フラグメントシェーダーの中でメイン画像のアルファが 0.5 未満の画素を `clip` で捨てている。白い面は、メイン画像のアルファが 0 の部分に塗られていた色だった。
- このシェーダーには透過のモードを示すプロパティ（`_Mode`・`_Cutoff` など）も、名前の `Cutout` もなく、描画順も 2000 なので、lilToon への置き換え（`GenericMode`）は不透明と判定していた。アルファで捨てていた画素がそのまま描かれていた。
- シェーダー自身は `Tags { "VRCFallback"="ToonCutout" }` を持っている。VRChat はシェーダーを表示できない相手に、このタグに従って Toon の Cutout で描く。

## 決定

- `GenericMode` で、プロパティ・キーワード・シェーダー名から透過の手がかりが得られず、描画順でも半透明と判定されなかったとき、次の 2 つがそろえば Cutout にする。しきい値は lilToon の既定の 0.5（VRChat の Toon Cutout と同じ）。
  - `VRCFallback` タグ（マテリアルの上書きタグか、使われる SubShader のタグ）が VRChat の書式の Cutout（`Cutout`・`ToonCutout`・`ToonCutoutDoubleSided` など）である。
  - シェーダーのファイルの最初の SubShader で、色を描くパス（影・深度だけのパスを除く。サーフェスシェーダーは SubShader 全体）のコード（コメントを除く）に `clip(`・`discard`・`AlphaToMask` がある。
- タグだけでは決めない。代替表示の指定は、元のシェーダーが何かを捨てていることの証拠にならないため、シェーダー自身のコードで捨てていることも確かめる。ファイルの無いシェーダー（組み込み・見つからないもの）はタグがあっても従来どおり。
- 判定の順番は、描画順が 2500 より後ろで色を混ぜる場合の半透明の判定より後にした。半透明のシェーダーにも代替表示を Cutout にしているものがあり、タグで不透明の切り抜きに変えると半透明の部分が消えるため。
- タグの `Transparent`・`Fade` は使わない。不透明なマテリアルを半透明として書き出すと後ろが透けて見えるので、Cutout の判定違いより見た目への害が大きい。
- `GetTag` は別の SubShader や `Fallback` のシェーダーまでは探さない。描画に使われる SubShader のタグだけを見る。

## 成り立たない場合

- メイン画像以外（別のマスク・頂点カラー・計算した値）で捨てるシェーダーや、しきい値が 0.5 でないシェーダーでは、メイン画像のアルファを 0.5 で捨てる。捨てる場所がずれるが、何も捨てない従来の書き出しより元に近い。
- `#ifdef` やキーワードで切り替える `clip` も、切り替えの状態を見ずに捨てているとみなす。タグが Cutout で、そのキーワードがオフのマテリアルのメイン画像のアルファに 0.5 未満の部分があると、元に無い穴が開く。この組み合わせは今回確かめたアバターには無かった。
- シェーダーの `Cull Off`（両面描画）は、プロパティで示されていなければ置き換え先に写していない。このアバターでは見え方に差は出なかった。
