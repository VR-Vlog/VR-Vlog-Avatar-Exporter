# 大規模リファクタリングの進め方（第 1 段: 監査・回帰の土台・計画）

- 日付: 2026-11-02
- 対象: `Editor/`・`Runtime/`・`Formats/` の本体 200 ファイル、`Tests/` の 203 ファイル、`Tools/`（Vendor の UniVRM は対象外）

## 背景

Exporter は 1 年で機能が増え、同じことをする処理と画面が複数の場所にできた。例を挙げる。

- 書き出しの結果一覧が、転送の完了画面と別ウィンドウの 2 か所にある。
- Editor と LanTransfer の 2 つのアセンブリが、互いを `Type.GetType` と 27 個のデリゲートで名前で呼び合っている。
- 表情の束縛（Renderer とシェイプ名の組）をビルドの前後で付け替える処理が、瞬き・視線・統合表情のそれぞれに別の形で書かれている。
- 入口の無いウィンドウ（アプリの見え方のプレビュー、開発用の転送ウィンドウ）と、テストからしか呼ばれない保存・読み込みの経路が残っている。
- 幅が狭いときに文字を縮めて 1 行に収めるような、見た目の特例が点在する。

本体は 54,364 行、テストは 70,179 行ある（2026-11-02 の `develop`、空行とコメントを含む物理行）。行数を大きく減らし、重複を 1 か所にまとめる。ただし書き出す VRM の中身、画面の見た目、対応する Unity・lilToon・NDMF・Modular Avatar・AAO の組み合わせは、1 つも悪くしない。

## 決定

### 進め方

- 第 1 段（この記録）は、監査・回帰の土台・計画の 3 つだけを行い、本体のコードは変えない。第 2 段で計画の単位ごとに別々の作業者が実装する。
- 統合ブランチ `refactor/big-20261102` を `develop` から切り、すべての変更はここへ PR を出す。`develop` へ戻すのは、全単位がそろい、回帰比較の全件が基準と同じになってからにする。
- 単位は 8〜10 個に分け、並列に進める単位どうしでファイルを共有しない。依存する単位のファイルは、依存先がマージされてから触る。
- 各 PR の本文に、本体とテストの before/after の行数、なぜ良くなるか、消した特例、敵対的セルフレビューの結果（3 行以内）、回帰比較と 3 つのテストプロファイルの結果を書く。

### 回帰の土台

- 書き出しの基準: 手元にあるすべてのアバターと設定の組（464 組）を `develop` の Exporter で 2 回ずつ書き出し、VRM のファイル一覧・ハッシュ・メッシュ／マテリアル／テクスチャ／ブレンドシェイプ／表情の要約・警告・体と顔と各表情のスクリーンショットを保存する（この記録の時点で 2 レーンで実行中。全件がそろってから full の比較に使う）。実行役は `Tools/ExportRegressionRunner.cs`（Unity のバッチモードで表情ボードを開き、通常の書き出しと同じ経路で保存する）。
- 比べ方: リファクタ後のブランチで同じ組を書き出し、`Tools/compare-exports.py` で基準と比べる。PR の前は代表の組（quick）、マージの前は全件（full）。差が 1 件でも出たら PR 本文に理由を書き、意図した差かどうかは作業者が決めずに判断を仰ぐ。
- テストの基準: EditMode テストを `compatibility`・`exporter-behavior`・`exporter-integration` の 3 プロファイルで回し、結果を保存した。`compatibility` は 36 件のうち 34 件が緑で、`DependencyRoundTripTests` の 2 件は使われていないモーフを削る処理を足したときから赤のままになっている。`exporter-behavior` は 1,577 件のうち 1,563 件が緑、`exporter-integration` は 1,622 件のうち 1,601 件が緑（6 件はスキップ）で、赤の 14 件と 15 件（上の 2 件を含み、多くは両方に出る同じテスト）はリファクタの前からの赤として記録し、テスト整理の単位で原因を調べて直すか消す。
- 行数は本体・テスト・ツールを分けて同じスクリプトで数え、単位ごとに before/after を出す。

### 単位の切り方

- テストの整理（削除するテストは 1 件ずつ、残るテストか回帰比較のどちらが同じ挙動を守るかを書く。守るものが無ければ小さなテストを先に足す）。
- 転送の境界（LanTransfer から Editor への一方向の参照にし、名前で呼び合う仕組みとデリゲートを消す。開発用の転送ウィンドウと検証メニューの削除は、利用者への影響があるので判断を仰ぐ）。
- 転送の画面（結果一覧を完了画面の 1 か所に。IMGUI で残っている利用条件とアップロードの進みを UI Toolkit に。QR の警告は文字サイズを固定して 2 行まで折り返す）。
- 表情ボードと周辺のウィンドウ（保存の経路を 1 つの型に。入口の無いプレビューの削除とステップ表示の扱いは判断を仰ぐ）。
- VRM の表情の書き込み（瞬き・視線・統合表情を、コピーの `VRM10Object` の `VRM10Expression` として 1 か所で書く。束縛の付け替えは 1 つの型で持つ）。
- 表情のセッションと契約型（テストからしか呼ばれない経路を消し、契約型の読み書きの補助を 1 つにまとめる）。
- 書き出しの流れ（UniVRM への受け渡しと NDMF の準備、段の表、復旧、診断、VRChat / MA / AAO のコンポーネントの変換。段ごとの表示名と区分を 1 つの表にし、JSON の取り出しと型判定の写しを 1 か所に寄せ、テスト専用の経路を本番と同じ経路に揃える）。
- lilToon のマテリアルとテクスチャの変換（未対応シェーダーの置き換えの標本化を 1 か所に。一覧の写しは生成スクリプトで共有する。1.x 用の読み取り一式の削除は判断を仰ぐ）。
- VRChat の表情の読み取り（FX レイヤーの走査・条件の評価・曲線の判定をそれぞれ 1 つの型にし、項目ごとに作り直していた解析を 1 回にする）。
- 無表情の形の決め方（メニューの読み取りを 1 か所に、パスとレンダラーの対応付けを 1 つの型に。前の単位の型を使う側なので、そのマージ後に行う）。

### 変えないもの

- `ExporterWindowHeader`・`ExporterLocalization.T`・メニューの定数・`ExportSettingsStore` の公開メンバーは、どの画面の単位からも使われるので今回は変えない。
- 法的な文言（利用条件・同意の確認・ライセンス表記）は変えない。
- 画面の文言を直すときは、意味を担う語（必須・任意・単位・状態・注意）を落とさない。

## 選ばなかったもの

- Feature Flag を作って新旧を切り替える: Exporter は Unity のエディター拡張で、公開の出し分けに使う仕組みを持たない。リファクタリングは既定の挙動を変えないので、切り替えは要らない。
- 本体を半分にすることを先に決めて削る: 重複と特例を消して減る量は監査で測った分だけで、無理に減らすと出力や見た目が変わる。目標は測った数字で持ち、出力を変えてまで減らさない。
- 単位ごとにテストファイルを分割する: テストの多くが複数の単位の型を参照している。ファイルを分けると `Tools/run-*-tests.ps1` の固定一覧と合わなくなるので、持ち主を 1 単位に決め、他の単位は名前の追従など最小限の変更だけにする。
- 自動の整形やリネームだけの PR: 行数は減らず、差分で中身の変更が見えなくなる。
- スカッシュマージ: 単位の中の変更の経緯を統合ブランチに残す。

## 確かめたこと

- 監査: 本体と テストの全ファイルを読み、重複・責務の混在・入口の無いコード・特例のパッチを所見として一覧にした。所見の反証（参照の有無（リフレクションの文字列・メニュー属性・asmdef・ツールの固定一覧を含む）・消える行数・出力への影響の再確認）は第 1 段では終わらなかった。各単位の作業者が着手前に自分の所見を確かめ、違っていた所見は PR 本文に書いて落とす。
- 回帰の土台: 464 組の書き出しを 2 レーンで実行中で、同じ組を 2 回書き出して run の間の揺れも記録する。終わった組について比較のスクリプトを同じコードに対して走らせ、差が 0 になることを確かめてから、各単位の PR の判定に使う。
- テスト: 3 プロファイルの結果を保存し、リファクタ前から赤のテスト（`exporter-behavior` 14 件・`exporter-integration` 15 件、重なりを含む）を記録した。Unity を使わないスクリプトのテスト（`Tools/test-*.py`・`Tools/validate.py`）はすべて緑。
