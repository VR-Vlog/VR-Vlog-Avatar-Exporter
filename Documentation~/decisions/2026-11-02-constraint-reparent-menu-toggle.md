# メニューで隠れるオブジェクトの中の小物をソースの子に移すとき、同じ切り替えで隠す

- 日付: 2026-11-02
- 対象: `Editor/ConstraintExport.cs`・`Editor/ObjectToggleCapture.cs`・`Editor/UniVrmOneClickExporter.cs`・`Editor/Locales/ExporterLocale_*.json`・`Tests/Editor/ObjectToggleCaptureTests.cs`
- Issue: #596

## 背景

[2026-10-23 の決定](2026-10-23-parent-constraint-reparent.md)で、Parent Constraint で追従する小物をソースの子に移して書き出すようにした。この記録の「欠点」には、メニューでオンにする非表示の小物は今の姿勢のまま書き出すと書いたが、実際はそうならない。

書き出しでは、Parent Constraint を変換する前に表示の切り替え（`VRVLOG_object_toggles`）の取り込みが走り、既定でオフの切り替え対象をオンにしてから書き出す。アプリは切り替え対象のノードだけを隠して既定の状態を作る。そのため、既定でオフの切り替え対象の中にある Parent Constraint の小物は、オンにされたあとでソースの子に移され、切り替え対象の外に出る。アプリでは切り替え対象を隠しても、移した小物は隠れずに見えたままになる。

## 決定

- コンストレイントの変換に、表示の切り替えの取り込み結果を渡す。
- 小物をソースの子に移すと、ちょうど1つの切り替え対象の外に出る場合は、移したうえで、その小物を同じ切り替えの対象に足す。各値でのオン・オフは、出てきた切り替え対象と同じにする。
- 次の場合は移さず、今の姿勢のまま書き出して、結果の一覧に「ソースの子に移すとメニューの表示切り替えが元と変わるため…」と理由を出す。
  - 2つ以上の切り替え対象の外に出る（入れ子の切り替えは1つの状態で表せない）
  - 外に出る小物が、それ自身も切り替え対象である（2つの切り替えの対象になる）
  - ソースが、小物の入っていない切り替え対象の中にある（移すと、元は関係のない切り替えで隠れるようになる）
- 切り替えの対象に足すのは、コンストレイントの変換がすべて済んでからにする。途中で失敗したときは移した小物を戻すだけでよく、切り替えのデータは触らない。

## 確認

- `ObjectToggleCaptureTests.APropMovedOutOfAToggleStillHidesWithIt` で、既定でオフの切り替え対象の中の小物がソースの子に移り、書き出す切り替えのデータでその切り替えの対象に入って各値で同じ状態になること、ソースが別の切り替え対象の中にある小物は移らず理由が出ることを確かめる。実際の VRChat SDK が無い環境ではスキップする。

## 欠点

- 切り替え対象が既定でオンでも、同じように小物を切り替えの対象に足す。アプリでの見え方は元と同じになるが、切り替えの対象の数は元より増える。
- 移した小物は、切り替え対象の中にあったときと違い、切り替え対象の拡大縮小や位置のアニメーションには追従しない（ソースに追従する）。Parent Constraint の動きはもともとソースに従うので、元の見た目と同じになる。
