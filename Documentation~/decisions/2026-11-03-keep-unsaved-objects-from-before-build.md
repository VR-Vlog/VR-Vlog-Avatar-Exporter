# ビルドの前からある未保存のオブジェクトを、書き出しの片付けで消さない

- 日付: 2026-11-03
- 対象: `Editor/NdmfExportPreparation.cs`・`Tests/Editor/NdmfPreparationTests.cs`・`Tests/Editor/NdmfSharedObjectTests.cs`・`Tests/NdmfPlugin/SharedObjectTestPlugin.cs`・`Tools/run-unity-compatibility.py`・`Tools/NdmfPreparationTestShim.cs`

## 背景

1.5.2 で、自分が作っていないマテリアルが消えるエラーを直した。同じ種類の不具合が他に無いか調べたところ、書き出しの片付け（`NdmfExportPreparation.Dispose`）にも同じ形があった。

片付けが消すものは 2 通りある。

- `CaptureGenerated` が「コピーから参照されている未保存のオブジェクトのうち、元のアバターとコピーに無かったもの」を、ビルドが作ったものとして `DestroyImmediate` する。
- NDMF は `BuildContext.Serialize` で、コピーから参照されている未保存のオブジェクトを `DontSave` や `HideAndDontSave` のものまで一時フォルダーに保存する。片付けでこのフォルダーを消すと、保存されたものも消える。

どちらも、ビルドのツールが自分で持ち続けているオブジェクト（static に置いたマテリアル・テクスチャ・メッシュなど）をアバターに割り当てると、ツールのものを消してしまう。テスト用のプラグインで測ると、フラグなし・`DontSave`・`HideAndDontSave` のマテリアルとテクスチャ、`DontSave` のメッシュがすべて、1 回目の書き出しの片付けのあとで消えていた。

元のアバターのシーンに埋め込まれた未保存のマテリアル・テクスチャ・メッシュは、`IsolateSharedAssets` がコピーを分けてあるので消えない。こちらも測って確かめた。問題になるのはツールが持っているものだけである。

このプロジェクトに入っている Modular Avatar と NDMF にはこの形の static の持ち方が無く、他のツールが実際にそうしているかは分からない。ツールが持つオブジェクトを消してしまうと、シーンを開いたときと同じ `MissingReferenceException` がツールや Unity の画面の側から出るので、起きうる形として直す。

## 決定

- ビルドの前（`ProcessClone` の最初と、NDMF を通らないときの `ApplyVrcFury` の最初）に、読み込まれている未保存のオブジェクトを `Resources.FindObjectsOfTypeAll` で控える。GameObject と Component は片付けの対象でないので除く。
- `CaptureGenerated` はこの控えにあるものを生成物に入れない。これまで引数で渡していた「元のアバターとコピーの参照先」は控えに含まれるので、引数をなくした。
- 片付けで一時フォルダーを消す前に、控えにあるオブジェクトのうち一時フォルダーに保存されたものを `AssetDatabase.RemoveObjectFromAsset` で取り出す。メインアセットになっているものも取り出せること、`hideFlags` とマテリアルからテクスチャへの参照が残ることを測って確かめた。
- `IsolateSharedAssets` の分離コピーは控えのあとで作るので、これまでどおり片付けで消える。ビルド中にできたものも同じである。

## 採らなかった案

- フラグで見分ける: `DontSave` の有無では持ち主が分からず、`DontSave` のものも一時フォルダーに保存されて消える。
- ビルドのあとで参照をコピーに差し替える: 差し替え先をコンポーネントとアセットの全体で追うことになり、取り出すより複雑になる。

## できないこと

ツールがビルドの最中に作って持ち続けるものは、ビルドが作った他のものと見分けられないので、これまでどおり片付けで消える。NDMF の通常のビルドでも一時アセットの置き場は次のビルドで消される（読んだ範囲での推測で、測っていない）ので、ツールの側で `== null` を見て作り直す前提でよいと判断した。

ツールがビルドの前から持っているマテリアルを、ビルド中に作ったテクスチャ（アトラスなど）を指すように書き換えると、マテリアルは残るがテクスチャは片付けで消える。マテリアルからの参照は切れた状態になる。

同時に複数の書き出しが走ると、片方の控えにもう片方の生成物が入って、片付けで消えずに残ることがある（読んだ範囲での推測で、測っていない）。残るだけで、消えてはいけないものを消すことはない。

取り出しに失敗したものは警告を出して、一時フォルダーと一緒に消える。フォルダーの削除を止めず、書き出しが失敗した元の例外も隠さないためである。

NDMF が `DontSave` のオブジェクトを保存するときに Unity が内部の Assert を出す。これは NDMF 側のログなので、この変更では触らない。

## 確かめたこと

- `NdmfSharedObjectTests` を実物の NDMF と Modular Avatar で回した。取り出しの呼び出しを外すと、1 回目の書き出しのあとでコピーのマテリアルが消えて落ちる。入れると 2 回続けて書き出しても全部残り、一時フォルダーも残らない。
- `NdmfPreparationTests` に、ビルドの前からあるものは残り、ビルド中に作ったものは消えることを、NDMF の経路と NDMF を通らない経路の 2 本で足した。CI で必ず回るよう、`NdmfSharedObjectTests` は `INTEGRATION_CASES` に、この 2 本は `BEHAVIOR_CASES` に載せ、Unity を使わない検査（`Tools/run-ndmf-preparation-tests.ps1`）のシムにも必要な API を足した。
- 実物のアバターを修正前（1.5.2）と修正後で 2 回ずつ書き出した。glTF の bin は完全に一致し、JSON の違いは毎回ランダムに付く画像名の GUID 1 か所だけだった。控えを取る時間は、読み込み済み 6262 個で 6 ms だった。
