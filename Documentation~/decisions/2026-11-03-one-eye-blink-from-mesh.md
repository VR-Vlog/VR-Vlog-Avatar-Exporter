# 片目ずつの瞬きを顔のメッシュから決め、瞬きを左右の和にする

- 日付: 2026-11-03
- 対象: `Editor/EyeClosureSides.cs`・`Editor/BlinkExportSession.cs`・`Editor/BlinkShapeNames.cs`・`Tests/Editor/OneEyeBlinkInferenceTests.cs`・`Tools/collect-eye-closure-corpus.py`・`Tools/summarize-eye-closure-corpus.py`

## 背景

瞬きの左右（VRMの `blinkLeft`・`blinkRight`）は、`Blink_L` / `Blink_R` のような決まった名前か、両目の瞬きの名前に左右の印を付けた形（`まばたき_L` など）のときしか決まらなかった。手元の検証用アバター80件を集計すると、両目の瞬きが分かるのは42件で、左右まで決まるのはそのうち9件だった。残りの33件にも片目を閉じる変形はあるが、`eye_close_left`・`ウィンク２右`・`ウィンク` のように両目の瞬きと名前の形が違う。片方だけに印があり、もう片方は印の無い名前のこともある。

## 決定

- 両目の瞬きが決まり、名前の規則では左右が決まらないとき、同じメッシュの変形から左右を探す。名前は見ない。
  - 左右はヒューマノイドの左目と右目のボーン（無ければ左右の上腕）の位置から決める。ヒューマノイドが無いアバターでは探さない。
  - 候補は、動く量の90%以上がアバターの左か右の片側にあり、90%以上が両目の瞬きで動く頂点の中にある変形。
  - 左の候補と右の候補を足したものと両目の瞬きとの差の二乗和が、両目の瞬きの二乗和の5%以下の組を選ぶ。差がいちばん小さい組を使う。
  - 名前に左右の印があり、メッシュで測った側と逆のものは使わない。
  - 差がほぼ同じ組（同じ変形が2つの名前で入っているもの）は、印を除くと同じ名前になる組（`ウィンク` / `ウィンク右` も含む）を優先し、それでも同じなら先にある変形を使う。
  - 両目の瞬きが複数のメッシュにあるときは、すべてのメッシュで左右が見つかったときだけ使う。
- 自動のときに左右が分かったら、瞬きは左右の2つの変形を100%ずつ動かす形で書き出す（2026-11-03 mk）。名前の決まった組・Unified Expressions・VRChatの設定から決まった左右も同じにする。ただし、左右の和と両目の変形との差の二乗和が両目の変形の二乗和の5%を超えるときは、両目の変形のまま書き出す。左右が無いメッシュの両目の変形はそのまま残す。左右が分からないアバターの瞬きは今までどおり。手動の設定は変えない。
- ビルドの前処理で探した左右の変形が消えたときは、元の両目の変形に戻して瞬きを残す。

## 決め方の根拠

- `Tools/collect-eye-closure-corpus.py` で手元のアバターのFBXとアニメーションを読み、`Tools/summarize-eye-closure-corpus.py` で集計した（アバターの名前は出さず、IDだけを出す）。
- 両目の瞬きがある42件すべてで、片側だけを動かす変形2つの和が両目の瞬きと完全に一致した（差は0）。名前の左右の印がメッシュで測った側と逆のものは0件だった。しきい値の5%と90%は、この一致から大きく離れた値にしてある。
- ウィンクの名前のアニメーションは58件あったが、左右の変形を90%以上動かすものは0件で、多くは笑った目の片目閉じだった。メニュー・ジェスチャーの名前から左右を読むと、この笑った目を拾うことになる。このため名前・クリップ・ジェスチャーから左右を決めることはしない。
- 特定のアバターや変形の名前を判定に書かない。テストの名前は手元のアバターで見た印の付け方（`_L` / `_R`・`left` / `right`・`左` / `右`・片方だけ印のある形）を写したもの。

## 確かめたこと

- `Tests/Editor/OneEyeBlinkInferenceTests.cs` で、いろいろな左右の印・印の無い名前・名前と逆の側・笑った目のウィンク・半分だけ閉じる変形・両目を閉じる変形・ヒューマノイドの無いアバター・向きを変えたアバターと、瞬きが左右の和になることを確かめる。
- 既存の `BlinkNameFallbackTests` の、左右が決まるケースの瞬きの期待を左右の和に直した。`BlinkExportTests`・`ExpressionPresetTests` の仮のメッシュはどの変形も同じ頂点を同じだけ動かすので、左右の和が両目の変形の2倍になり、瞬きは今までどおり両目の変形になる（期待は変えていない）。
- 手元の24件を書き出して、変更前と変更後の `blink`・`blinkLeft`・`blinkRight` の変形を比べた。

## 左右の和にしない場合を足した理由

決まった名前の左右（`Blink_L` / `Blink_R` など）を持つアバターのうち4件では、左右の変形が目のほかに口元の頂点を最大2cmほど動かしていた。左右の和で瞬きを書き出すと、瞬きのたびに口元の線が太くなった。両目の変形は口元を動かさないので、左右の和が両目の変形を作り直せるときだけ左右の和にする。しきい値は左右を探すときと同じ5%で、この4件の差は6.6%、ほかの左右が分かるアバターは0だった。
