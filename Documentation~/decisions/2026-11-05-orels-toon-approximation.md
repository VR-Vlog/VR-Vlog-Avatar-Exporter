# orels Toon の値を公式 lilToon の同じ役割の項目へ写す

- 日付: 2026-11-05
- 対象: `Editor/ShaderApprox/OrelsToonApproximation.cs`・`Editor/ShaderApprox/ShaderApproximations.cs`・`Tests/Editor/ShaderApprox/OrelsToon*`・`README.md`・`README.en.md`・`CHANGELOG.md`

## 背景

orels Toon には最初の版（シェーダー名 `orels1/Toon/...`）と v2（`orels1/Toon/v2/...`）があり、どちらも描画モードをシェーダー名（Main・Cutout・Transparent）で分け、陰影をランプ画像で、主画像の色を HSV の足し算で変える。汎用の読み方は主画像と主色、カットオフ、法線マップ、発光の画像と色、`_CullMode` を拾うが、ランプ・色相の調整・輪郭線・リム・マットキャップ・反射は落ちていた。

## 決定

2026-11-05 のシェーダーごとの近似（`IShaderApproximation`）に 1 クラス足し、最初の版と v2 を同じクラスで読む。値はシェーダー本体（生成元の `.orlsource`）が使う意味で読む。共通部分は変えず、登録の 1 行だけ足した。

- 見分け方: シェーダー名が `orels1/Toon/` で始まるもの。シェーダーが見つからないマテリアルは、主の部分にしかない `_BackfaceAlbedoTint` と `_TintByVertexColor` が両方あるもの。v2 かどうかは名前の `orels1/Toon/v2/` で、名前が無いときは v2 の発光にしかない `_EmissionPower` の有無で決める。
- 描画モード: 名前に Transparent を含むものは半透明、Cutout を含むものはカットアウト、それ以外は不透明。
- 主画像の色: orels Toon は主画像 × `_Color` を HSV にし、色相に `_Hue` を足して 1 で回し、彩度と明度に `_Saturation`・`_Value` を足して 0〜1 に収める。公式 lilToon の `_MainTexHSVG` は彩度と明度を掛けるので式が違う。主画像と主色を掛けた色に orels Toon の式を当てて主画像に焼き、主色を白にする。主画像が無いときは主色に当てる。
- アルファ: 半透明とカットアウトでは `saturate(alpha × _AlphaScale)` を焼く。`SEPARATE_ALPHA` のときは `_AlphaTex` の赤（v2 で負の倍率なら `1 − 赤 × −倍率`、最初の版は負なら 0）を公式 lilToon のアルファマスクの置き換えのモードで同じ式にする。
- 陰影: 明るさは `ramp(N·L × 0.5 + 0.5)` の下の行で決まる。ランプを 129 点読み、明るさが半分になる位置を影の境界、10% と 90% の幅をぼかし、暗い端の色を影の色にする（SCSS の Lightramp と同じ当て方）。ランプが白一色なら影なしにする。既定のランプ（`grayscaleRamp`）はマテリアルに保存されないので、黒から白への直線のグラデーションとして読む。これは推測で、実物を描いた差が 2.7 に収まったことで確かめた。
- 輪郭線: `OUTLINE_ENABLED` のとき、幅（cm）、色、`_OutlineTex`、幅のマスクを写す。`_OutlineLightingMode` が Emissive なら照らさない。`_OutlineAlbedoTint` が半分以上で輪郭線の画像が無いときは主画像と主色を輪郭線の色に使う。
- 発光: 汎用の読み方を上書きする。最初の版は `_EMISSION`（画像を入れたときだけ付く）があるとき、画像を 2 回掛けた値を焼く。v2 は高さ 16 ピクセルを超える画像があるとき、選んだチャンネルと `_EmissionPower` の累乗を焼く。発光の色相・彩度・明度（最初の版は主の値、v2 は `_EmissionHue` など）は色の向きに当てて焼き、一番大きい値を発光の色にする。`_EmissionTintToDiffuse` は公式 lilToon の `_EmissionMainStrength` に写す。
- リム: `RIMLIGHT_ON` のとき、境界を `_RimRange`（v2 は `1 − _RimSpread`）、ぼかしを `_RimSharpness` の 2 倍（v2 は `1 − _RimSharpness` の 2 倍）、色を `_RimTint × アルファ × _RimIntensity` にして加算する。`_RimThreshold` が 0 より大きいと光の当たる側だけに出るので、公式 lilToon の影でのマスクを付ける。
- マットキャップ: v2 の 1 枚目と 2 枚目を公式 lilToon の 2 枚へ。加算は照らして加算、乗算は照らさずに乗算にし、共有マスクの選んだチャンネルを `lerp(1, mask, 強さ)` で焼く。減算と 3・4 枚目は表示する。最初の版の反射のモード Matcap は公式 lilToon のマットキャップにし、加算なら照らし、乗算なら照らさない。
- 反射: 最初の版の PBR と Baked Cubemap、v2 の `REFLECTIONS_ON` のとき、メタリックと滑らかさを写す。8 ピクセルより大きい `_MetallicGlossMap` は赤をメタリック、アルファを滑らかさ（粗さのモードなら反転）としてそれぞれの範囲に写して焼く。非金属の反射率はどちらの版も `0.16 × _ReflectivityLevel²`。
- 裏面: 両面のとき、`_BackfaceAlbedoTint` が 0 なら `_BackfaceColor` を公式 lilToon の裏面の色にする。主画像に掛ける場合は写す先が無いので表示する。
- 法線: orels Toon は法線マップを主画像の UV × `_BumpMapTiling`（Independent なら最初の UV × タイリング）で読むので、そのタイリングに直す。
- リムの影、スペキュラー、オクルージョン、ディテールの法線、デカール、AudioLink、LTCGI、UV の切り抜き、頂点カラーでの色付け、発光の UV のタイルでのマスクと光での強さの変化などは書き出さず、保存前に表示する。

## 残した差

- 発光の色相・彩度・明度を 0 以外にし、`_EmissionTintToDiffuse` も 0 より大きいとき、orels Toon は主画像を掛けた後の色に調整を当てるが、ここでは発光の画像に当ててから公式 lilToon が主色を掛けるので、色が少し変わる。調整が 0 なら変換は恒等で差は出ない。
- ランプの明るい側が白でないとき、その色は写さない（SCSS の Lightramp と同じ）。
- 既定のランプは直線として読んだが、内蔵の画像の色空間は確かめていない。リニアのプロジェクトでは境界が明るい側へずれている可能性がある（推測）。
- `_OutlineAlbedoTint` は半分を境に、主画像を使うかどうかの 2 値で写す。
- 最初の版の反射は反射率を混ぜる比にもう一度掛けるが、ここでは掛けない。

## 確認したこと

- EditMode テスト 31 件で、名前ごとの描画モード 6 種、色相の焼き込み（主画像あり・なし）、アルファの倍率、別のアルファ画像、ランプ（2 色・既定・白）、輪郭線、発光（最初の版・v2・色相）、リム（両方の版）、マットキャップ、反射のマットキャップ、メタリックと滑らかさ（値と画像）、裏面の色、法線のタイリング、表示する効果、シェーダーが見つからない場合、同じ名前のプロパティを持つ別のシェーダーに当たらないことを確かめた。
- Standard・lilToon・VRChat SDK のシェーダー・他のトゥーンシェーダーのテストは変えずに通る。
- 実際の orels Toon（7.3.1）を入れたプロジェクトで 10 通りを書き出し、VRM のマテリアルを読んだ。カットアウトは `MASK`、半透明は `BLEND`、両面は `doubleSided`、発光ありは発光の画像を持つ。球に描いた元のシェーダーとアプリでの表示の差（0〜255 の平均）は、両面の裏側（13.8）と反射（6.9）を除いて 2.7 以下で、これまでの 2.2〜43.1 から下がった（カットアウトと半透明はこれまでも 2.6 以下）。比較画像はリポジトリには入れていない。

## 検討した代替案と不採用理由

- 色相の調整を公式 lilToon の `_MainTexHSVG` に写す: 彩度と明度を足す orels Toon の式と、掛ける lilToon の式が違うため、焼き込みにした。画像を読めないとき（グラフィックスデバイスが無いとき）だけ色相を写し、彩度と明度は表示する。
- 最初の版と v2 を別のクラスにする: 主・輪郭線・陰影の部分は同じで、違うのは発光・リムの名前・マットキャップ・反射だけなので、1 クラスで分岐にした。
