# 自分のアニメーターで表示に切り替わる VRChat 用のギミックも丸ごと外す

- 日付: 2026-11-07
- 対象: `Editor/ExportGimmickDetection.cs`・`Tests/Editor/ExportGimmickTests.cs`

## 背景

外部の影のシステム（Modular Avatar のメニューとアニメーターの組み込みを持ち、カメラ・ライト・コンストレイントと、画面を暗くする大きな箱のメッシュでできたもの）を入れたアバターを書き出すと、書き出しは成功するが VRM が壊れるという報告があった。3 体のアバターに同じシステムの 2 つの版を入れて書き出すと、次のことが起きた。

- 箱のメッシュが lilToon で近似されて VRM に入り、全身を正面から撮ると灰色一色になる。
- システムのアニメーターが Modular Avatar で FX に統合され、遷移に BlendShape 以外の変化（カメラの有効・無効）が入るため、FX の初期状態を固定できない。アバター本来の既定の見た目（髪の長さ・胸の形・目の形）が焼き込まれない。

2026-10-21 の決定（`2026-10-21-structural-gimmick-strip.md`）で、VRChat の中でだけ動く部品を持つ Modular Avatar のギミックは丸ごと外すようにした。ただし候補にするのは、元のアバターで表示中の階層と、表示中のメッシュを持つものだけだった。このシステムはギミックのルートが非表示で、システム自身のアニメーターがルートを表示に切り替える作りなので、候補から漏れていた。表示切り替えの取り込みがメッシュを表示にして書き出し、統合された FX が初期状態の固定を止めていた。

## 決定

元のアバターで非表示（ギミックのルートか、メッシュの Renderer が無効）でも、ギミックのルートに付いた Modular Avatar のアニメーターの組み込みがそれを 1 つのクリップでオンにでき、ギミックの中にカメラがあれば、表示中のギミックと同じ判定にかけて外す。オンにできるとは、そのクリップに、ギミックの中のオブジェクトの `m_IsActive` かメッシュの Renderer の `m_Enabled` を 1 にするキーがあることを指す。クリップのパスは Modular Avatar の `AvatarObjectReference` と同じ順序で解く（相対なら指定の基準か組み込みのオブジェクトから、アバターのルートを指す基準も含む。絶対ならアバターのルートから）。基準が見つからないときに同じ名前の Armature を選び直す処理は真似ず、組み込みのオブジェクトから読む。この経路では確認だけの結果は出さず、外すか、これまでどおり何もしないかのどちらかにする。

- 判定の材料は製品名ではなく性質（カメラ・アバターと違う系統のマテリアル・自分のアニメーターで表示に切り替わる）で、同じ作りのほかのギミックにも当たる。拾うのは Merge Animator のクリップで表示になるものだけで、Modular Avatar の Object Toggle で表示になるものは対象外。
- カメラを条件にしたのは、非表示で自分のメニューから出す持ち物（コンストレイントで手に付け、Standard 系のマテリアルで描く傘やカップなど）を外さないため。これらはこれまで表示の切り替えとして書き出され、アプリでオンにできた。カメラは VRM に入らない部品で、カメラを含む表示中のギミックはこれまでも外している。非表示のカメラ付きの小物（撮影用のカメラなど）も、表示中のものと同じく外れる。ライトだけ・音だけ・パーティクルだけの非表示のギミックは、これまでどおり残る。
- 読むのはギミックのルートに付いた組み込みだけにした。入れ物の中の別のギミックのアニメーターが入れ物を表示にしても、入れ物を一つのギミックとは見なさず、同じ入れ物のほかの小物を巻き込まない。ルートと別のオブジェクトに組み込みを置く作りは拾わない。
- 1 つのクリップの中でルートとメッシュの両方がオンになるものだけを数える。別々のクリップのオンを足すと、実際には同時に起きない表示を数えるため。
- 既定でオンの **補助ギミックを自動除外** の中に入れた。外す条件はこれまでのギミックと同じで、表示のされ方だけが違うため。外したものは一覧に出て、**含める** で残せる。
- どこからも表示にならないメッシュ（Renderer が無効で、どのアニメーターもオンにしない）は、これまでどおり設定だけの階層として残す。表情とポーズの取り込みが読むため。
- アバター側のメニュー（ギミックの外のアニメーター）が表示に切り替えるものは対象にしない。ギミックの中の部品で判断し、他の仕組みから使われるものを誤って外さないため。

Animator Override Controller は、差し替えたクリップを差し替え先で数え、元のクリップは数えない。そのクリップの状態に遷移できるかまでは追わない。ほかの条件（カメラ・アバターと違う系統のマテリアル）もそろったときだけ外すので、これで誤って外す階層は小さいと判断した。

非表示のメッシュもすべて数える案は、設定だけの階層を外してしまうので採らなかった。新しく拾うギミックを確認だけに回す案は、報告のあった書き出しが既定のままでは直らないので採らなかった。外したものは一覧に出て **含める** で残せる。

## 確かめたこと

- EditMode: 非表示のギミックは自分のアニメーターがオンにしなければ残り、オンにすれば丸ごと外れること、無効のメッシュを自分のアニメーターが有効にすれば表示中と数えること、差し替えで消えたクリップは数えないこと、カメラの無い非表示の持ち物・消すだけのキー・ギミックの外のアニメーターでは外さないこと、別々のクリップのオンを足さないこと、入れ物の中のギミックが入れ物を表示にしても入れ物を外さないこと、アバターのルートを基準にしたパスと絶対パスを解けることをテストに足した。
- `ExportGimmickTests` の 60 件が Unity 2022.3 で通った。
- 書き出し: 3 体のアバターに同じシステムの 2 つの版を入れ、入れないものと合わせて修正前と修正後で書き出した。修正前は 6 通りすべてで全身の写真が灰色一色になり、2 体で FX の初期状態の固定が止まった。修正後は 6 通りすべてで、このシステムが「除外」として一覧に出て、全身・顔・表情の写真（1 体あたり 37〜52 枚）が入れない場合と 1 画素も違わなかった。入れない場合の書き出しは修正前と修正後で同じ大きさで、警告も変わらなかった。
