# 「すべて表示」は書き出しの結果ごとに閉じた状態から始め、長い変更はサロゲートペアの途中で切らない

- 日付: 2026-11-08
- 対象: `Editor/ExportRecoveryComparisonWindow.cs`・`Editor/ExportAppearanceReport.cs`・`Tests/Editor/ExportAppearanceReportLanguageTests.cs`

## 背景

#711 で、書き出すVRMの確認の「見た目の変更」に Foldout「すべて表示」を足した。レビュー（P2）で次の 3 点が残っていた。

- 開いたまま「対処を変更する」で書き出し直すと、次の結果でも開いたままになり、短い一覧を見るつもりで全件が出る。
- 110 文字で切る境界（110 文字はそのまま、111 文字で切る）のテストが無い。
- 107 文字目で切るとき、そこが絵文字などサロゲートペアの前半だと、半分の文字が残って崩れた字になる。

## 決定

- Foldout の開閉を、どの結果に対してのものか（`session.LastSuccess` の参照）と一緒に持つ。結果が変わったら閉じる。判定は `ShowsAllChanges(result)` にまとめ、テストから呼べるようにする。
- 切る位置の直前がサロゲートペアの前半なら 1 文字手前で切る。
- 110 文字・111 文字・サロゲートペアをまたぐ・またがない場合をテストする。

## 検討した代替案と不採用理由

- 書き出し直すときに `showAllChanges` を false に戻す: 書き出し直しの経路（対処の変更・保存・Unity の再読み込みで確認が無効になる）ごとに書く必要があり、漏れやすい。表示する結果と比べれば 1 か所で済む。
- 書記素（結合文字や異体字セレクターを含むまとまり）単位で切る: `StringInfo` で書けるが、この一覧は警告の要約で、崩れて見えるのはサロゲートペアの半分だけなので、そこまではしない。

## 確かめたこと

Unity 2022.3.22f1・lilToon 2.3.4 の Gamma のプロジェクトで `ExportAppearanceReportLanguageTests`・`ExportRecoveryTests` の 59 件が通った。`ExportAppearanceReport.cs` を前に戻すと、サロゲートペアのテストが落ちる（109 文字の崩れた結果になる）。
