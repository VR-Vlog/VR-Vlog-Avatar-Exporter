# エイムとコピーした回転の循環の判定でも、親子をはさんでたどる

- 日付: 2026-11-08
- 対象: `Editor/ConstraintExport.cs`・`Tests/Editor/ConstraintExportTests.cs`

## 背景

VRMC_node_constraint は循環を禁じている。`ConstraintExport` は Unity・VRChat のコンストレイントを VRM のものに変えるとき、足すと循環になるものは変えずに今の姿勢のまま残す（理由は `OmittedCycle`）。

#709 で、付け替え（Position・Parent Constraint）の判定は `DependsOnInside` に置き換え、親子とコンストレイントを交互にたどるようにした。エイム・ルックアット・ローテーション・ロールの判定（`Apply`）は `Reaches` だけで、VRM のコンストレイントの辺しかたどらなかった。このため次の形を見落とし、循環する VRM のコンストレイントを書いていた。

- エイム同士: A のエイムが点 R を向き、R の親 H のエイムが A の中の点を向く。A が回ると点が動いて H が回り、R が動いて A がまた回る。
- コピーした回転: B が A の回転を写し、A のエイムが B の中の点を向く。B が回ると点が動き、A が回って B がまた回る。
- エイムの親: A のエイムは親のワールドの向きから回すが、その親が A の回転を写している。
- 自分の子を向くエイム: 回ると向く先も動く。

UniVRM（`Vrm10Runtime`）はコンストレイントを部品の順に 1 回ずつ解き、依存の順に並べ替えない。ローテーションとロールはソースのローカルの回転だけを読み、エイムはソースのワールドの位置と自分の親のワールドの向きを読む（`Vrm10AimConstraint.Process`）。

## 決定

- コンストレイントの辺だけでたどれる循環（仕様が禁じる形）は、今までどおり `Reaches` で止める。
- そのほかに、読むものを「ローカルの回転」「ワールドの位置」「ワールドの姿勢」の 3 つに分けて `DependsOnInside` でたどる。
  - ワールドの姿勢は、親のワールドの姿勢と自分のローカルの回転から決まる。
  - ワールドの位置は、親のワールドの姿勢だけから決まる（自分が回っても原点は動かない）。
  - ローカルの回転は、自分の VRM のコンストレイントだけで変わる。ローテーション・ロールはソースのローカルの回転を、エイムはソースのワールドの位置と親のワールドの姿勢を読む。
- ローテーション・ロールはソースのローカルの回転から、エイム・ルックアットはソースのワールドの位置と対象の親のワールドの姿勢からたどり、対象の中に着けば変えない。対象を回すだけなので、対象自身の原点の位置は動かないものとして扱う。
- 付け替えはソースのワールドの姿勢からたどり、対象ごと動くので対象自身の位置も動くものとして扱う。前はエイムのソースを姿勢ごとたどっていたので、エイムのソースが回るだけの形は前より移す側に寄る。
- 判定は安全側に倒す。ワールドの位置は親の姿勢全体から決まるものとして扱うので、親が回っても動かない点（親の原点に置いた子など）を読む形も止める。ローカルの位置を見て除くと、後でアニメーションなどで位置が動く場合を見落とす。

## 検討した代替案と不採用理由

- `Reaches` に親をたどる処理を足す: 付け替えの判定と同じことを 2 か所に書くことになり、#709 で直した「ローカルの回転だけを読むものは親へたどらない」の区別も入れ直すことになる。
- 読むものを分けず、ローテーションはローカル・それ以外は姿勢の 2 つでたどる（最初の版）: エイムのソースが自分のエイムで対象の中を向いているだけの形まで循環として止めていた（Codex のレビュー）。エイムのソースは回っても位置が変わらないので、成り立つ。
- 対象の親を見ない: エイムの親が対象の回転を写している形が残る。

## 確かめたこと

`ConstraintExportTests` に、背景の 4 つの形を止めるテストと、エイムのソースが回るだけの形を変換するテスト、付け替えでソースのエイムが向く点が回るだけの形を移すテスト（Position と Parent の 2 通り）を足した。製品のファイルを develop のものに戻すと、4 つの形のテストと付け替えのテストが落ち、最初の版に戻すとエイムのソースが回るだけの形のテストが落ちる。

- Unity 2022.3.22f1・lilToon 2.3.4 の Linear のプロジェクト（VRChat SDK なし）: `ConstraintExportTests` の 75 件が通った（SDK が要る 6 件はスキップ）。
- VRChat SDK 3.10.4 を入れた Gamma のプロジェクト: `ConstraintExportTests` と `ObjectToggleCaptureTests` の 90 件がスキップ無しで通った。
