# エイムとコピーした回転の循環の判定でも、親子をはさんでたどる

- 日付: 2026-11-08
- 対象: `Editor/ConstraintExport.cs`・`Tests/Editor/ConstraintExportTests.cs`

## 背景

VRMC_node_constraint は循環を禁じている。`ConstraintExport` は Unity・VRChat のコンストレイントを VRM のものに変えるとき、足すと循環になるものは変えずに今の姿勢のまま残す（理由は `OmittedCycle`）。

#709 で、付け替え（Position・Parent Constraint）の判定は `DependsOnInside` に置き換え、親子とコンストレイントを交互にたどるようにした。エイム・ルックアット・ローテーション・ロールの判定（`Apply`）は `Reaches` のままで、VRM のコンストレイントの辺しかたどらなかった。このため次の形を見落とし、循環する VRM のコンストレイントを書いていた。

- エイム同士: A のエイムが点 R を向き、R の親 H のエイムが A の中の点を向く。A が回ると H が回り、R が動いて A がまた回る。
- コピーした回転: B が A の回転を写し、A のエイムが B の中の点を向く。B が回ると点が動き、A が回って B がまた回る。
- エイムの親: A のエイムは親のワールドの向きから回すが、その親が A の回転を写している。

## 決定

- `DependsOnInside` に「ワールドの姿勢から読むか、ローカルの回転だけを読むか」の引数を足し、`Reaches` を消す。
- ローテーション・ロールは、ソースのローカルの回転から読む（`world` が false）。ソースがエイムなら、その親とエイムの読む点のワールドの姿勢までたどる。
- エイム・ルックアットは、ソースのワールドの位置から読み、さらに対象の親のワールドの姿勢からも読む。どちらかが対象の中に着けば循環として変えない。
- 付け替えは今までどおりソースのワールドの姿勢から読む。

この結果、自分の子を向くエイムも循環として変えない（回ると向く先も動くため）。

## 検討した代替案と不採用理由

- `Reaches` に親をたどる処理を足す: 付け替えの判定と同じことを 2 か所に書くことになり、#709 で直した「ローカルの回転だけを読むものは親へたどらない」の区別も入れ直すことになる。
- 対象の親を見ない: エイムの親が対象の回転を写している形が残る。辺を 1 つ余分にたどるだけなので入れた。

## 確かめたこと

`ConstraintExportTests` に 3 つを足した（上の 3 つの形）。製品の変更を戻すと 3 つとも落ち、戻すと通る。Unity 2022.3.22f1・lilToon 2.3.4 の Linear のプロジェクト（VRChat SDK なし）で `ConstraintExportTests` の 71 件が通った（SDK が要る 6 件はスキップ）。VRChat SDK 3.10.4 を入れた Gamma のプロジェクトでは `ConstraintExportTests` と `ObjectToggleCaptureTests` の 86 件がスキップ無しで通った。
