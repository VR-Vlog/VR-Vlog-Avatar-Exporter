# フリップブックのテクスチャは自動の軽量化で縮めない

- 日付: 2026-11-09
- 対象: `Editor/TexelDensity.cs`

## 背景

自動の軽量化は、メッシュの UV の面積と表面積からテクスチャの密度を求めて、目標の密度まで縮める。この計算は UV の 0〜1 がテクスチャ全体に当たる前提になっている。

lilToon の `_Main2ndTex` と `_Main3rdTex` はフリップブックにできる。シェーダーは `lilCalcAtlasAnimation` で UV に `DecalSubParam.xy / DecalAnimation.xy` を掛けるので、4x4 のシートなら UV の 0〜1 に見えるのは 1 コマだけになる。実際の密度は計算の値の 1/4 なのに、計算の値で縮めるので、コマの絵が必要以上に粗くなっていた。

## 決定

`DecalAnimation` か `DecalSubParam` の xy が既定の (1, 1) でないスロットは、MSDF と同じく縮めない扱いにする。

既定値のマテリアルは計算も出力も変わらない。変わるのはフリップブックとして設定されたテクスチャだけで、向きは縮める量が減るほうだけになる。

## 検討した代替案と不採用理由

- コマ数で密度を割って縮める量を正しく計算する: `DecalSubParam` は 1 より大きくも小さくもでき、組み合わせの検証が増える。フリップブックの枚数は少なく、縮めないことで増える容量は小さい。
- `_Main2ndTexIsDecal` がオンのときだけ縮めない: シェーダーの UV の変換はこのスイッチに関係なく入るので、判定に使えない。

## 確かめたこと

`TexelDensityTests.AFlipbookTextureNeverShrinks` で、既定値なら密度を測り、xy を変えると測らないことを Unity 2022.3 で確かめた。結果は PR の本文に書く。
