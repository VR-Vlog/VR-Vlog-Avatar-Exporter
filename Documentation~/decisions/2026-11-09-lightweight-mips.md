# 自動の軽量化ではテクスチャのミップをミップ0だけにして書き出す

- 日付: 2026-11-09
- 対象: `Editor/LilToonFullSnapshot.cs`・`Editor/ExportVrmLilToonPreview.cs`

## 背景

`VRVLOG_materials_liltoon` のテクスチャは、Editor が作ったミップを全段そのまま書き出していた。ミップの段はミップ0の約3分の1の大きさがあり、VRM の容量とアプリの読み込み時の展開の量がそのぶん増える。

ミップの段の中身は、ほとんどのテクスチャで Unity の標準の box フィルタで縮めたものなので、アプリが読み込み時に `Texture2D.Apply(true)` で作っても同じものになる。

## 決定

「自動で軽量化する」がオンのときだけ、2D のテクスチャをミップ0だけで書き出す。アプリは、ミップが1段だけの 2D の画像に、読み込み時にミップを全段作る（`mips` の値だけで決め、目印は足さない）。

次のテクスチャは、これまでどおり Editor が作ったミップを全段書き出す。

1. 法線マップ: アプリの `Apply(true)` は画素を色として平均するだけなので、法線として縮めた Editor のミップと遠くの陰影が変わる
2. 不透明でない lilToon のマテリアル（カットアウト・半透明など）が読むテクスチャ: アルファが輪郭を描くので、遠くで輪郭が欠けないよう Editor のミップを残す
3. Point フィルタのテクスチャ: ディザやドット絵の目印なので、アプリもミップを作らない
4. インポーターでミップの作り方を変えたテクスチャ: fadeout・Preserve Coverage・Border Mip Maps のどれかがオン、または Mip Map Filter が box 以外
5. キューブマップ（反射など）: アプリはキューブにミップを作らない
6. インポーターの無いテクスチャ（各段を手で書いた `.asset`・メモリ上で作ったテクスチャ）: アプリの box フィルタでは同じ段を作れない

書き出したファイルのプレビュー（`ExportVrmLilToonPreview`）も、アプリと同じ条件でミップを作る。

## 影響

1. 軽量化がオンの VRM で、対象のテクスチャの容量がミップの段のぶん（約25%）減る。GPU に載る量は、アプリがミップを作るので変わらない
2. ミップを作らない古いアプリで読むと、対象のテクスチャがミップ無しで描かれ、遠くでちらつく。アプリ側の対応が本番に出てから、この変更を含む版を出す
3. 作者がミップを切った（Generate Mip Maps がオフ）で Point でないテクスチャは、軽量化のオンオフに関わらず、新しいアプリで読み込み時にミップが作られる。目印を足さずにミップの数だけで決めたため。これまで書き出された VRM で該当するのは 4×4 の平らな法線マップ程度で、見た目は変わらない

## 検討した代替案と不採用理由

- 目印（「アプリでミップを作る」のフラグ）を足す: 作者がミップを切った画像を区別できるが、形式の版を上げることになり、古いアプリとの互換の扱いが増える。区別したい画像が今の書き出しにほぼ無い
- 不透明でないマテリアルの画像もミップ0だけにする: アプリの box フィルタのミップではアルファの面積が段ごとに減り、カットアウトの輪郭が遠くで細る
- 法線マップもミップ0だけにする: 色として平均したミップでは法線が短くなり、遠くの陰影が変わる

## 確かめたこと

- `LightweightMipsTests`: オプションがオフなら全段のまま・不透明でないマテリアルの画像と Point の画像とインポーターでミップの作り方を変えた画像とインポーターの無い画像は全段のまま・それ以外はミップ0だけになる
- `ExportVrmLilToonPreviewTests`: Point の画像はプレビューでもミップを作らない
