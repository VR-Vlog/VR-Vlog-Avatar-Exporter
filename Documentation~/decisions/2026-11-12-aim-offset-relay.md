# 回転のオフセットがある Aim を、間に足した空のオブジェクトで書き出す

- 日付: 2026-11-12
- 対象: `Editor/ConstraintExport.cs`（`Apply` の Aim と Look At、`Reparent`、`Relays`）、`Editor/PhysBoneSpringExport.cs`（`UniqueName` を同じアセンブリから使えるようにした）、`Editor/UniVrmOneClickExporter.cs`（表情のトラックが動かす対象を渡す）
- Issue: #770

## 背景

VRM の Aim（`VRMC_node_constraint` の aim）には回転のオフセットが無い。UniVRM は、親の回転と対象の初期のローカル回転から求めた軸を、ソースへの向きに最短の回転で合わせる。Unity と VRChat の Aim Constraint・Look At Constraint は Activate でオフセットを持てるので、腕の装甲のように、軸がソースを向いていない姿勢のまま追従させているものが多い。これを VRM の Aim にすると、静止していても軸がソースへ回って形が崩れるため、これまでは変換せずに今の姿勢のまま書き出していた（`OmittedRest`）。VRM では肘を曲げても部品が動かなかった。

## 決定

- 軸がソースから `MaximumAimAngle`（2°）より外れている Aim は、対象と親の間に空のオブジェクト（`<対象の名前>-VRVlog Aim`）を足す。足したオブジェクトは対象と同じ位置・同じ兄弟の順に置き、Aim の軸がソースを向く回転にして、VRM の Aim をこれに付ける。対象はその子にし、ワールドの姿勢を変えない（親が不均一に拡大縮小されていても行列が同じになる組み方にして、足した後に確かめる）。
- 最短の回転で軸を合わせるので、足したオブジェクトのロール（軸まわりの向き）をどう選んでも、ソースが動いたときに対象が回る量は同じになる。対象から見ると、オフセットを付けた軸がソースを向いたまま追従する。
- 軸は Unity・VRChat のコンストレイントの Aim Vector から決めた軸（`TryAxis`）をそのまま使う。
- 結果の一覧の理由は、オフセットが無い Aim と同じ `ApproximatedAim` を使う（上方向の指定を使わない近似である点は同じ）。
- 次のときはオブジェクトを足すと Aim 以外も変わるので足さず、これまでどおり `OmittedRest` で今の姿勢のまま書き出す。
  - 対象か、その下にヒューマノイドのボーンがある（骨格の親子が変わる）
  - 対象に揺れ物の関節（`VRM10SpringBoneJoint`）がある（揺れ物は親子で鎖を組む）
  - 対象か、その下が回転・ロールのコンストレイントのソースになっている（VRM の回転とロールはソースのローカル回転を読む）
  - VRM の表情か一人称の設定が、対象か、その下をパスで指している
  - 対象に、強さが 0 より大きい有効な Parent Constraint か Rotation Constraint もある（足したオブジェクトに Aim を付けると、同じ対象の重複として、これまで書き出していたほうが書き出せなくなる）
  - 表情のアニメーションが対象の位置・回転・拡大縮小を動かす（トラックは親から見たローカルの値なので、位置と回転は足したオブジェクトの分だけずれる。拡大縮小だけのトラックもまとめて足さない。対象より下を動かすトラックは変わらないので足す）
- 狙う先が VRM では動かないときも足さず、`OmittedRest` に戻す。狙う先、または狙う先から Aim の対象と共通の親までの間のオブジェクトが、書き出せずに今の姿勢のまま残したコンストレイント（狙う先そのものは位置・親のコンストレイント、間のオブジェクトはどれでも）を持つときがこれに当たる。元のアバターでは動く点が VRM では止まるので、Aim を付けると対象が違う向きへ回る。足さなかった対象は回らなくなるので、その下を狙う先にする Aim も同じ判定にかける（変わらなくなるまで繰り返す）。判定は全部のコンストレイントを決めた後に行い、足したオブジェクトを外して対象を元の親の下に戻す。手元のテスト用アバターで、強さ 0.5 の Position Constraint で肘に半分だけ寄る継ぎ手を前腕の装甲の Aim が狙っており、継ぎ手が VRM では T ポーズの位置に残るため、上腕を下ろすと装甲が肩の高さを向いた。
- 位置のコンストレイントで親を移す対象（#602）に足したときは、足したオブジェクトごとソースの子へ移す。表示切替の判定は対象のオブジェクトで行うので、足したオブジェクトは表示切替に入らない（中身は対象だけ）。
- 循環の判定は、コンストレイントが付いたオブジェクト（足したオブジェクト）を辺の起点にし、実際の親子でたどる。
- #602 で親を移す条件の「ほかのコンストレイントから参照されない」を、回転とロールから参照されない、に狭めた。Aim はソースのワールドの位置を読み、親を移しても静止時の位置は変わらないので、Aim のソースになっているだけの対象は移す。Aim をたどる循環は、これまでどおり循環の判定で止める。オフセットのある Aim を書き出すようになると、これまで書き出せていた位置のコンストレイントが、その Aim から参照されるという理由で書き出せなくなるモデルがあったため（手元のテスト用アバターで、前腕の部品を狙う Aim を書き出すようになった分、その部品の位置のコンストレイントが外れた）。
- オフセットが無い Aim と、コンストレイントの無いモデルの書き出す内容は変わらない。ただし Aim のソースが #602 で親を移せる対象のときは、その対象もソースの子に移すようになる（これまでは今の姿勢のまま書き出していた）。

## 既知の制限

- 狙う先ではなく Aim の対象自身（か、対象から共通の親までの間）のコンストレイントを書き出せなかったときは、足したオブジェクトを残す。対象は元のアバターより動かないまま狙う先へ向くので、向きは元とずれることがある。手元のテスト用アバターでは、強さ 0.5 の Position Constraint で肘に半分寄る継ぎ手が当たり、足さないと継ぎ手は前腕の方を向かずに止まる。足したほうが元に近いので、狙う先の側だけを判定する。
- Aim が狙う部品を #602 でソースの子に移すようになったので、その部品は #602 のほかの Position Constraint と同じく、ソースの回転にも付いて回る（ソースが回ると周りを回る）。これまでは、ソースが動いても部品はその場に残っていた。

## 検討した代替案と不採用理由

- 表情・一人称のパスを書き換えて、パスが指すメッシュの下にも足す: #602 の親の移し替えは、パスが指すものを動かさない方針（`OmittedBound`）にしている。同じ方針にそろえ、書き換えの経路を増やさない。
- 足さずに対象の初期の回転を変えて書く: 対象の下のメッシュやボーンの姿勢が変わる。
- Aim を回転のコンストレイントに置き換える: ソースの位置ではなく回転を読むので、肘を曲げたときの向きが合わない。
