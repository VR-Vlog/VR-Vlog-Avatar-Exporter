# 評価器で、FXのパラメーターを動かす曲線を再生する

- 日付: 2026-11-14
- 対象: `Formats/Runtime/AvatarAnimatorEvaluator.cs`、`Tests/AnimatorComparison/AvatarAnimatorComparisonCases.cs`、`Tests/AnimatorComparison/AvatarAnimatorEvaluatorComparisonTests.cs`、`Tools/AvatarAnimatorEvaluatorTests.cs`、`Tools/Fixtures/AvatarAnimator`、`Formats/README.md`

## 背景

[FXのパラメーターを動かす曲線と、Prevent Repeatsを拡張に書く](2026-11-13-avatar-animator-parameter-curves.md)で、パラメーターを動かす曲線を`{"property":"parameter"}`のターゲットとして書くようにした。評価器（`AvatarAnimatorEvaluator`）はこのターゲットを再生できず、`Supports`で断っていた。

Unityがこの曲線をどう扱うかは、2026-11-13の記録のT1〜T13で、ほかのパラメーターや遷移とは切り離して測ってあった。評価器はレイヤーの混ぜ方（M6・M7）をノードのターゲットで測って決めているので、パラメーターのターゲットも同じ混ぜ方になるかを、比較のテスト（`Tests/AnimatorComparison`）にケースを足して、Unity 2022.3.22f1で60fps・30fps・ばらつくフレーム時間の3通りを記録して確かめた。

## 測って分かったこと

| 番号 | ケース | 結果 |
|---|---|---|
| U1 | `parameterCurves`: Write Defaultsがオンのレイヤーで、floatのDriveを0から1へ動かすステートと動かさないステートを行き来する。別のレイヤーがDriveとintのCount（曲線あり）を条件に遷移する。Driveを動かしていない間と動かしている間に`SetFloat`・`SetInteger`する | Driveは遷移の間もノードと同じ混ぜ方で動き、動かすステートから出るとすぐにコントローラーの既定値（0.25）に戻る。`SetFloat`・`SetInteger`はどちらの間も効かず、その直後のフレームの遷移も起きない。Countは既定値のまま |
| U2 | U1の同じレイヤーのノードのターゲット（動かさない方のステートだけが書く） | 書くステートから書かないステートへの遷移が終わると、ノードも既定値（0）になる。評価器はそれまで前のフレームの値を持ち続けていた（下のレイヤーが何も書いていないとき） |
| U3 | `parameterHold`: Write Defaultsがオフのレイヤーで、Heldを動かすステートからモーションの無いステートへ0.2秒で移り、戻る | 移る間、空のステートの側の値は、遷移の始めはレイヤーの直前の値で、そこからフレームごとに「既定値 +（前のフレームのその値 − 既定値）× 前のフレームの進み」になって既定値（0.1）に近づく。遷移が終わるとその値のまま止まる。ノードでは同じ場面で前のフレームの出力に近づく（M6）。戻る遷移は、止まった値から始まる |
| U4 | `parameterPass`: Write Defaultsがオフで、モーションがHeldを書かないステートへ移る。モーションの重みの半分だけがHeldを書く1Dツリーのステートへ移る | どちらもノードと同じで、書かない分は前のフレームの値になる（持ち続ける・フレームごとに近づく） |

記録は`Tools/Fixtures/AvatarAnimator`の`parameterCurves`・`parameterHold`・`parameterPass`の9個。既存の57個の記録は、記録の仕方を変えた後に取り直しても1バイトも変わらなかった。

## 決定

- パラメーターのターゲットは、ノードのターゲットと同じくM6・M7で混ぜる。違うのはU3の場面だけで、Write Defaultsがオフのモーションの無いステートへ移る間、レイヤー自身のそのパラメーターの値を、遷移元の側を既定値に置き換えたノードの式で求める。これを評価器のM11とする
- フレームの最後に、パラメーターの値をレイヤーが書いた値にする。どのレイヤーも書いていなければ`rest`（コントローラーの既定値）にする。int・bool・triggerは常に`rest`。次のフレームの遷移とツリーはこの値を見る（1フレーム遅れ、2026-11-13のT3）
- `Set`と Parameter Driver は、パラメーターのターゲットがあるパラメーターを変えない（U1、2026-11-13のT1d・T2・T3）。最初の値もExpression Parametersの既定値ではなく`rest`にする
- U2に合わせ、Write Defaultsがオンでモーションのあるステートが書かないターゲットは、下のレイヤーがどれも書いていなければ`rest`にする（M6の訂正）。モーションの無いWrite Defaultsのステートはもともとこうしていた。ノードのターゲットにも効く変更で、既存の57個の記録もこの規則で一致する
- `Supports`はパラメーターのターゲットのあるデータを断らない。Additiveのレイヤーは断ったままなので、2026-11-13のT13（Additiveで足す量）は評価器では使わない

## 検討した代替案と不採用理由

- パラメーターは、前のフレームの値を読み返す場面ではどこでも既定値を読む、という1つの規則にする: U3は説明できるが、U4で外れた。U4ではノードと同じく前のフレームの値を読んでいた。測って合った場面だけを分ける
- U2を、パラメーターのケースから外して別に扱う: U1のDriveも同じ規則（書かないステートで既定値に戻る）で一致させる必要があり、ノードだけを外す理由が無かった。既存の記録と照らして、ほかのケースを変えないことを確かめた

## 既知の制限

- U3の式は1つのレイヤーで測った。下のレイヤーが同じパラメーターを書くとき、遷移元の側を既定値にするのか下のレイヤーの値にするのかは測っていない
- 遷移が割り込まれて止まった複製から混ぜるとき（M5）のパラメーターは測っていない
- 遷移で使ったトリガーに曲線があるとき（Unityはそのトリガーを既定値に固定する）、遷移がそれを使い切ったあとの扱いは測っていない。評価器は既定値のままにする
- VRChatのクライアントで同じになるかは確かめていない。M1〜M7と同じく、Unityの`Animator`と比べている

## 確かめ方

- `AvatarAnimatorEvaluatorComparisonTests`をUnityで回し、66ケース（22ケース×3通り）が評価器と一致すること
- `Tools/run-avatar-animator-evaluator-tests.ps1`で、評価器の単体の確認（`ParameterCurves`を含む100件）と66個の記録の再生が通ること
- 評価器から次のどれか1つを戻すと、記録の再生か単体の確認で落ちることを手元で確かめた: `Set`を効かせる、Parameter Driverで変える、U3の規則を外す、U2の訂正を外す
