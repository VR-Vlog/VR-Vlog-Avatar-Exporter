# 評価器は、次のフレームで何も変わらない間は評価を飛ばす

- 日付: 2026-11-15
- 対象: `Formats/Runtime/AvatarAnimatorEvaluator.cs`、`Formats/Runtime/ExpressionAnimationData.cs`、`Tools/AvatarAnimatorEvaluatorTests.cs`、`Tools/AvatarAnimatorSettledCheck.cs`、`Tools/run-avatar-animator-evaluator-tests.ps1`、`Formats/README.md`
- Issue: VR-Vlog/VR-Vlog#3664（Epic VR-Vlog/VR-Vlog#3658）

## 背景

アプリで、何も操作していない間も評価器が毎フレームすべてのレイヤーを評価し、アプリがすべての対象に値を書いていた。レイヤーの多いアバターでは、Android の実機で評価と書き込みに合わせて 1.6 ms ほどかかっていた。目標は何も操作しない間 0.5 ms 以内。

## 決定

- フレームの終わりに、次のフレームが今のフレームと同じ結果になるかを確かめ、なるなら次の `Advance` は評価しない（落ち着いた状態）。そのときはステートの正規化時間だけを、評価するときと同じ式で進め、`Values` を変えず、`Changed` を false にする。アプリは `Changed` が false のフレームでは書き込みを飛ばせる
- 落ち着いたとみなす条件は、そのフレームで次のすべてが成り立つこと
  - どのレイヤーもステートに入らず、遷移を始めも終えもせず、重みを変えていない。FX の重みもブレンドしていない
  - パラメーターがフレームの始めと終わりで同じ（Parameter Driver と M11 が書いたものも含む）
  - `Values` が前のフレームと同じ
  - どのステートのモーションも、時間で値が変わらない。キーの値がすべて同じで接線が 0 か stepped のクリップ、速さ 0、`TimeParameter`（パラメーターと時間が一致しているとき）、終わりまで再生したループしないクリップのどれか
  - exit time の遷移が待っていない。条件が成り立たない、速さが 0 以下、exit time が 1 以上でもう過ぎた、のどれか。exit time の無い遷移はこのフレームですべて見て、どれも通らなかった
- 長さ 0 の Layer Control がレイヤーの重みを変えたフレームは、落ち着いたとみなさない。そのフレームで先に進んだレイヤーは、新しい重みを次のフレームから使うため（自分へ入り直すステートから実行されると、ステートの出入りとしては数えないので、これが無いと古い重みのまま止まる）
- `Set` で値が変わったとき、`SetLayerWeight` を呼んだとき（同じ重みでも）は、次のフレームを評価する。`SetLayerWeight` は呼ばれることが少ないので、値を比べずに評価し直す
- Any State から自分のステートへ、長さ 0・exit time なしで毎フレーム入り直すレイヤーは、毎フレーム同じ結果になる。そのステートか外側のステートマシンに `random` の Parameter Driver があるときだけは、入るたびに乱数を引くので落ち着いたとみなさない。synced レイヤーのソースがこの形のときも落ち着いたとみなさない
- materialSlot は stepped で、評価器は遷移の途中でも重みの大きいほうの値を取る。落ち着いた判定は値の比較とモーションの判定だけで決め、stepped の対象を別に扱わない。stepped のキーで値が変わるクリップは、時間で値が変わるクリップとして扱う
- `Curve.Evaluate` は、値が同じで間の接線が 0 の区間ではベジェを計算せずにその値を返す。平らな区間でも、ベジェの丸め誤差で 4 と 3.9999999999999996 を行き来することがあり、毎フレーム評価する側が落ち着かなかった。値は丸め誤差の分しか変わらない
- `SkipsSettledFrames` を false にすると毎フレーム評価する。同じ入力で並べて比べるため

- `pwsh Tools/run-avatar-animator-evaluator-tests.ps1`: 単体テスト 3804 件と録画 105 本の再生が通る。足した `Settled` のテストは、飛ばす評価器と毎フレーム評価する評価器を並べ、毎フレームの `Values`・`Written`・パラメーター・ステート・遷移の進み・正規化時間・レイヤーの重みが一致することと、どのフレームを飛ばしたかを見る。トグル、ループして値が変わるクリップ、ループしないクリップの終わり、exit time（1 以上と 1 未満）、materialSlot の遷移と stepped のキー、自分へ入り直す遷移（乱数あり・なし）、自分へ入り直すステートの長さ 0 の Layer Control が前のレイヤーの重みを変える場合、`SetLayerWeight`、`TimeParameter`、synced レイヤーを含む

## 残ったもの

- 実機での評価と書き込みの時間はアプリの PR で測る

## 追記: 時間だけが進む遷移と exit time の待ちも飛ばす（U4-14）

A9 が落ち着かなかったのは、まばたきの間隔を決めるレイヤーが、空のクリップから空のクリップへ長さ 6 秒・10 秒（固定の長さ）の遷移をタイマーとして使っているためだった。遷移の途中は落ち着いたとみなさなかったので、待つ間ずっと毎フレーム評価していた。この遷移はどちらの側も値を書かないので、進むのは遷移の進みだけになる。

### 決定

- 両側がすべての対象に同じ値を出す遷移は、落ち着いた状態のまま遷移の進みだけを進める。評価したフレームで、A 側と B 側の値が違う対象があったか、パラメーターの値が進みで変わる形（B 側がモーションなしで Write Defaults オフ）だったら、その遷移は落ち着いたとみなさない。割り込まれた遷移（M5 の止めた写し）と、始めたフレームでまだ進みが 0 の遷移も落ち着いたとみなさない。行き先のステートのモーションも、時間で値が変わらないこと
- exit time の遷移が待っているステートも飛ばす。条件が成り立ち、これから exit time に届く遷移を覚えておき（遷移の途中なら、割り込みの元に応じて元と行き先の遷移）、それを越えるフレームだけ評価する
- 飛ばすフレームでは、評価するときと同じ式（`AdvanceTime` と `Progress + dt / Duration`）で次の正規化時間と進みを先に計算し、遷移が終わる（進みが 1 以上）か、覚えた exit time を越える（`TryFire` と同じ `Crossing`）なら、何も進めずにそのフレームを評価する。フレーム数を先に数えて予約すると dt の丸めや可変 dt で 1 フレームずれるので、毎フレーム同じ計算で確かめる
- 覚える遷移が実際より多くても、評価するフレームが増えるだけで値は変わらない
- 重み 0 で休んでいるレイヤーが、前のフレームまでに書いた値を M7 で忘れたフレームは、落ち着いたとみなさない。忘れた次のフレームからそのレイヤーは対象を書かなくなり、`Written` が変わる。値が同じでも `Written` だけが変わるので、値の比較では見つからなかった（変更前からあったずれで、exit time の待ちを飛ばすようにして当たる形が増えた）。毎フレーム書き直して忘れるだけのレイヤーは、フレームの始めに何も覚えていないので落ち着く

### 確かめたこと

- `pwsh Tools/run-avatar-animator-evaluator-tests.ps1`: 単体テスト 13416 件と録画 105 本の再生が通り、比較ケース 255795 フレームが毎フレーム評価と一致する（飛ばすのは 62817 から 63242 フレームに増えた）。足したテストは、タイマーの遷移（両側が同じ値・空・Write Defaults オフの空）、両側が違う値の遷移、割り込みの元 5 通りのタイマーで、飛ばす評価器と毎フレーム評価する評価器を並べて比べ、遷移の終わりと exit time のフレームを評価することを見る。これらと直した 2 件は変更前の評価器で落ちる。重み 0 で忘れるレイヤーのテストは、この修正の前の評価器で `Written` が食い違って落ちる
- 敵対的レビューで、乱数で作ったコントローラー（1〜3 レイヤー、可変 dt）を飛ばす評価器と毎フレーム評価する評価器で並べて再生した。6000 個で、上の `Written` のずれのほかに値が食い違うものが 5 個あり、どれも変更前の評価器でも同じフレームで食い違う（synced レイヤーがソースより前にあり `TimeParameter` のステートを使う形）。この変更では直さない
- 変更前の評価器を別の名前空間で読み、同じ入力で並べて比べた。比較ケース（M5 の割り込み、M6 の Write Defaults オフと混在を含む）255795 フレームと、書き出した 10 体のすべてのフレームで、`Values`・`Written`・パラメーター・ステート・時刻・重みがビット単位で一致した
