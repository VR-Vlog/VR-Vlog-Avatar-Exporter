# humanoidのレイヤーは、書かないマッスルを休みの値にする

- 日付: 2026-11-16
- 対象: `Formats/Runtime/AvatarAnimatorEvaluator.cs`（M6）、`Tests/AnimatorComparison/AvatarAnimatorComparisonCases.cs`（`handsOverEmpty`・`handsOverNoMotion`・`handsUnderThumb`）
- Issue: VR-Vlog/VR-Vlog#3666（Epic VR-Vlog/VR-Vlog#3658 の段5-3）

## 背景

段5-3でGestureとActionもUnityのグラフで再生するようにしたところ、書き出し後の照合（`AvatarAnimatorCrossCheck`）の警告がA2とA10で「31項目中8」から「31項目中31」に増えた。最初にずれるのは左手の親指のマッスルで、Unityは-0.064、評価器は-2.0だった。

照合の再生に一時的なログを足してA2を書き出した。フレーム0は一致し、フレーム1からずれる。このときGestureの手のレイヤーの1つは、Write Defaultsがオフで空のクリップを持つステートから、指のマッスルを書くステートへの遷移の途中だった（Uprightが既定の0なので、フレーム0で遷移が始まる）。プレイアブルの重みとレイヤーの重みは両者で一致していた。

これを直すと、増えた23項目のうち15項目が消えた。残る8項目はメニューのモーション（Action）で、Actionの重みが0から上がり始めたフレームでずれる。Actionの待機のクリップは体のマッスルを49個書くが、指は書かない。Unityは指を休みの値（0）としてActionの重みで混ぜた（Gestureの値×(1−0.033)と一致）。評価器は前のフレームの値を通していた。

これも直したが、A2とA10の警告は「31項目中16」で、8以下には戻っていない。増えた分として残るのはメニューのモーション8項目。指のずれは消えた。いまは、Actionの重みが0.133になるフレームで、脚と足のマッスル12個が3e-4〜1.1e-3ずれ、照合の許容（1e-3）をわずかに超える（A2のWaveでフレーム34、例: 左下腿のねじれ Unity -0.00092、評価器 -0.00196）。Foot IKを使うステートはどのコントローラーにも無い。手の形の8項目は段5-3の前からあるもので、FXの尻尾と耳の回転のずれ。

## 決めたこと

- 直すのは評価器のほう。照合のUnity側はM15とM16のとおりにグラフを組んでいて、ずれはレイヤーの合成の規則の差だった。素のUnityの記録が評価器と違うので、評価器をUnityに合わせる
- M6をマッスルについて次のように変える。Unityはhumanoidのレイヤーの姿勢を、マッスルをまとめて1つの姿勢として作る、という読みに沿う
  - マッスルを1つでも書くモーションは、書かないマッスルを休みの値にする。Write Defaultsのオンとオフは関係しない
  - マッスルを1つも書かないモーション（空のクリップなど）は、これまでどおり下のレイヤーのマッスルを通す
  - 遷移の途中で、どちらかの側のモーションがマッスルを1つでも書くときは、マッスルを書かない側はどのマッスルも休みの値を出す
  - Write Defaultsがオフでモーションの無いステートは、これまでどおりレイヤー自身の最後の値を出す。ただし、レイヤーがまだ書いていないマッスルでは、下のレイヤーの値でなく休みの値とする
- マッスルを書くステートでは、下のレイヤーの値をまとめて通す近道（#3664）を使わない。メニューの切り替えのレイヤーは普通マッスルを書かないので、近道の効果は変わらない
- 3つのケースを比較テストに足し、60fps・30fps・不揃いなフレーム時間のUnityの記録を`Tools/Fixtures/AvatarAnimator`に入れた
  - `handsOverEmpty`: 空のクリップで休んでいる間、Unityは下の手を通す。指を書くステートとの間の遷移では、空の側を休みの値として混ぜる。直す前の評価器は下のレイヤーの値を混ぜていた（t=0.733でUnity 0.025、評価器0.758）
  - `handsOverNoMotion`: モーションの無いステートでは、Unityは最初のフレームから休みの値を出す（直す前の評価器は-1.5）。指を書くステートから戻る遷移とその後は、レイヤーが最後に書いた値を保つ
  - `handsUnderThumb`: 親指だけを書くクリップの下で、人差し指は休みの値になる。Write Defaultsがオンのクリップでも同じ。親指だけを書くステートから空のクリップへ遷移する間も、どちらの側も書かない人差し指は休みの値になる（遷移が終わると下の手を通す）

## 測っていないこと

- 遷移の長さがフレームのちょうど整数倍（60fpsで0.2秒）だと、遷移が終わるフレームで、Unityは空の側の休みの値をもう1フレーム出した。Unityのfloatの時刻では、そのフレームでまだ遷移が終わっていないためと見ているが、確かめていない。ケースでは遷移を0.17秒や0.18秒にして、この境目を避けた
- ブレンドツリーの中で、マッスルを書く子と書かない子が混ざるときは、書かない子も休みの値で混ぜることにしたが、Unityでは測っていない
- 割り込みで止まった遷移元（評価器の`Frozen`）がマッスルを書いていたかは見ていない。遷移先が書くときだけ、遷移中のマッスルを休みの値にする
- Actionが混ざり始めるときの脚と足のマッスルの小さなずれ（上の8項目）の原因は分かっていない
- マッスルを一度も書かないコントローラーで、モーションの無いステートが下のレイヤーのマッスルをどう扱うかも測っていない。評価器はそのコントローラーが動かすターゲットにしか手を付けないので、この変更でも変わらない

## アプリへの影響

アプリは同じ評価器で手の形と体の姿勢を出す。次のアバターでは、姿勢がUnityに近づく方向に変わる。

- Gestureの手のレイヤーに、Write Defaultsがオフの空のクリップかモーションの無いステートを持つ
- 一部のマッスルだけを書くクリップを持つ（Actionの待機のクリップなど）

アプリの`Formats`の固定を上げるときに確かめる。
