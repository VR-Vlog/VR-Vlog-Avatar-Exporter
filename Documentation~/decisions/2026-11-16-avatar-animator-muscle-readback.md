# 照合では、評価器のマッスルもUnityと同じ読み戻しを通してから比べる

- 日付: 2026-11-16
- 対象: `Editor/AvatarAnimatorCrossCheck.cs`、`Formats/Runtime/AvatarAnimatorEvaluator.cs`（ブレンドツリーの子が書かないターゲット）、`Tests/Editor/AvatarAnimatorCrossCheckTests.cs`（`MusclesReadBackAsAPosePutOnTheBones`）、`Tests/AnimatorComparison/AvatarAnimatorComparisonCases.cs`（`handsUnderThumbHalf`・`treeFallback`・`frozenMuscles`）
- Issue: Epic VR-Vlog/VR-Vlog#3658 の段5-3X

## 背景

段5-3でマッスルの規則（M6）を直した後も、書き出し後の照合（`AvatarAnimatorCrossCheck`）の警告はA2とA10で「31項目中16」残った（[humanoidのレイヤーは、書かないマッスルを休みの値にする](2026-11-16-avatar-animator-muscle-empty-side.md)）。うち8項目はメニューのモーションで、Actionの重みが0.133になるフレームで、脚と足のマッスル12個が3e-4〜1.1e-3ずれる。

同じ入力をUnityと評価器に流す合成のケースで調べた。体のマッスルを書くActionのクリップを、手の形のレイヤーの上に1/30〜1の重みで混ぜ、Unityの値を`HumanPoseHandler.GetHumanPose`で読む。

- Unityの読んだ値は、混ぜる前の2つの姿勢を重みで線形に混ぜた値から、ねじれ（Twist）のマッスルと脚の内外のマッスルで最大で約1.5e-3ずれた。ずれは重みに対して単調でなく、ねじれの配分（twist distribution）が0でも0.5でも出た
- 線形に混ぜた値を`SetHumanPose`で骨に置き、`GetHumanPose`で読み戻すと、Unityの読んだ値と1e-6以内で一致した

Unityは混ぜるときはマッスルを線形に混ぜていて、ずれは骨からマッスルを読み戻すときに出る。評価器の値（線形に混ぜた値）は正しく、照合が読み戻しの誤差を評価器のずれとして数えていた。

## 決めたこと

- 照合の許容（1e-3）は広げない。読み戻しの誤差は姿勢によっては許容より大きいので、広げても残るうえ、本当のずれも見逃す
- 照合では、評価器のマッスルを同じリグの骨に`SetHumanPose`で置き、`GetHumanPose`で読み戻してから、Unityの読んだ値と比べる（`MuscleReader`）。体の位置と向きはUnityの読んだ値を使い、評価器が書かないマッスルは0とする。読んだ後は骨の位置・回転・スケールを元に戻す
- テスト`MusclesReadBackAsAPosePutOnTheBones`で、そのまま比べると許容を超え、読み戻してから比べると1e-4未満になることを確かめる

## 測ったこと（段5-3のレビューで残った点）

レビューで指摘された点を、合成のケースでUnityと比べた。ケースは比較テストに足し、60fps・30fps・不揃いなフレーム時間のUnityの記録を`Tools/Fixtures/AvatarAnimator`に入れた。

- `handsUnderThumbHalf`: 重みが1未満（0.5、途中から0.25）のレイヤーで、クリップが書かないマッスルは、そのレイヤーの休みの値を下のレイヤーの値と重みで混ぜたものになる。評価器のとおりで、直していない
- `frozenMuscles`: 親指を書くクリップから空のクリップへの遷移を、遷移先からの遷移で割り込んだ。割り込みで止まった遷移元（`Frozen`）のマッスルは、遷移先がマッスルを書かなくても評価器と一致した。直していない
- `treeFallback`: Write Defaultsがオフのステートの1Dのブレンドツリーで、子が書かないターゲットは、下のレイヤーがそのフレームに書いた値で混ざる。評価器は前のフレームの最終の値（上のレイヤーの値も入る）を使っていて、最初のフレームから最大で0.24ずれた（Unity 5.758、評価器 6）。評価器を、下のレイヤーがそのフレームに書いた値（どれも書かなければ前のフレームの値）を使うように直した。Write Defaultsがオンのツリーと、マッスルを書く子と空のクリップの子のツリーは、直す前から一致していた

### 直していないこと

- 重みが0で値を忘れたレイヤーが、次のフレームでWrite Defaultsがオフのモーションの無いステートから遷移を始める場合を測るケースを作った。Unityの記録が、FXとGestureの2つのコントローラーをPlayableGraphで再生したときと、Gestureだけを`Animator`で再生したときで違った
  - `Animator`のときは、遷移の始まりの値から遷移先へ線形に混ざる。いまの評価器（遷移の始まりの値を`Held`に取っておく）と一致する
  - PlayableGraphのときは、空の遷移元が、レイヤー自身の前のフレームの出力を出す。毎フレーム、前の出力から遷移先へ混ぜ直すので、線形より早く遷移先に近づく。レイヤーが値を持たないターゲットは、遷移の最初のフレームでは下のレイヤーの値のままで、次のフレームから休みの値から始まる
  - 書き出したアバターはVRChatと同じくPlayableGraphで再生されるので、評価器を合わせるならこちらだが、M6の`Held`の前提を変えることになる。別の段で、どちらを再現するか決めてから直す。このケースはコミットしていない
- 遷移の長さがフレームのちょうど整数倍のときに、Unityがもう1フレーム休みの値を出すこと（[前の決定記録](2026-11-16-avatar-animator-muscle-empty-side.md)の「測っていないこと」）は、時間が足りず測っていない

## 結果

A1〜A11を、直す前（`feature/full-reproduction`の2fbf1f4f）と直した後で書き出し、照合の警告「アプリの再生がUnityと合わないメニューの項目・手の形」を比べた。

| アバター | 直す前 | 直した後 |
|---|---|---|
| A1 | 34項目中8 | なし |
| A2 | 31項目中16 | 31項目中8 |
| A6 | 15項目中12 | 15項目中12 |
| A10 | 31項目中16 | 31項目中8 |
| A11 | 25項目中8 | なし |
| A3〜A5・A7〜A9 | なし | なし |

- 消えたのはどれもメニューのモーション8項目（Wave・Clap・Point・Cheer・Dance・Backflip・SadKick・Die）
- A2とA10に残る8項目は段5-3の前からある手の形の項目、A6の12項目は直す前と同じ項目
- 書き出したVRMは、画像の名前（`images[].name`）のほかは直す前と同じだった。画像の名前は、直した後のパッケージで2回書き出しても変わる
- `Tools/run-avatar-animator-evaluator-tests.ps1`で、足したケースを含む144の記録が評価器と一致した

## アプリへの影響

照合の変更は書き出しの確認だけで、VRMに書く内容は変えない。アプリには影響しない。

ブレンドツリーの変更は評価器の変更なので、アプリの`Formats`の固定を上げると反映される。Write Defaultsがオフのステートに、子ごとに違うターゲットを書くブレンドツリーがあり、その下のレイヤーも同じターゲットを書くアバターで、ツリーが書かない分の値が、前のフレームの最終の値でなく、そのフレームに下のレイヤーが書いた値になる。Unityに近づく方向の変更で、ほかのアバターの動きは変わらない。
