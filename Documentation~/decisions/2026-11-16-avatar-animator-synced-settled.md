# ソースより前にある synced レイヤーで、落ち着いたフレームの判定が時間のずれを見るようにする

- 日付: 2026-11-16
- 対象: `Formats/Runtime/AvatarAnimatorEvaluator.cs`、`Tools/AvatarAnimatorEvaluatorTests.cs`
- Issue: VR-Vlog/VR-Vlog#3666（Epic VR-Vlog/VR-Vlog#3658 の段5-2b）

## 背景

評価器は、次のフレームが今のフレームと同じになると分かると、そのフレームを評価せずに時間だけを進める（`Settles`・#3664）。段4-14 のレビューで、乱数で作ったデータのうち、synced レイヤーがソースより前にあり、ソースのステートの時間をパラメーター（Motion Time）で決める形で、飛ばす評価器と毎フレーム評価する評価器の値がずれることが見つかっていた（変更前から）。

synced レイヤーは `Sync` でソースの時間を写す。ソースが後ろにあると、写すのはソースが前のフレームに進めた時間になり、1 フレーム遅れる。ソースの時間がパラメーターで決まるステートは速さ 0 として扱うので、`Holds` は速さ 0 なら時間を見ずに「この先も同じ値」と答えていた。そのため、パラメーターを変えたフレームでソース自身の出力が変わらないと、synced レイヤーが次のフレームで新しい時間に移るのに、そのフレームを飛ばしていた。

## 決定

- `Holds` に、レイヤーの時間とソース（同期していないレイヤーなら自分）の時間を両方渡す。速さ 0 のときは 2 つが一致するときだけ「この先も同じ値」とする。速さが 0 でないときは今までどおり、モーションが止まっているかクリップの端を過ぎているかで決める（ソースの時間はレイヤーの時間から同じ向きに進んだ先にあるので、途中で通る）
- 遷移中の次のステートも同じく、次の時間とソースの次の時間を比べる（ソースが Motion Time のステートへ遷移している間に時間のパラメーターを変えると、ここを比べないと次のフレームを飛ばしてずれる）

## 選ばなかった案

- synced レイヤーの時間がソースと違えば必ず飛ばさない。ソースが後ろにあり速さが 0 でない間は毎フレーム 1 フレーム分ずれるので、止まったクリップを回す synced レイヤーでも飛ばせなくなる。値がずれるのは速さ 0 のときだけなので採らない
- synced レイヤーを常にソースの後ろで回す。Unity はレイヤーの順に回し、前にある synced レイヤーは 1 フレーム遅れて見える（`Sync` のコメント）。評価器の出力が Unity と変わるので採らない

## 確かめたこと

- `Tools/run-avatar-animator-evaluator-tests.ps1` が通る（13987 件の確認、Unity の記録 105 件の再生、比較ケースは 255795 フレームが一致し 63242 フレームを飛ばす。飛ばした数は変更前と同じ）
- 足したテスト: ソースより前の synced レイヤーで、ソースの時間のパラメーターを変えた次のフレームを飛ばさないこと（ソースのステートにいるとき、Motion Time のステートへ遷移している間の 2 つ）。乱数で作った synced レイヤーの seed 4・10・18・53・67 で、飛ばしあり・なしが一致すること。生成器はソースの前後・Motion Time・速さ 0 と負を振るが、選んだ 5 seed はどれもソースより前・ソースが Motion Time の形で、手で組んだテストと同じ原因を見ている。どのテストも変更前の評価器で失敗し、遷移中のテストは次のステートの比較だけを戻した評価器でも失敗する
- 段4-14 のレビューの seed（5330 ほか）はその時のファザーが残っていないので、同じ形を作る乱数の生成器をテストに入れ、変更前に失敗した seed を選んだ。最初に作った外のファザーの 1500 seed（744 万フレーム）で、変更前は 117 seed が失敗し、変更後は 0。テストに入れた生成器の 1500 seed では変更前は 137 seed が失敗し、変更後は 0（レビューで数えた）。レビューで生成器を広げたファザー（速さ・Cycle Offset のパラメーター、1D ツリー、遷移の Offset、Any State の自己遷移など）の 15000 seed・4500 万フレームでも、変更後の不一致は 0
