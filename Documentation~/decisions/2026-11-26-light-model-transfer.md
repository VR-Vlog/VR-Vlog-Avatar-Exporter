# QRの転送で、通常のモデルと一緒に複数人撮影用の軽量モデルも送る

- 日付: 2026-11-26
- 対象: `Editor/ExportSettings.cs`（`LightModelChoices`）・`Editor/ExperimentalExpressionCaptureWindow.cs`・`Editor/AppTransferExport.cs`・`Editor/LanTransfer/CloudTransferProtocol.cs`・`Editor/LanTransfer/CloudVrmTransferSession.cs`・`Editor/LanTransfer/AppTransferFlow.cs`・`Editor/LanTransfer/AppTransferPanel.cs`・`Editor/LanTransfer/AppTransferWindow.*`・`Editor/Locales/ExporterLocale_*.json`・`Tests/LanTransfer/CloudTransferPairTests.cs`・`Tests/LanTransfer/CloudTransferTests.cs`・`Tests/Editor/ExportSettingsTests.cs`・`Documentation~/CloudTransfer.md`

## 背景

アプリで何人も並べて撮るときは、1人で撮るときより軽いモデルのほうが表示が速い。今は表情ボードの **軽量化** を **最大** にして書き出し直し、もう一度送るしかなく、1人で撮るときのモデルとは別に送る手間がかかる。

1回のQRで、通常のモデルと軽量モデルの2つを送れるようにする。アプリは複数人撮影のときに軽量モデルを使う。

## 決定

### 2本の別のファイルとして送る

通常のモデルと軽量モデルは別のVRMとして書き出し、別々の転送として上げる。

- 1つのファイルに両方を入れる形は、アプリの読み込みとVRMの形式の両方を変えることになる。別のファイルなら、アプリは今のVRMの読み込みをそのまま2回使える。
- 転送サービス（Worker）は変えない。2本はそれぞれ今の転送の作成・アップロード・公開を通り、鍵・受取用の認証情報・アップロード用の認証情報も別々に持つ。片方の認証情報でもう片方は読めない。
- 2本とも上げ終えてから、通常・軽量の順に続けて公開する。受取期限は公開から決まるので、続けて公開すると2本の期限がほぼそろう。リンクの `exp` は2本のうち早いほうにする。
- 中止・再試行・期限切れは2本まとめて扱う。進み具合は2本の合計で出す。
- 軽量モデルのアップロードは、通常のモデルのアップロードの期限の60秒前に打ち切る。2本とも公開まで進めるための余裕で、間に合わなければ軽量モデルを諦める。
- アップロードの期限が作成から3分の旧サービスでは、2本で3分を分け合えないので軽量モデルを送らない。

### QRのリンクの v4

QRのリンクは、軽量モデルを送るときだけ `v=4` にする。v3 の8項目を同じ順に並べ、そのあとに軽量モデルの `lid`・`ltoken`・`lsize`・`lsha256`・`lkey` を足した13項目にする。`l` の付く項目の検査は通常の側と同じで、`lid` が `id` と同じリンクは作らない。名前は2本で共通なので1つだけ持つ。

v3 のリンクは変えない。軽量モデルを送らない転送は、今までどおり v3 のリンクを出す。

### 既定はオフで、v3 を出す

設定の既定はオフにする。オフなら今までと同じ1本の v3 のリンクになる。

- v4 を読めないアプリでv4のQRを読むと、取り込みが始まらず、読めない理由も出ない。今の配布版のアプリはv4に対応していない。
- オンにした人には、チェックの下に「古いバージョンのアプリでは読み取れません」と出す。
- アプリがv4に対応した版を出したら、既定をオンに変える（`AppTransferFlow.SendLightModelByDefault`）。

### 軽量モデルの中身と、1本にする条件

軽量モデルは、通常のモデルと同じ入力（表情・除外・視線・利用条件など）で、軽量化の設定だけを変えて書き出す。何を変えるかは `LightModelChoices.Light` の1か所だけに書く。今は **軽量化** を **最大** にするだけで、ほかの軽量化の項目は足していない。

軽量モデルが通常のモデルと同じ出力になる間だけ1本にする。追加の軽量化が入れば常に2本になる。

- 同じかどうかは `LightModelChoices.WritesTheSameAs` の1つの比較で決める。比べるのは `LightModelChoices` のすべての項目で、Avatar Optimizerを使わないアバターの **最大** は **標準** と同じものとして比べる。
- 今の比較では、通常のモデルが **標準**（Avatar Optimizerなし）か **最大** のとき同じ出力になり、1本になる。このときチェックの下に「軽量化しても変わらないため通常のモデルだけ送ります」と出す。
- 軽量モデルに項目を足すと `Light` が変える項目が増え、`WritesTheSameAs` はそれも比べる。軽量化の段がどれでも違う出力になるので、コードを変えずに2本になる。段ごとに「送る・送らない」を書く形にはしていない。

### 軽量モデルが失敗しても止めない

軽量モデルの書き出し・暗号化・アップロード・公開のどれかが失敗したときは、軽量モデルだけを諦め、通常のモデルを v3 のリンクで送る。QRの下に「軽量モデルを送れなかったため通常のモデルだけ送ります」と1行出す。

- 通常のモデルは軽量モデルが無くても使える。軽量モデルのせいで1人の撮影の分まで送れなくなるより、1本で送るほうがよい。
- 軽量モデルを v4 のリンクに入れると1つのQRに収まらない名前（v3 なら収まる長さ）も、同じく通常のモデルだけを送る。

### 書き出しは表情ボードの1回の呼び出しの中で

軽量モデルは、通常のモデルを書き出した直後に、同じ表情ボードの呼び出しの中で書き出す。かんたんの転送の見えない表情ボードは、その呼び出しの間しか無いため。

- 通常のモデルの書き出しは変えない。かんたんの転送は、今までどおり表情ボードを開いたまま何も変えずに書き出す通常と同じVRMを書き出す（`QuickTransferMatchesDefaultNormalTests`）。
- 軽量モデルの書き出しの結果は、書き出し結果の一覧・確認・前回の書き出しの記録に入れない。失敗はConsoleの警告1行だけにする。
- 書き出しの間、Unityの進み具合のバーに「軽量モデルを書き出し中」と出す。

### 保存とQRが書き出しを共有する決まりを広げる

`2026-10-22-save-and-transfer-one-export.md` は「**VRMを保存** と **QRコードを作る** のどちらを先に押しても書き出しは1回」と決めた。ここを次のように広げる。

- **VRMを保存** は今までどおり通常のモデル1本だけを保存する。軽量モデルは保存しない。
- QRを作ったあとに保存すると、送った通常のモデルの一時VRMをコピーする。ここは変えない。
- 先に保存してからQRを作るとき、軽量モデルも送るなら、保存したファイルを使い回さずに書き出し直す（`MayReuseSavedCopy` が false を返す）。保存したファイルに軽量モデルは無いので、軽量モデルを作るには表情ボードの書き出しが要る。書き出しは1回のままで、通常のモデルのバイトは保存したものと同じになる。

### 画面

**アプリに転送** の名前の欄の下に、チェックの行「複数人撮影用の軽量モデルも送る」を1行と、その下に注記の1行を足した。

- チェックはこのPCのUnity Editorの設定（EditorPrefs）に覚える。アバターごとではない。
- 注記の行は、チェックがオフのときも高さを取って空けておく。注記が出ても消えてもほかの部品が動かない。
- QRの画面の失敗の注記は、軽量モデルを送ろうとした転送でだけ行を取る。既定の転送のレイアウトは変えない。

## 検討して採らなかったもの

- 「**最大** のときは軽量モデルを作らない」と段で決める案。軽量モデルに項目を足したとき、段の分岐も直さないと2本にならない。出力が同じかどうかの1つの比較にした。
- 既定をオンにする案。今のアプリはv4のQRを読めず、理由も出ないので、アプリの対応を待つ。
- 軽量モデルが失敗したら転送全体を止める案。通常のモデルまで送れなくなる。
- 軽量モデルも **VRMを保存** で保存する案。保存は1本という今の決まりを変えることになり、頼まれていない。
- 2本を1つの転送（1つのファイル）にまとめる案。Workerとアプリの読み込みの両方を変える。

## 確認したこと

- `Tools/run-lan-transfer-tests.ps1`: v4 のリンクのベクトル、2本の作成・アップロード・公開の順番、`exp` が早いほう、軽量モデルの失敗で v3 に落ちること、軽量モデルを頼まないときに1本になること、v4 の仮のリンクが本物より短くならないこと、長い名前のQR、中央にアイコンを置いたv4のQRの読み取り。
- `Tests/Editor/ExportSettingsTests.TheLightweightModelIsASecondFileOnlyWhileItWritesSomethingElse`: 設定が違えば2本、同じなら1本。
- `Tests/LanTransfer/CloudTransferWindowTests.SendingTheLightModelDefaultsOffAndIsSaved`: 既定はオフで、変えた値を覚える。

## 影響

- 軽量モデルを送ると、書き出しとアップロードの時間が軽量モデルの分だけ増える。
- v4 のリンクは v3 より約270文字長く、同じ名前でもQRのモジュールが細かくなる。12文字の名前で、v3 はQRのバージョン19（101モジュール）、v4 はバージョン26（129モジュール）になる。QRの表示の大きさは変えていない。
- 1つのQRに収まる名前の長さは、ひらがなで v3 が224文字、v4 が194文字。中央にアイコンを置ける長さは v3 が107文字、v4 が77文字。
