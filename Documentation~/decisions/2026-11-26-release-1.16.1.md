# 軽量化の3段と既定でオフの服や小物の透明化を、1.16.1として公開する

- 日付: 2026-11-26
- 対象: `package.json`・`Editor/ExportEntry.cs`（`PackageVersion` のフォールバック）・`CHANGELOG.md`・`README.md`・`README.en.md`・`Documentation~`・`Compatibility/AvatarPreservation.md`

## 背景

1.15.2のあと、developに#855、#747、#857、#858、#859、#860、#861が入った。#855はAvatar Optimizerを使うアバターでメッシュを結合する。#747は軽量化でテクスチャをミップ0だけにする。#857は既定でオフの服や小物を、VR Vlog以外のVRMビューアで見えないようにする。#858は「自動で軽量化する」と結合を「軽量化」のなし・標準・最大にまとめる。#861は軽量化の既定を最大から標準にする。#859は#857の結果一覧の出し方の修正、#860はCIの検証だけの変更。mkから、developの内容をリリースするよう指示があった。

## 決定

- MINORを上げて `1.16.0` にする。表情ボードの項目が変わり（#858）、書き出す内容も足している（#855・#857）。
- `release/1.16.0` はdevelopの `a1611332`（#861のマージ）から作る。
- `CHANGELOG.md` の「未リリース」を `## 1.16.0` にし、冒頭に1行の説明を足す。Releaseの本文に使うので、項目は3行に縮め、細かい条件はREADME・各PR・決定記録に残す。#859は#857の中の修正、#860はCIだけなので項目にしない。
- 公開の前に、1.15.2とdevelopでEditModeテストを全件回して新しい失敗が無いことを確かめる（結果はPRに書く）。
- リリースには画像を添付しない。
- バージョンを書き換えるファイルと公開の手順は1.15.2と同じにする（[1.15.2の決定記録](2026-11-17-release-1.15.2.md)）。

## 1.16.0を公開せず1.16.1にする（2026-11-26）

#862をmainへマージしたあと、Build release candidateが `Documentation~/ExperimentalExpressionCapture.md` の決定記録へのリンク（#855・#858で足したもの）で止まった。決定記録はZIPに入らないので、ZIPの中では行き先が無い。Release VPM Packagesは走らず、`v1.16.0` のタグ・Release・VPMの一覧はどれもできていない。

- 2つのリンクを、GitHub上の決定記録を指す絶対URLにする。
- mainへの昇格はパッケージのバージョンを上げ、ブランチ名を `release/X.Y.Z` にしないと通らない（`Tools/check-gitflow.py`）。mainはすでに `1.16.0` なので、`release/1.16.1` で `1.16.1` に上げて出し直す。`1.16.0` は誰にも配っていないので欠番にし、`CHANGELOG.md` の見出しも `## 1.16.1` にする。中身は1.16.0として準備したものとリンクの修正だけ。
- ゲートを迂回して `1.16.0` のまま入れることはしない。
- PRのCIはZIPのリンクを見ていないので、この種の不備はmainに入るまで見つからない。PRの段階でZIPを作ってリンクを確かめる検査は別のPRで足す。
