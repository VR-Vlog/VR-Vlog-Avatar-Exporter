# メニューやエフェクトなどの再現を、2.0.0として公開する

- 日付: 2026-11-27
- 対象: `package.json`・`Editor/ExportEntry.cs`（`PackageVersion` のフォールバック）・`CHANGELOG.md`・`README.md`・`README.en.md`・`Documentation~`・`Compatibility/AvatarPreservation.md`

## 背景

1.17.0のあと、developに#871（feature/full-reproduction。プレリリースの2.0.0-alpha.1と同じ内容）と、#872〜#878が入った。Unityで見えるアバターの動き（メニューの切り替え、エフェクト、Contact、Constraint、PhysBoneのパラメーター）をアプリでも再現するための拡張をVRMに書く。mkから、2.0.0を正式リリースするよう指示があった。

## 決定

- MAJORを上げて `2.0.0` にする。書き出すVRMの拡張が増え、対応前のアプリでは見え方が変わることがあるため。パッケージの依存（`vpmDependencies`）とUnityの対応版は1.17.0と同じ。
- `release/2.0.0` はdevelopの `41bf840c`（#878のマージ）から作る。
- `CHANGELOG.md` の「未リリース」を `## 2.0.0` にする。Releaseの本文に使うので、冒頭の説明と3行の項目に縮める。もとの項目は下に残す。
- 「未リリース」に書いていた「アプリの1.2.9以降（仮）」は、アプリの1.2.9（2026-11-25公開）と1.3.0がschema 2の `VRVLOG_avatar_animator` を読むので、仮を外して1.2.9以降とする。`VRVLOG_requiredAppVersions` の `1.2.9` はそのまま正しい。
- 公開の前に、1.17.0と2.0.0でEditModeテストを全件回して新しい失敗が無いことを確かめる（結果はPRに書く）。
- リリースには画像を添付しない。
- バージョンを書き換えるファイルと公開の手順は1.17.0と同じにする（[1.17.0の決定記録](2026-11-26-release-1.17.0.md)）。

## 「未リリース」に書いていた項目

Unityで見えるアバターの動き（メニューの切り替え、エフェクト、Contact、Constraint、PhysBoneのパラメーター）をアプリでも同じに再現するための情報をVRMに書きます。プレリリースの2.0.0-alpha.1と同じ内容です。古いVR Vlogのアプリでは見え方が変わることがあります。

- アプリでメニューを再生するための表（`VRVLOG_avatar_animator`）を小さくしてVRMに書くようにしました。名前とタイミング以外が同じクリップの動きを1つにまとめ、表を圧縮してVRMのバイナリに置きます。試したアバターでは表が5〜7MBから0.5〜0.65MBになり、VRM全体で4.5〜6.3MB小さくなりました。この形を読むにはアプリの1.2.9以降が要ります。それより前のアプリでも開けますが、メニューの再生は表が無いときと同じになります。
- メッシュのアセットが見つからない部分（元のモデル（FBX）がプロジェクトに無いときなど）があるとき、「自動除外せず保持」や「メッシュが空のRendererを書き出しから外しました」ではなく、部分ごとに「メッシュが見つからず省略」の1行を出し、その部分がVRMに入らないことと確かめる場所を伝えるようにしました。転送の結果画面では注意の件数に数えます。ビルドの処理（メッシュの結合など）でメッシュが入った部分には出しません。
- アプリで動かすエフェクトやContactの表をVRMに書けなかったとき、コンソールだけでなく書き出しの注意と結果一覧にも「書き出しの一部を省略しました」として出すようにしました。このとき表情のアニメーションは、書けなかった表を指さないように作り直します。
- アプリで動かすConstraintとPhysBoneのパラメーターの表をVRMに書けなかったときも、エフェクトやContactの表と同じく書き出しの注意と結果一覧に出すようにしました。エフェクト・Contact・PhysBoneの表を読み取れなかったときも同じように出します。
- Contact Senderが上限を超えたときと、このバージョンが対応していないContactがあるときも、アプリで動かない数を書き出しの注意に出すようにしました。
- 書き出しの注意の「アプリの再生がUnityと合わないメニューの項目・手の形」に、アプリでもUnityと同じに動くメニューのモーションが出ることがあったのを直しました。Unityから手足のねじれの値を読み取るときに出る小さな誤差を、アプリとのずれとして数えていました。
- メニューでlilToonの機能（逆光ライトやリムライトなど）を入れ切りするとき、その切り替えもVRMに書くようにしました。今までは書き出しの注意に「マテリアルの機能のオン・オフ」として数えるだけで、アプリではメニューを操作しても変わりませんでした。「自動で軽量化する」がオンでも、メニューで付ける機能の画像は書き出します。
- 2.0.0-alpha.1で、メニューで切り替えるlilToonのマテリアルがあるアバターでは、「自動で軽量化する」の頂点データを詰めることと他のVRMアプリ向けの画像を小さくすることが行われず、VRMが大きくなっていたのを直しました。試したアバター5体では、直す前は1.17.0の1.5〜1.6倍の大きさでした。
- 「自動で軽量化する」で頂点カラーを外すかどうかを決めるとき、メニューがそのメッシュに付けるほかのメッシュのマテリアルも見るようにしました。今までは、輪郭線の太さやファーの向きを頂点カラーで決めるマテリアルにメニューで入れ替えると、アプリで輪郭線やファーが崩れることがありました。
- 「自動で軽量化する」で頂点カラーを外すかどうかを決めるとき、メニューが動かすマテリアルの値も見るようにしました。今までは、ふだんは頂点カラーを使わず、メニューで輪郭線の太さやファーの向きを頂点カラーで決める設定に切り替えるマテリアルでは頂点カラーが外れ、アプリでメニューを切り替えたときに輪郭線やファーが崩れることがありました。
- 書き出しのときにメニューの項目と手の形をアプリとUnityの両方で再生して比べる時間の上限を、60秒から30秒にしました。上限を超えたときに再生中の項目も、そこで止めて比べないようにしました。メニューの多いアバターでは書き出しが最大30秒ほど短くなります。比べられなかった項目の数はコンソールに出ます。
- 書き出しのときにメニューの項目と手の形を比べるとき、FXのPlayable Layer Controlを動かすために比べない項目を、Unityで再生する前に見分けて飛ばすようにしました。今までは、そうした項目もUnityで1つあたり0.45秒ほど再生してから飛ばしていたため、30秒の上限のうちの多くを使い、ほかの項目を比べられないことがありました。書き出すVRMは変わりません。
- メニューで切り替えるlilToonのマテリアル用のMToonの画像も、「自動で軽量化する」で他のVRMアプリ向けの画像と同じく小さくするようにしました。このマテリアルはどのメッシュにも付いていないので他のVRMアプリには出ず、アプリでもlilToonを読み込めなかったときにだけ使います。メニューがこのマテリアルやほかのlilToonのマテリアルを、lilToonのマテリアルが無いメッシュに付けるときは、アプリがMToonで描くので小さくしません。
